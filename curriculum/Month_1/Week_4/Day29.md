### Q1: "서버가 느릴 때 어떻게 분석하나요?"

```
┌─────────────────────────────────────────────────────────────────────┐
│  모범 답변                                                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  "체계적인 순서로 분석합니다:                                       │
│                                                                      │
│  1. CPU/메모리 확인: top, vmstat                                    │
│     → CPU 사용률, 메모리 부족, 스왑 사용                            │
│                                                                      │
│  2. 디스크 I/O 확인: iostat -x 1                                    │
│     → %util이 높으면 디스크 병목                                    │
│                                                                      │
│  3. 네트워크 확인: ss -s, netstat                                   │
│     → TIME_WAIT 폭증, 연결 문제                                     │
│                                                                      │
│  4. 프로세스 분석: ps aux, strace                                   │
│     → 문제 프로세스의 시스템 콜 패턴 분석                           │
│                                                                      │
│  5. 로그 확인: journalctl, 앱 로그                                  │
│     → 에러 메시지, 경고 확인                                        │
│                                                                      │
│  예시: 최근 DB 연결 지연 문제를 분석할 때,                          │
│  ss로 TIME_WAIT가 폭증한 것을 발견하고                              │
│  Connection Pool을 도입하여 해결했습니다."                          │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### Q2: "Docker 컨테이너가 계속 재시작할 때 어떻게 분석하나요?"

```
┌─────────────────────────────────────────────────────────────────────┐
│  모범 답변                                                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  "Exit Code를 기준으로 분석합니다:                                   │
│                                                                      │
│  1. docker logs로 에러 메시지 확인                                   │
│                                                                      │
│  2. docker inspect로 Exit Code 확인:                                 │
│     • 0: 정상 종료                                                  │
│     • 1: 앱 에러 → 앱 로그 분석                                     │
│     • 137 (128+9): SIGKILL, OOMKilled                               │
│     • 139 (128+11): SIGSEGV, 메모리 오류                            │
│                                                                      │
│  3. 137이면 OOMKilled 확인:                                          │
│     docker inspect --format '{{.State.OOMKilled}}'                  │
│                                                                      │
│  4. OOMKilled라면:                                                  │
│     • docker stats로 메모리 사용량 확인                             │
│     • 메모리 제한 늘리기 또는                                       │
│     • 앱 메모리 누수 수정                                           │
│                                                                      │
│  예시: Flask 앱이 137로 종료되어 OOMKilled 확인 후                  │
│  docker stats로 분석한 결과, 대용량 파일 처리 시                    │
│  메모리 누수가 있어 스트리밍 처리로 수정했습니다."                  │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

```
├─────────────────────────────────────────────────────────────────────┤

│     → 이름 해석이 되는지                                            │

│                                                                      │
│  예시: API 서버 연결 실패 시 nc로 테스트한 결과                     │
│  방화벽에서 차단된 것을 발견하여 ufw allow로 해결했습니다."         │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### Q4: "Docker Compose로 앱을 운영할 때 주의사항은?"

```
모범 답변:

"프로덕션 환경에서 Docker Compose 사용 시 주의사항:

1. depends_on의 한계
   - 컨테이너 시작 순서만 보장, 앱 Ready 보장 안 함
   - 해결: healthcheck + condition: service_healthy

2. 볼륨 관리
   - 데이터 영속성을 위해 named volume 사용
   - 백업 전략 필수

3. 리소스 제한
   - deploy.resources로 CPU/메모리 제한
   - OOM 방지

4. 네트워크 격리
   - 목적별 네트워크 분리 (frontend, backend)
   - 보안 강화

5. 로깅 설정
   - logging driver로 로그 크기 제한
   - 로그 로테이션

6. 환경 변수 관리
   - .env 파일 또는 secrets
   - 민감정보 분리

단, 대규모 프로덕션은 Kubernetes 권장합니다."
```

### Q5: "메모리 사용량이 높을 때 분석 방법은?"

```
모범 답변:

"시스템 레벨과 프로세스 레벨로 분석합니다:

1. 시스템 전체: free -h
   - used, buff/cache, available 확인
   - available이 낮으면 메모리 부족

2. 스왑 사용: vmstat 1
   - si/so가 높으면 스왑 활발 → 메모리 부족

3. 프로세스별: ps aux --sort=-%mem | head
   - 메모리 많이 쓰는 프로세스 식별

4. 상세 분석: /proc/<pid>/status
   - VmRSS: 실제 메모리 사용
   - VmSwap: 스왑 사용량

5. 캐시 정리 (긴급 시)
   - sync && echo 3 > /proc/sys/vm/drop_caches

6. 근본 해결
   - 메모리 누수 수정
   - 스케일 업 또는 아웃
   - 애플리케이션 최적화"
```
