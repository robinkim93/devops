# 📅 Day 109: External Secrets Operator (ESO)

## 🎯 오늘의 목표

> Vault의 시크릿을 Kubernetes Secret으로 자동 동기화하는 External Secrets Operator를 구축합니다.

애플리케이션이 기존 방식대로 K8s Secret을 사용하면서, 실제 시크릿은 Vault에서 중앙 관리합니다.

## 📚 Part 1: ESO 아키텍처

### 작동 원리

```
┌────────────────────────────────────────────────────────────────────────────┐
│                   External Secrets Operator Flow                            │
├────────────────────────────────────────────────────────────────────────────┤
│                                                                            │
│  1. ExternalSecret 리소스 생성                                             │
│     ┌──────────────────────┐                                               │
│     │ kind: ExternalSecret │                                               │
│     │ spec:                │                                               │
│     │   remoteRef:         │                                               │
│     │     key: myapp/db    │                                               │
│     └──────────────────────┘                                               │
│              │                                                             │
│              ▼                                                             │
│  2. ESO Controller가 감지                                                  │
│     ┌──────────────────────┐                                               │
│     │ External Secrets     │                                               │
│     │ Operator             │                                               │
│     └──────────────────────┘                                               │
│              │                                                             │
│              ▼                                                             │
│  3. Vault에서 시크릿 조회                                                  │
│     ┌──────────────────────┐                                               │
│     │ HashiCorp Vault      │                                               │
│     │ secret/myapp/db      │──────────────────────────────────────────────│
│     └──────────────────────┘   OR  AWS Secrets Manager, GCP, Azure        │
│              │                                                             │
│              ▼                                                             │
│  4. K8s Secret 생성/업데이트                                               │
│     ┌──────────────────────┐                                               │
│     │ kind: Secret         │                                               │
│     │ data:                │                                               │
│     │   password: xxxxx    │ ← Pod가 이 Secret 사용                        │
│     └──────────────────────┘                                               │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘
```

### 핵심 리소스

| 리소스 | 설명 |
|--------|------|
| `SecretStore` | 시크릿 저장소 연결 설정 (네임스페이스 범위) |
| `ClusterSecretStore` | 시크릿 저장소 연결 설정 (클러스터 범위) |
| `ExternalSecret` | 어떤 시크릿을 가져올지 정의 |
| `ClusterExternalSecret` | 여러 네임스페이스에 시크릿 배포 |

### 지원하는 Provider

| Provider | 설명 |
|----------|------|
| HashiCorp Vault | 가장 일반적 |
| AWS Secrets Manager | AWS 네이티브 |
| AWS Parameter Store | SSM Parameter |
| GCP Secret Manager | GCP 네이티브 |
| Azure Key Vault | Azure 네이티브 |
| Kubernetes | 다른 클러스터의 Secret |

## 🛠️ Part 2: ESO 설치

### Helm Chart 설치

```bash
# Helm 레포 추가
helm repo add external-secrets https://charts.external-secrets.io
helm repo update

# 네임스페이스 생성
kubectl create namespace external-secrets

# 설치
helm install external-secrets external-secrets/external-secrets \
  -n external-secrets \
  --set installCRDs=true \
  --set webhook.port=9443 \
  --set certController.serviceAccount.create=true

# Pod 확인
kubectl get pods -n external-secrets

# 예상 출력:
# NAME                                               READY   STATUS
# external-secrets-xxxxx                             1/1     Running
# external-secrets-cert-controller-xxxxx             1/1     Running
# external-secrets-webhook-xxxxx                     1/1     Running
```

### CRD 확인

```bash
kubectl get crd | grep external-secrets

# 예상 출력:
# clustersecretstores.external-secrets.io
# externalsecrets.external-secrets.io
# secretstores.external-secrets.io
# ...
```

## 🛠️ Part 3: Vault SecretStore 설정

### Service Account 토큰 생성 (Vault 인증용)

```yaml
# vault-auth-sa.yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: vault-auth
  namespace: default
---
apiVersion: v1
kind: Secret
metadata:
  name: vault-auth-token
  namespace: default
  annotations:
    kubernetes.io/service-account.name: vault-auth
type: kubernetes.io/service-account-token
```

```bash
kubectl apply -f vault-auth-sa.yaml
```

### Vault에서 ESO용 Policy 및 Role 생성

```bash
# ESO가 사용할 Policy
kubectl exec -it -n vault vault-0 -- vault policy write external-secrets - <<EOF
path "secret/data/*" {
  capabilities = ["read", "list"]
}
path "secret/metadata/*" {
  capabilities = ["read", "list"]
}
EOF

# ESO용 Kubernetes Role
kubectl exec -it -n vault vault-0 -- vault write auth/kubernetes/role/external-secrets \
  bound_service_account_names=vault-auth \
  bound_service_account_namespaces=default \
  policies=external-secrets \
  ttl=1h
```

### SecretStore 생성

```yaml
# vault-secretstore.yaml
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: vault-backend
  namespace: default
spec:
  provider:
    vault:
      server: "http://vault.vault.svc:8200"
      path: "secret"
      version: "v2"
      auth:
        kubernetes:
          mountPath: "kubernetes"
          role: "external-secrets"
          serviceAccountRef:
            name: vault-auth
```

```bash
kubectl apply -f vault-secretstore.yaml

# 상태 확인
kubectl get secretstore -n default

# 예상 출력:
# NAME            AGE   STATUS   CAPABILITIES   READY
# vault-backend   10s   Valid    ReadWrite      True
```

### ClusterSecretStore (클러스터 전역)

```yaml
# cluster-secretstore.yaml
apiVersion: external-secrets.io/v1beta1
kind: ClusterSecretStore
metadata:
  name: vault-cluster
spec:
  provider:
    vault:
      server: "http://vault.vault.svc:8200"
      path: "secret"
      version: "v2"
      auth:
        kubernetes:
          mountPath: "kubernetes"
          role: "external-secrets"
          secretRef:
            name: vault-auth-token
            namespace: default
            key: token
```

## 🛠️ Part 4: ExternalSecret 생성

### 단일 시크릿 동기화

```yaml
# myapp-external-secret.yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: myapp-secret
  namespace: default
spec:
  # 동기화 주기
  refreshInterval: 1h
  
  # SecretStore 참조
  secretStoreRef:
    name: vault-backend
    kind: SecretStore
  
  # 생성될 K8s Secret 설정
  target:
    name: myapp-secret  # K8s Secret 이름
    creationPolicy: Owner
    template:
      type: Opaque
      data:
        # 필요시 변환 가능
        DB_CONNECTION: "mysql://{{ .username }}:{{ .password }}@db:3306/myapp"
  
  # Vault에서 가져올 데이터
  data:
  - secretKey: username      # K8s Secret의 키
    remoteRef:
      key: myapp/config      # Vault 경로
      property: username     # Vault 시크릿의 필드
  
  - secretKey: password
    remoteRef:
      key: myapp/config
      property: password
  
  - secretKey: api_key
    remoteRef:
      key: myapp/config
      property: api_key
```

```bash
kubectl apply -f myapp-external-secret.yaml

# ExternalSecret 상태 확인
kubectl get externalsecret -n default

# 예상 출력:
# NAME           STORE           REFRESH   STATUS         READY
# myapp-secret   vault-backend   1h        SecretSynced   True

# 생성된 K8s Secret 확인
kubectl get secret myapp-secret -o yaml

# 시크릿 값 디코딩
kubectl get secret myapp-secret -o jsonpath='{.data.password}' | base64 -d
```

### 전체 Path 동기화

```yaml
# 특정 경로의 모든 시크릿을 동기화
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: myapp-all-secrets
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: vault-backend
    kind: SecretStore
  target:
    name: myapp-all-secrets
  dataFrom:
  - extract:
      key: myapp/config  # 모든 필드 추출
```

### 템플릿 활용

```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: myapp-configmap
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: vault-backend
    kind: SecretStore
  target:
    name: myapp-config
    template:
      type: Opaque
      data:
        config.yaml: |
          database:
            host: {{ .db_host }}
            port: {{ .db_port }}
            username: {{ .db_user }}
            password: {{ .db_pass }}
          redis:
            host: {{ .redis_host }}
            port: 6379
  data:
  - secretKey: db_host
    remoteRef:
      key: myapp/database
      property: host
  - secretKey: db_port
    remoteRef:
      key: myapp/database
      property: port
  # ...
```

## 🛠️ Part 5: 애플리케이션 연동

### Deployment에서 Secret 사용

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  template:
    spec:
      containers:
      - name: myapp
        image: myapp:latest
        env:
        # 개별 키 참조
        - name: DB_USERNAME
          valueFrom:
            secretKeyRef:
              name: myapp-secret  # ESO가 생성한 Secret
              key: username
        - name: DB_PASSWORD
          valueFrom:
            secretKeyRef:
              name: myapp-secret
              key: password
        
        # 전체 Secret을 envFrom
        envFrom:
        - secretRef:
            name: myapp-all-secrets
        
        # 파일로 마운트
        volumeMounts:
        - name: secrets
          mountPath: /etc/secrets
          readOnly: true
      volumes:
      - name: secrets
        secret:
          secretName: myapp-secret
```

## 🔍 트러블슈팅

### 문제 1: SecretSyncedError

```bash
# ExternalSecret 상태 확인
kubectl describe externalsecret myapp-secret

# Events에서 에러 확인
# "could not get secret data: ..."
```

**원인**: Vault 인증 실패 또는 Policy 권한 부족

**해결**:
```bash
# Vault에서 직접 확인
kubectl exec -it -n vault vault-0 -- vault kv get secret/myapp/config

# Policy 확인
kubectl exec -it -n vault vault-0 -- vault policy read external-secrets
```

### 문제 2: Secret 동기화 안됨

```bash
# ESO 로그 확인
kubectl logs -n external-secrets -l app.kubernetes.io/name=external-secrets

# SecretStore 상태 확인
kubectl describe secretstore vault-backend
```
