### 1.2 도구별 특징 비교

| 도구 | 용도 | 강점 | 약점 | 토스플레이스 연관 |
|------|------|------|------|-----------------|
| **ArgoCD** | GitOps CD | K8s 네이티브, 선언적, UI 직관적 | 복잡한 파이프라인 불리 | 명시적 사용 |
| **GoCD** | Pipeline CD | Value Stream Map, 멀티 Stage, 승인 | 학습 곡선 | 명시적 사용 |
| **Vault** | 시크릿 관리 | 동적 시크릿, 감사 로그, 다양한 백엔드 | 운영 복잡성 | 명시적 사용 |
| **ESO** | 시크릿 동기화 | Vault → K8s Secret 자동화 | 추가 컴포넌트 | Vault 연동 |
| **GitHub Actions** | CI | 통합 편의성, 마켓플레이스 | Self-hosted 제한 | CI 빌드 |

## 🔑 Part 2: 핵심 개념 상세 정리 (1시간)

### 2.1 GoCD 핵심

```yaml
# GoCD Pipeline 구조
# 파일: gocd-pipeline.gocd.yaml

format_version: 10
pipelines:
  myapp-pipeline:
    group: myapp
    label_template: "${COUNT}-${git[:8]}"
    
    # 소스 정의
    materials:
      git:
        git: https://github.com/org/myapp.git
        branch: main
        auto_update: true
    
    # 환경 변수
    environment_variables:
      DOCKER_REGISTRY: "123456789.dkr.ecr.ap-northeast-2.amazonaws.com"
      APP_NAME: "myapp"
    
    stages:
      # Stage 1: 빌드
      - build:
          clean_workspace: true
          jobs:
            build:
              tasks:
                - exec:
                    command: docker
                    arguments:
                      - build
                      - -t
                      - "${DOCKER_REGISTRY}/${APP_NAME}:${GO_PIPELINE_COUNTER}"
                      - .
                - exec:
                    command: docker
                    arguments:
                      - push
                      - "${DOCKER_REGISTRY}/${APP_NAME}:${GO_PIPELINE_COUNTER}"
      
      # Stage 2: 테스트 (병렬)
      - test:
          jobs:
            unit_test:
              tasks:
                - exec:
                    command: make
                    arguments: [test-unit]
            integration_test:
              tasks:
                - exec:
                    command: make
                    arguments: [test-integration]
      
      # Stage 3: Staging 배포 (자동)
      - deploy-staging:
          approval:
            type: success  # 이전 Stage 성공 시 자동
          jobs:
            deploy:
              tasks:
                - exec:
                    command: kubectl
                    arguments:
                      - set
                      - image
                      - deployment/myapp
                      - "app=${DOCKER_REGISTRY}/${APP_NAME}:${GO_PIPELINE_COUNTER}"
                      - -n
                      - staging
      
      # Stage 4: Production 배포 (수동 승인)
      - deploy-production:
          approval:
            type: manual
            roles:
              - release-manager
          jobs:
            deploy:
              tasks:
                - exec:
                    command: kubectl
                    arguments:
                      - set
                      - image
                      - deployment/myapp
                      - "app=${DOCKER_REGISTRY}/${APP_NAME}:${GO_PIPELINE_COUNTER}"
                      - -n
                      - production
```

**GoCD 핵심 개념:**
- **Pipeline**: 전체 배포 흐름
- **Stage**: 순차 실행되는 단계 (빌드 → 테스트 → 배포)
- **Job**: 병렬 실행 가능한 작업
- **Task**: 실제 실행 명령
- **Approval**: manual(수동 승인), success(자동)
- **Value Stream Map**: 파이프라인 시각화

### 2.2 Vault 핵심

```bash
# Vault 초기화 및 설정
#================================================

# 1. Vault 설치 (Helm)
helm repo add hashicorp https://helm.releases.hashicorp.com
helm install vault hashicorp/vault \
  --namespace vault \
  --create-namespace \
  --set "server.dev.enabled=true"

# 2. Vault 초기화 (Production)
kubectl exec -it vault-0 -n vault -- vault operator init

# 출력:
# Unseal Key 1: xxx
# Unseal Key 2: xxx
# ...
# Initial Root Token: hvs.xxx

# 3. Unseal (3개 키 필요)
kubectl exec -it vault-0 -n vault -- vault operator unseal <key1>
kubectl exec -it vault-0 -n vault -- vault operator unseal <key2>
kubectl exec -it vault-0 -n vault -- vault operator unseal <key3>

# 4. 로그인
kubectl exec -it vault-0 -n vault -- vault login <root-token>

#================================================
# 시크릿 관리
#================================================

# KV 시크릿 엔진 활성화 (v2)
vault secrets enable -path=secret kv-v2

# 시크릿 저장
vault kv put secret/myapp/config \
  db_host="mysql.db.svc.cluster.local" \
  db_port="3306" \
  db_user="app_user" \
  db_password="super-secret-password"

# 시크릿 조회
vault kv get secret/myapp/config

# 특정 필드만 조회
vault kv get -field=db_password secret/myapp/config

# 시크릿 버전 관리
vault kv get -version=1 secret/myapp/config

# 시크릿 삭제
vault kv delete secret/myapp/config

#================================================
# Kubernetes 인증 설정
#================================================

# 1. Kubernetes Auth 활성화
vault auth enable kubernetes

# 2. Kubernetes 연결 설정
vault write auth/kubernetes/config \
  kubernetes_host="https://kubernetes.default.svc" \
  token_reviewer_jwt="$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  kubernetes_ca_cert="@/var/run/secrets/kubernetes.io/serviceaccount/ca.crt"

# 3. Policy 생성
vault policy write myapp - <<EOF
path "secret/data/myapp/*" {
  capabilities = ["read", "list"]
}

path "secret/metadata/myapp/*" {
  capabilities = ["read", "list"]
}
EOF

# 4. Role 생성 (ServiceAccount 바인딩)
vault write auth/kubernetes/role/myapp \
  bound_service_account_names=myapp \
  bound_service_account_namespaces=default \
  policies=myapp \
  ttl=1h
```

**Vault 핵심 개념:**
- **Secrets Engine**: 시크릿 저장 백엔드 (KV, AWS, Database 등)
- **Auth Method**: 인증 방식 (Kubernetes, LDAP, Token 등)
- **Policy**: 권한 정책 (path + capabilities)
- **Role**: Auth Method와 Policy 연결
- **Seal/Unseal**: 암호화 키 관리

### 2.3 ESO (External Secrets Operator) 핵심

```yaml
# SecretStore: Vault 연결 정의
# 파일: secretstore.yaml
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: vault-backend
  namespace: default
spec:
  provider:
    vault:
      server: "http://vault.vault.svc.cluster.local:8200"
      path: "secret"
      version: "v2"
      auth:
        kubernetes:
          mountPath: "kubernetes"
          role: "external-secrets"
          serviceAccountRef:
            name: "external-secrets"
---
# ClusterSecretStore: 클러스터 전역
apiVersion: external-secrets.io/v1beta1
kind: ClusterSecretStore
metadata:
  name: vault-cluster
spec:
  provider:
    vault:
      server: "http://vault.vault.svc.cluster.local:8200"
      path: "secret"
      version: "v2"
      auth:
        kubernetes:
          mountPath: "kubernetes"
          role: "external-secrets-cluster"
          serviceAccountRef:
            name: "external-secrets"
            namespace: "external-secrets"
---
# ExternalSecret: 시크릿 동기화
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: myapp-secret
  namespace: default
spec:
  # 동기화 주기
  refreshInterval: 1h
  
  # SecretStore 참조
  secretStoreRef:
    name: vault-backend
    kind: SecretStore
  
  # 생성될 K8s Secret
  target:
    name: myapp-secret
    creationPolicy: Owner
    template:
      type: Opaque
      data:
        # 템플릿 사용 가능
        config.json: |
          {
            "db_host": "{{ .db_host }}",
            "db_port": "{{ .db_port }}",
            "db_user": "{{ .db_user }}",
            "db_password": "{{ .db_password }}"
          }
  
  # Vault에서 가져올 데이터
  data:
    - secretKey: db_host
      remoteRef:
        key: myapp/config
        property: db_host
    - secretKey: db_port
      remoteRef:
        key: myapp/config
        property: db_port
    - secretKey: db_user
      remoteRef:
        key: myapp/config
        property: db_user
    - secretKey: db_password
      remoteRef:
        key: myapp/config
        property: db_password
---
# dataFrom: 전체 시크릿 가져오기
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: myapp-all-secrets
  namespace: default
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: vault-backend
    kind: SecretStore
  target:
    name: myapp-all-secrets
  dataFrom:
    - extract:
        key: myapp/config
```

**ESO 핵심 개념:**
- **SecretStore/ClusterSecretStore**: 외부 시크릿 저장소 연결
- **ExternalSecret**: 동기화할 시크릿 정의
- **refreshInterval**: 동기화 주기
- **data vs dataFrom**: 개별 필드 vs 전체 시크릿

```bash
#!/bin/bash

echo ""

# 5. ArgoCD 상태 확인
```

### 3.2 시크릿 플로우 테스트

```bash
# 1. Vault에 시크릿 저장
kubectl exec -it vault-0 -n vault -- vault kv put secret/myapp/config \
  db_password="new-password-$(date +%s)"

# 2. ESO가 동기화할 때까지 대기 (또는 수동 트리거)
kubectl annotate externalsecret myapp-secret force-sync=$(date +%s) --overwrite

# 3. K8s Secret 확인
kubectl get secret myapp-secret -o jsonpath='{.data.db_password}' | base64 -d

# 4. Pod에서 시크릿 사용 확인
kubectl exec -it myapp-xxx -- env | grep DB_PASSWORD
```

```bash
vault auth enable kubernetes

vault policy write name policy.hcl

vault policy list

# Role 관리

# ESO

kubectl get secretstores -A
kubectl get clustersecretstores

kubectl describe secretstore <name>

kubectl annotate externalsecret <name> force-sync=$(date +%s) --overwrite
```
