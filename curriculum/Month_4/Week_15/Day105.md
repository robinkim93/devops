## 📚 Part 1: GoCD 아키텍처

### GoCD vs 다른 CI/CD 도구

| 특징 | GoCD | Jenkins | ArgoCD |
|------|------|---------|--------|
| 패러다임 | Pipeline as Code | Job 기반 | GitOps |
| 주요 용도 | CD 중심 | CI/CD 범용 | K8s 배포 |
| 환경 관리 | Built-in | 플러그인 | Application |
| 승인 흐름 | Native | 플러그인 | Sync Policy |
| 가시성 | VSM (Value Stream Map) | Blue Ocean | App Status |

### GoCD 핵심 개념

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           GoCD Concepts                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   Pipeline                                                                  │
│   └── 전체 배포 흐름                                                        │
│                                                                             │
│       Stage 1: Build     Stage 2: Test     Stage 3: Deploy                 │
│       ┌─────────────┐    ┌─────────────┐    ┌─────────────┐                │
│       │ Job: compile│    │ Job: unit   │    │ Job: staging│                │
│       │ Job: docker │    │ Job: integr │    │ Job: prod   │                │
│       └─────────────┘    └─────────────┘    └─────────────┘                │
│                                                                             │
│   Material: Git Repository (트리거 소스)                                    │
│   Agent: 실제 작업 실행하는 Worker                                          │
│   Artifact: Stage 간 전달되는 산출물                                        │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Value Stream Map (VSM)

```
Source → Build → Test → Staging → Production
  │        │       │        │          │
  Git    Docker  JUnit   Deploy    Manual
  Repo   Image   Tests   Auto      Approval
```

## 🛠️ Part 2: Pipeline as Code (YAML)

### 기본 구조

```yaml
# gocd.yaml
format_version: 10

# Pipeline Groups
pipelines:
  myapp-deploy:
    group: tossplace-apps
    
    # 레이블 템플릿 (버전 관리)
    label_template: "${git[:8]}-${COUNT}"
    
    # Lock Behavior (동시 실행 제어)
    lock_behavior: unlockWhenFinished
    
    # Materials (트리거 소스)
    materials:
      git:
        git: https://github.com/tossplace/myapp.git
        branch: main
        auto_update: true
        shallow_clone: true
    
    # 전역 환경 변수
    environment_variables:
      REGISTRY: docker.io/tossplace
      APP_NAME: myapp
    
    # 암호화된 변수
    secure_variables:
      DOCKER_PASSWORD: AES:encrypted_value
    
    # Stages 정의
    stages:
      # ... stages 정의
```

### 완전한 멀티 Stage 파이프라인

```yaml
format_version: 10

pipelines:
  myapp-deploy:
    group: production
    label_template: "${git[:8]}"
    
    materials:
      git:
        git: https://github.com/tossplace/myapp.git
        branch: main
        auto_update: true
    
    environment_variables:
      REGISTRY: docker.io/tossplace
      APP_NAME: myapp
    
    stages:
    #──────────────────────────────────────────────────
    # Stage 1: Build
    #──────────────────────────────────────────────────
    - build:
        clean_workspace: true
        jobs:
          build-image:
            elastic_profile_id: docker-agent
            artifacts:
              - build:
                  source: docker-digest.txt
                  destination: artifacts/
            tasks:
            - exec:
                command: docker
                arguments:
                - build
                - -t
                - ${REGISTRY}/${APP_NAME}:${GO_PIPELINE_LABEL}
                - .
            - exec:
                command: docker
                arguments:
                - push
                - ${REGISTRY}/${APP_NAME}:${GO_PIPELINE_LABEL}
            - exec:
                command: /bin/bash
                arguments:
                - -c
                - docker inspect --format='{{index .RepoDigests 0}}' ${REGISTRY}/${APP_NAME}:${GO_PIPELINE_LABEL} > docker-digest.txt
    
    #──────────────────────────────────────────────────
    # Stage 2: Test (병렬 실행)
    #──────────────────────────────────────────────────
    - test:
        jobs:
          unit-test:
            tasks:
            - exec:
                command: make
                arguments: [test-unit]
            artifacts:
              - test:
                  source: reports/unit/*.xml
                  destination: test-results/
          
          integration-test:
            tasks:
            - exec:
                command: make
                arguments: [test-integration]
            artifacts:
              - test:
                  source: reports/integration/*.xml
                  destination: test-results/
          
          security-scan:
            tasks:
            - exec:
                command: trivy
                arguments:
                - image
                - --severity
                - HIGH,CRITICAL
                - ${REGISTRY}/${APP_NAME}:${GO_PIPELINE_LABEL}
    
    #──────────────────────────────────────────────────
    # Stage 3: Deploy to Staging (자동)
    #──────────────────────────────────────────────────
    - deploy-staging:
        approval:
          type: success  # 이전 단계 성공 시 자동 실행
          allow_only_on_success: true
        environment_variables:
          TARGET_ENV: staging
          NAMESPACE: staging
        jobs:
          deploy:
            elastic_profile_id: k8s-agent
            tasks:
            - fetch:
                stage: build
                job: build-image
                source: artifacts/docker-digest.txt
                destination: .
            - exec:
                command: kubectl
                arguments:
                - set
                - image
                - deployment/${APP_NAME}
                - ${APP_NAME}=${REGISTRY}/${APP_NAME}:${GO_PIPELINE_LABEL}
                - -n
                - ${NAMESPACE}
            - exec:
                command: kubectl
                arguments:
                - rollout
                - status
                - deployment/${APP_NAME}
                - -n
                - ${NAMESPACE}
                - --timeout=300s
    
    #──────────────────────────────────────────────────
    # Stage 4: Deploy to Production (수동 승인)
    #──────────────────────────────────────────────────
    - deploy-production:
        approval:
          type: manual  # 수동 승인 필요
          roles:
            - release-manager
            - devops-team
        environment_variables:
          TARGET_ENV: production
          NAMESPACE: production
        jobs:
          deploy:
            elastic_profile_id: k8s-agent
            tasks:
            - exec:
                command: kubectl
                arguments:
                - set
                - image
                - deployment/${APP_NAME}
                - ${APP_NAME}=${REGISTRY}/${APP_NAME}:${GO_PIPELINE_LABEL}
                - -n
                - ${NAMESPACE}
            - exec:
                command: kubectl
                arguments:
                - rollout
                - status
                - deployment/${APP_NAME}
                - -n
                - ${NAMESPACE}
                - --timeout=300s
          
          notify:
            tasks:
            - exec:
                command: /bin/bash
                arguments:
                - -c
                - |
                  curl -X POST $SLACK_WEBHOOK \
                    -d '{"text":"🚀 ${APP_NAME} ${GO_PIPELINE_LABEL} deployed to production"}'
```

## 📚 Part 3: 고급 기능

### Pipeline Dependencies (Fan-in)

```yaml
# 여러 파이프라인의 결과를 모아서 배포
pipelines:
  deploy-all:
    materials:
      frontend:
        pipeline: frontend-build
        stage: build
      backend:
        pipeline: backend-build
        stage: build
      database:
        pipeline: db-migration
        stage: migrate
    
    stages:
    - deploy:
        # frontend, backend, database 모두 성공해야 실행
```

### Environment 설정

```yaml
environments:
  production:
    pipelines:
      - myapp-deploy
    agents:
      - prod-agent-1
      - prod-agent-2
    environment_variables:
      DEPLOY_ENV: production
    secure_variables:
      API_KEY: AES:encrypted
```

### Approval Types

| Type | 설명 | 사용 시점 |
|------|------|----------|
| `success` | 이전 Stage 성공 시 자동 실행 | 자동 배포 |
| `manual` | 수동 승인 필요 | Production 배포 |
| `fetch` | Material 없이 수동 트리거 | On-demand 작업 |

### Artifacts 공유

```yaml
stages:
- build:
    jobs:
      build:
        artifacts:
          - build:
              source: target/*.jar
              destination: artifacts/
          - test:
              source: reports/**/*
              destination: test-reports/
- deploy:
    jobs:
      deploy:
        tasks:
        - fetch:
            stage: build
            job: build
            source: artifacts/app.jar
            destination: deploy/
```

## 🔍 트러블슈팅

### 문제 1: Pipeline Trigger 안됨

```bash
# Material 업데이트 확인
# GoCD UI → Admin → Materials → Check connection

# auto_update 확인
materials:
  git:
    auto_update: true  # 반드시 true
```

### 문제 2: Agent 할당 안됨

```yaml
# elastic_profile_id 또는 resources 확인
jobs:
  build:
    elastic_profile_id: docker-agent
    # 또는
    resources:
      - docker
      - linux
```

## 🔑 핵심 GoCD 개념

```yaml
# 핵심 구성 요소
Pipeline:      전체 배포 흐름
Stage:         배포 단계 (순차 실행)
Job:           Stage 내 작업 (병렬 가능)
Task:          Job 내 개별 명령
Material:      트리거 소스 (Git 등)
Agent:         작업 실행 Worker
Artifact:      Stage 간 전달 파일
```
