## 📚 Part 1: GoCD 개요

### GoCD란?

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                         GoCD Architecture                                    │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   ┌────────────────────────────────────────────────────────────────────────┐│
│   │                         GoCD Server                                    ││
│   │  • Pipeline 스케줄링 및 관리                                           ││
│   │  • UI 및 API 제공                                                      ││
│   │  • 설정 저장소                                                          ││
│   └───────────────────────┬────────────────────────────────────────────────┘│
│                           │                                                  │
│           ┌───────────────┼───────────────┐                                 │
│           │               │               │                                 │
│   ┌───────▼───────┐ ┌─────▼─────┐ ┌───────▼───────┐                         │
│   │  GoCD Agent   │ │GoCD Agent │ │  GoCD Agent   │                         │
│   │  (Build)      │ │ (Test)    │ │  (Deploy)     │                         │
│   └───────────────┘ └───────────┘ └───────────────┘                         │
│                                                                              │
│   Agent: 실제 작업을 수행하는 워커                                            │
│   - 여러 Agent를 두어 병렬 처리                                               │
│   - Kubernetes Elastic Agent 지원                                            │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

### GoCD vs Jenkins vs ArgoCD

| 특징 | GoCD | Jenkins | ArgoCD |
|------|------|---------|--------|
| 주 용도 | CD 중심 | CI 중심 | GitOps CD |
| Pipeline | YAML (선언적) | Groovy (명령적) | YAML (선언적) |
| 시각화 | Value Stream Map | Blue Ocean | Application Graph |
| Kubernetes | Elastic Agent | Plugin | 네이티브 |

### GoCD 핵심 개념

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                        GoCD Pipeline 구조                                    │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   Pipeline (myapp)                                                           │
│   ├── Material (Git Repository)                                              │
│   │                                                                          │
│   ├── Stage: build                 ┐                                         │
│   │   └── Job: compile             │ 순차 실행                               │
│   │       └── Task: docker build   │                                         │
│   │                                │                                         │
│   ├── Stage: test                  │                                         │
│   │   ├── Job: unit-test     ┐     │                                         │
│   │   │   └── Task: npm test │병렬  │                                         │
│   │   └── Job: lint          ┘     │                                         │
│   │       └── Task: npm lint       │                                         │
│   │                                │                                         │
│   └── Stage: deploy                ┘                                         │
│       └── Job: k8s-deploy                                                    │
│           └── Task: kubectl apply                                            │
│                                                                              │
│   ∙ Stage: 순차 실행 (이전 Stage 성공 후 실행)                                │
│   ∙ Job: 같은 Stage 내에서 병렬 실행 가능                                     │
│   ∙ Task: Job 내에서 순차 실행                                                │
│                                                                              │
```

## 🛠️ Part 2: GoCD 설치

### 방법 1: Docker Compose

```yaml
# docker-compose.yaml
version: '3'
services:
  gocd-server:
    image: gocd/gocd-server:v23.5.0
    ports:
      - "8153:8153"   # HTTP
      - "8154:8154"   # HTTPS
    volumes:
      - gocd-data:/godata
      - gocd-home:/home/go
    environment:
      - GOCD_PLUGIN_INSTALL_kubernetes-elastic-agents=https://github.com/gocd/kubernetes-elastic-agents/releases/download/v4.0.0/kubernetes-elastic-agent-4.0.0-310.jar

  gocd-agent:
    image: gocd/gocd-agent-alpine-3.18:v23.5.0
    depends_on:
      - gocd-server
    environment:
      - GO_SERVER_URL=https://gocd-server:8154/go
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock  # Docker in Docker

volumes:
  gocd-data:
  gocd-home:
```

```bash
# 실행
docker-compose up -d

# 접속: http://localhost:8153
```

### 방법 2: Kubernetes (Helm)

```bash
# Helm Repository 추가
helm repo add gocd https://gocd.github.io/helm-chart
helm repo update

# 설치
helm install gocd gocd/gocd \
  -n gocd --create-namespace \
  --set server.persistence.enabled=true \
  --set agent.persistence.enabled=false \
  --set agent.replicaCount=2

# 접속
kubectl port-forward svc/gocd-server -n gocd 8153:8153
```

## 🛠️ Part 3: Pipeline as Code

### 기본 구조

```yaml
# gocd.yaml
format_version: 10
pipelines:
  myapp:
    group: production             # Pipeline 그룹
    display_order: 1              # UI 순서
    lock_behavior: unlockWhenFinished  # 동시 실행 제어
    
    materials:                    # 트리거 소스
      git:
        git: https://github.com/myorg/myapp.git
        branch: main
        auto_update: true         # 자동 트리거
    
    environment_variables:        # 환경 변수
      DOCKER_REGISTRY: registry.example.com
    
    stages:
    - build:
        clean_workspace: true
        jobs:
          build:
            tasks:
            - exec:
                command: docker
                arguments:
                - build
                - -t
                - ${DOCKER_REGISTRY}/myapp:${GO_PIPELINE_COUNTER}
                - .
            - exec:
                command: docker
                arguments:
                - push
                - ${DOCKER_REGISTRY}/myapp:${GO_PIPELINE_COUNTER}
```

### 완전한 CI/CD Pipeline

```yaml
# gocd.yaml
format_version: 10
pipelines:
  myapp-ci-cd:
    group: production
    
    materials:
      app-repo:
        git: https://github.com/myorg/myapp.git
        branch: main
        destination: app
      infra-repo:
        git: https://github.com/myorg/infra.git
        branch: main
        destination: infra
    
    environment_variables:
      DOCKER_REGISTRY: registry.example.com
      APP_NAME: myapp
    
    stages:
    # Stage 1: Build
    - build:
        clean_workspace: true
        jobs:
          build-image:
            elastic_profile_id: k8s-builder  # K8s Agent
            tasks:
            - exec:
                working_directory: app
                command: docker
                arguments:
                - build
                - -t
                - ${DOCKER_REGISTRY}/${APP_NAME}:${GO_PIPELINE_COUNTER}
                - .
            - exec:
                command: docker
                arguments:
                - push
                - ${DOCKER_REGISTRY}/${APP_NAME}:${GO_PIPELINE_COUNTER}
    
    # Stage 2: Test (병렬)
    - test:
        jobs:
          unit-test:
            elastic_profile_id: k8s-tester
            tasks:
            - exec:
                working_directory: app
                command: npm
                arguments: [test]
            artifacts:
            - test:
                source: coverage/**/*
                destination: coverage
          
          lint:
            elastic_profile_id: k8s-tester
            tasks:
            - exec:
                working_directory: app
                command: npm
                arguments: [run, lint]
          
          security-scan:
            elastic_profile_id: k8s-scanner
            tasks:
            - exec:
                command: trivy
                arguments:
                - image
                - ${DOCKER_REGISTRY}/${APP_NAME}:${GO_PIPELINE_COUNTER}
    
    # Stage 3: Deploy to Staging
    - deploy-staging:
        approval:
          type: success  # 자동 진행
        jobs:
          deploy:
            elastic_profile_id: k8s-deployer
            tasks:
            - exec:
                working_directory: infra
                command: /bin/bash
                arguments:
                - -c
                - |
                  # 이미지 태그 업데이트
                  sed -i "s|image:.*|image: ${DOCKER_REGISTRY}/${APP_NAME}:${GO_PIPELINE_COUNTER}|g" \
                    overlays/staging/kustomization.yaml
                  kubectl apply -k overlays/staging/
    
    # Stage 4: Deploy to Production (수동 승인)
    - deploy-production:
        approval:
          type: manual             # 수동 승인 필요
          roles:
          - deployer
        jobs:
          deploy:
            elastic_profile_id: k8s-deployer
            tasks:
            - exec:
                working_directory: infra
                command: /bin/bash
                arguments:
                - -c
                - |
                  sed -i "s|image:.*|image: ${DOCKER_REGISTRY}/${APP_NAME}:${GO_PIPELINE_COUNTER}|g" \
                    overlays/prod/kustomization.yaml
                  kubectl apply -k overlays/prod/
```

## 🛠️ Part 4: GoCD 환경 변수

### 기본 제공 변수

| 변수 | 설명 |
|------|------|
| `GO_PIPELINE_NAME` | 파이프라인 이름 |
| `GO_PIPELINE_COUNTER` | 파이프라인 실행 번호 |
| `GO_STAGE_NAME` | Stage 이름 |
| `GO_JOB_NAME` | Job 이름 |
| `GO_REVISION` | Git 커밋 해시 |
| `GO_FROM_REVISION` | 이전 실행의 커밋 |
| `GO_TO_REVISION` | 현재 실행의 커밋 |

### 커스텀 환경 변수

```yaml
pipelines:
  myapp:
    environment_variables:
      DOCKER_REGISTRY: registry.example.com
      DEPLOY_ENV: staging
    
    secure_variables:            # 암호화된 변수
      DOCKER_PASSWORD: AES:encrypted_value
    
    stages:
    - build:
        environment_variables:   # Stage 레벨 변수
          BUILD_TYPE: release
        jobs:
          build:
            environment_variables:  # Job 레벨 변수
              PARALLEL_JOBS: "4"
```

## 🛠️ Part 5: Value Stream Map

### VSM 개념

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                     Value Stream Map                                         │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   Git ─▶ [Build] ─▶ [Test] ─▶ [Staging] ─▶ [Production]                     │
│                                                                              │
│   • 전체 배포 흐름을 시각화                                                   │
│   • 각 Stage의 상태 확인                                                      │
│   • 병목 지점 식별                                                            │
│   • 어떤 커밋이 어느 환경에 배포되었는지 추적                                   │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

### Fan-in/Fan-out

```yaml
# Fan-out: 하나의 Pipeline이 여러 Pipeline 트리거
pipelines:
  build:
    stages: [...]
  
  deploy-staging:
    materials:
      upstream:
        pipeline: build
        stage: build
  
  deploy-prod:
    materials:
      upstream:
        pipeline: build
        stage: build

# Fan-in: 여러 Pipeline이 완료되면 하나의 Pipeline 트리거
pipelines:
  integration-test:
    materials:
      frontend:
        pipeline: frontend-build
        stage: build
      backend:
        pipeline: backend-build
        stage: build
```
