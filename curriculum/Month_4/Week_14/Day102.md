## 📚 Part 1: ArgoCD + Kustomize 개념

### 동작 원리

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    ArgoCD + Kustomize 연동                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   Git Repository                                                             │
│   ├── base/                                                                  │
│   │   ├── deployment.yaml                                                    │
│   │   ├── service.yaml                                                       │
│   │   └── kustomization.yaml                                                 │
│   └── overlays/                                                              │
│       ├── dev/                                                               │
│       │   └── kustomization.yaml  ◀─── ArgoCD App (dev)                     │
│       ├── staging/                                                           │
│       │   └── kustomization.yaml  ◀─── ArgoCD App (staging)                 │
│       └── prod/                                                              │
│           └── kustomization.yaml  ◀─── ArgoCD App (prod)                    │
│                                                                              │
│   ArgoCD는 자동으로 Kustomize를 감지하고                                      │
│   kustomize build를 실행하여 매니페스트를 생성합니다.                          │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 왜 Kustomize + ArgoCD인가?

| 장점 | 설명 |
|------|------|
| **환경 분리** | Dev, Staging, Prod 각각 관리 |
| **DRY 원칙** | base를 공유하여 중복 제거 |
| **GitOps** | Git에서 모든 환경 설정 관리 |
| **자동 감지** | ArgoCD가 kustomization.yaml 자동 인식 |

## 🛠️ Part 2: ArgoCD Application 설정

### 기본 Application (Kustomize)

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp-dev
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/user/infra-repo.git
    targetRevision: HEAD
    path: overlays/dev   # Kustomize overlay 경로
  destination:
    server: https://kubernetes.default.svc
    namespace: dev
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
    - CreateNamespace=true
```

### 환경별 Application

```yaml
# dev-app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp-dev
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/user/infra-repo.git
    targetRevision: HEAD
    path: overlays/dev
  destination:
    server: https://kubernetes.default.svc
    namespace: dev
  syncPolicy:
    automated:
      selfHeal: true
      prune: true
---
# staging-app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp-staging
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/user/infra-repo.git
    targetRevision: HEAD
    path: overlays/staging
  destination:
    server: https://kubernetes.default.svc
    namespace: staging
  syncPolicy:
    automated:
      selfHeal: true
      prune: false  # staging은 prune 비활성화
---
# prod-app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp-prod
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/user/infra-repo.git
    targetRevision: main  # prod는 main 브랜치만
    path: overlays/prod
  destination:
    server: https://kubernetes.default.svc
    namespace: prod
  syncPolicy:
    automated: {}  # prod는 수동 sync (또는 최소 설정)
```

## 🛠️ Part 3: Kustomize 고급 옵션

### ArgoCD 내 Kustomize 옵션

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp
spec:
  source:
    repoURL: https://github.com/user/repo.git
    path: overlays/prod
    kustomize:
      # 이름 접두사/접미사
      namePrefix: prod-
      nameSuffix: -v1
      
      # 이미지 오버라이드
      images:
      - nginx=nginx:1.25
      - myapp=registry.example.com/myapp:v2.0.0
      
      # 공통 라벨
      commonLabels:
        environment: production
        team: platform
      
      # 공통 어노테이션
      commonAnnotations:
        owner: devops-team
```

### 여러 환경에 다른 이미지 배포

```yaml
# Dev: 최신 이미지
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp-dev
spec:
  source:
    path: overlays/dev
    kustomize:
      images:
      - myapp=myapp:latest
---
# Prod: 고정 버전
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp-prod
spec:
  source:
    path: overlays/prod
    kustomize:
      images:
      - myapp=myapp:v1.2.3
```

## 🛠️ Part 4: App of Apps 패턴

### 여러 환경을 하나의 App으로 관리

```yaml
# apps/root-app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: root-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/user/infra-repo.git
    path: apps
    targetRevision: HEAD
  destination:
    server: https://kubernetes.default.svc
    namespace: argocd
  syncPolicy:
    automated:
      selfHeal: true
      prune: true
```

### apps/ 디렉토리 구조

```
apps/
├── kustomization.yaml
├── dev-app.yaml
├── staging-app.yaml
└── prod-app.yaml
```

### apps/kustomization.yaml

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
- dev-app.yaml
- staging-app.yaml
- prod-app.yaml
```

## 🛠️ Part 5: 실습 - 전체 워크플로우

### 1. Git Repository 구조

```
infra-repo/
├── apps/
│   ├── kustomization.yaml
│   ├── dev-app.yaml
│   ├── staging-app.yaml
│   └── prod-app.yaml
├── base/
│   ├── deployment.yaml
│   ├── service.yaml
│   └── kustomization.yaml
└── overlays/
    ├── dev/
    │   ├── kustomization.yaml
    │   └── patch-replicas.yaml
    ├── staging/
    │   └── kustomization.yaml
    └── prod/
        ├── kustomization.yaml
        └── patch-replicas.yaml
```

### 2. base/kustomization.yaml

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
- deployment.yaml
- service.yaml
```

### 3. overlays/prod/kustomization.yaml

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: prod
resources:
- ../../base
patches:
- path: patch-replicas.yaml
images:
- name: myapp
  newTag: v1.2.3
```

### 4. ArgoCD에서 확인

```bash
# Application 상태 확인
argocd app list

# 특정 환경 동기화
argocd app sync myapp-dev
argocd app sync myapp-prod

# 환경별 상태 확인
argocd app get myapp-dev
argocd app get myapp-prod
```
