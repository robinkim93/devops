```bash
# 아키텍처 상세

## GitOps 워크플로우

```
Developer → Git Push → ArgoCD Detect → Sync → Kubernetes

1. 개발자가 config 레포지토리에 변경 푸시
2. ArgoCD가 변경 감지 (폴링 또는 웹훅)
3. 현재 상태와 원하는 상태 비교
4. 차이가 있으면 자동 동기화
5. Kubernetes에 변경 적용
```

## 시크릿 관리 흐름

```
Vault → External Secrets → Kubernetes Secret → Pod

1. Vault에 시크릿 저장
2. ExternalSecret이 Vault에서 시크릿 조회
3. Kubernetes Secret 생성/갱신
4. Pod가 Secret 마운트하여 사용
```

## 환경별 설정

```
Base (공통)
  │
  ├── Overlay: Dev
  │   └── replicas: 1, resources: 낮음
  │
  └── Overlay: Prod
      └── replicas: 3, resources: 높음
```
EOF
```

### 면접 대비 핵심

**Q1: GitOps란 무엇인가요?**
> "Git을 Single Source of Truth로 사용하여 인프라와 애플리케이션을 선언적으로 관리하는 방식입니다. 모든 변경은 Git을 통해 이루어지고, ArgoCD 같은 도구가 Git 상태를 클러스터에 자동으로 동기화합니다."

**Q2: ArgoCD의 Self-Heal이란?**
> "클러스터 상태가 Git의 원하는 상태와 다를 때 자동으로 복구하는 기능입니다. 수동 변경이나 드리프트가 발생해도 Git 상태로 되돌립니다."

**Q3: Vault Kubernetes 인증의 장점은?**
> "Pod가 ServiceAccount 토큰으로 자동 인증하므로 시크릿을 하드코딩할 필요가 없습니다. 정책 기반 접근 제어로 최소 권한 원칙을 적용할 수 있습니다."

**Q4: Helm과 Kustomize의 차이는?**
> "Helm은 템플릿 기반으로 변수를 치환하고 차트로 패키징합니다. Kustomize는 패치/오버레이 방식으로 순수 YAML을 수정합니다. Helm은 복잡한 로직에, Kustomize는 간단한 환경별 설정에 적합합니다."
