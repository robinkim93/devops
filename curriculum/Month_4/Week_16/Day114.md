## 🛠️ Part 1: ArgoCD HA 설치

### 설치

```bash
kubectl create namespace argocd

# HA 모드 설치 (Production)
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/v2.9.3/manifests/ha/install.yaml

# 또는 Helm
helm repo add argo https://argoproj.github.io/argo-helm
helm install argocd argo/argo-cd \
  -n argocd \
  --set server.replicas=2 \
  --set controller.replicas=2 \
  --set repoServer.replicas=2
```

### 접속

```bash
# Port Forward
kubectl port-forward svc/argocd-server -n argocd 8080:443

# 초기 비밀번호
kubectl get secret argocd-initial-admin-secret -n argocd -o jsonpath='{.data.password}' | base64 -d

# CLI 로그인
argocd login localhost:8080 --insecure
```

## 🛠️ Part 2: ArgoCD Application

### Project 생성

```yaml
# apps/project.yaml
apiVersion: argoproj.io/v1alpha1
kind: AppProject
metadata:
  name: gitops-portfolio
  namespace: argocd
spec:
  description: "GitOps CI/CD Portfolio Project"
  
  sourceRepos:
  - 'https://github.com/YOUR_USER/infra-repo.git'
  
  destinations:
  - namespace: dev
    server: https://kubernetes.default.svc
  - namespace: staging
    server: https://kubernetes.default.svc
  - namespace: production
    server: https://kubernetes.default.svc
  
  clusterResourceWhitelist:
  - group: ''
    kind: Namespace
  
  namespaceResourceWhitelist:
  - group: '*'
    kind: '*'
```

### Staging Application

```yaml
# apps/myapp-staging.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp-staging
  namespace: argocd
  finalizers:
    - resources-finalizer.argocd.argoproj.io
spec:
  project: gitops-portfolio
  
  source:
    repoURL: https://github.com/YOUR_USER/infra-repo.git
    targetRevision: main
    path: overlays/staging
  
  destination:
    server: https://kubernetes.default.svc
    namespace: staging
  
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
      allowEmpty: false
    syncOptions:
    - CreateNamespace=true
    - PruneLast=true
    retry:
      limit: 5
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m
```

### Production Application (수동 승인)

```yaml
# apps/myapp-prod.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp-prod
  namespace: argocd
spec:
  project: gitops-portfolio
  
  source:
    repoURL: https://github.com/YOUR_USER/infra-repo.git
    targetRevision: main
    path: overlays/prod
  
  destination:
    server: https://kubernetes.default.svc
    namespace: production
  
  # automated 없음 = 수동 Sync
  syncPolicy:
    syncOptions:
    - CreateNamespace=true
```

## 🛠️ Part 3: App of Apps 패턴

### Root Application

```yaml
# apps/root-app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: root-app
  namespace: argocd
  finalizers:
    - resources-finalizer.argocd.argoproj.io
spec:
  project: default
  
  source:
    repoURL: https://github.com/YOUR_USER/infra-repo.git
    targetRevision: main
    path: apps  # 다른 Application YAML들이 있는 디렉토리
  
  destination:
    server: https://kubernetes.default.svc
    namespace: argocd
  
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
```

### 적용

```bash
# Root App만 생성하면 나머지는 자동
kubectl apply -f apps/root-app.yaml

# 확인
argocd app list
```

## 🛠️ Part 4: 자동 동기화 테스트

### Git 변경 → 자동 배포 확인

```bash
# Infra Repo에서 변경
cd infra-repo
echo "# test" >> README.md
git add . && git commit -m "test: trigger argocd"
git push

# ArgoCD에서 자동 감지 확인
argocd app get myapp-staging

# Pod 확인
kubectl get pods -n staging -w
```

### 롤백 테스트

```bash
# 히스토리 확인
argocd app history myapp-staging

# 롤백
argocd app rollback myapp-staging 1

# Git으로 롤백 (GitOps 방식)
cd infra-repo
git revert HEAD
git push
```
