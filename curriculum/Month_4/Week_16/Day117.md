## 🛠️ Part 2: Rollout 리소스 정의

### overlays/prod/rollout.yaml

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Rollout
metadata:
  name: myapp
spec:
  replicas: 5
  revisionHistoryLimit: 3
  
  selector:
    matchLabels:
      app: myapp
  
  template:
    metadata:
      labels:
        app: myapp
    spec:
      serviceAccountName: myapp
      containers:
      - name: myapp
        image: docker.io/YOUR_USER/myapp:v1.0.0
        ports:
        - containerPort: 8080
        env:
        - name: DB_HOST
          valueFrom:
            secretKeyRef:
              name: myapp-secrets
              key: DB_HOST
        resources:
          requests:
            cpu: 500m
            memory: 512Mi
  
  strategy:
    canary:
      # 카나리 단계
      steps:
      - setWeight: 10
      - pause: {duration: 2m}
      - setWeight: 25
      - pause: {duration: 2m}
      - setWeight: 50
      - pause: {duration: 5m}
      - setWeight: 75
      - pause: {duration: 5m}
      - setWeight: 100
      
      # Analysis 기반 자동 롤백 (선택)
      analysis:
        templates:
        - templateName: success-rate
        startingStep: 2
        args:
        - name: service-name
          value: myapp
      
      # 트래픽 관리
      canaryService: myapp-canary
      stableService: myapp-stable
      
      # Anti-Affinity (Canary와 Stable 분리)
      antiAffinity:
        requiredDuringSchedulingIgnoredDuringExecution: {}
```

### Services

```yaml
# overlays/prod/services.yaml
apiVersion: v1
kind: Service
metadata:
  name: myapp-stable
spec:
  selector:
    app: myapp
  ports:
  - port: 80
    targetPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: myapp-canary
spec:
  selector:
    app: myapp
  ports:
  - port: 80
    targetPort: 8080
```

## 🛠️ Part 3: Analysis Template (자동 롤백)

```yaml
# overlays/prod/analysis-template.yaml
apiVersion: argoproj.io/v1alpha1
kind: AnalysisTemplate
metadata:
  name: success-rate
spec:
  args:
  - name: service-name
  metrics:
  - name: success-rate
    interval: 1m
    count: 5
    successCondition: result[0] >= 0.95
    failureLimit: 3
    provider:
      prometheus:
        address: http://prometheus.monitoring:9090
        query: |
          sum(rate(
            http_requests_total{service="{{args.service-name}}",status=~"2.."}[5m]
          )) / sum(rate(
            http_requests_total{service="{{args.service-name}}"}[5m]
          ))
```

## 🛠️ Part 4: 배포 및 모니터링

### 배포 트리거

```bash
# 이미지 변경
kubectl argo rollouts set image myapp myapp=docker.io/YOUR_USER/myapp:v1.1.0 -n production
```

### 상태 모니터링

```bash
# 실시간 상태 확인
kubectl argo rollouts get rollout myapp -n production -w

# 예상 출력:
# Name:            myapp
# Namespace:       production
# Status:          ॥ Paused
# Strategy:        Canary
#   Step:          2/9
#   SetWeight:     10
#   ActualWeight:  10
# Images:          docker.io/YOUR_USER/myapp:v1.0.0 (stable)
#                  docker.io/YOUR_USER/myapp:v1.1.0 (canary)
# Replicas:
#   Desired:       5
#   Current:       6
#   Updated:       1
#   Ready:         6
#   Available:     6
```

### 수동 제어

```bash
# 다음 단계로 진행
kubectl argo rollouts promote myapp -n production

# 전체 완료 (모든 단계 스킵)
kubectl argo rollouts promote myapp --full -n production

# 롤백 (즉시)
kubectl argo rollouts abort myapp -n production

# 이전 버전으로 완전 롤백
kubectl argo rollouts undo myapp -n production
```

### 대시보드

```bash
# Argo Rollouts 대시보드
kubectl argo rollouts dashboard

# 브라우저: http://localhost:3100
```

## 🛠️ Part 5: kustomization.yaml 수정

```yaml
# overlays/prod/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

namespace: production

resources:
- ../../base
- rollout.yaml         # Deployment 대신 Rollout
- services.yaml        # Stable/Canary Services
- analysis-template.yaml

# 기존 Deployment 제거
patches:
- target:
    kind: Deployment
    name: myapp
  patch: |
    $patch: delete
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: myapp
```
