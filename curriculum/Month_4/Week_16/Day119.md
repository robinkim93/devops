## 🧪 Part 1: CI 파이프라인 테스트 (GoCD)

### 테스트 시나리오

```bash
# 1. 코드 변경
cd app-repo
echo "// v1.1.0 release" >> cmd/main.go
git add . && git commit -m "feat: new feature for v1.1.0"
git push origin main
```

### 확인 체크리스트

| Stage | 확인 사항 | 명령어 | 상태 |
|-------|----------|--------|------|
| Build | 이미지 빌드 성공 | GoCD UI | ☐ |
| Test | 단위 테스트 통과 | GoCD UI | ☐ |
| Security | Trivy 스캔 통과 | GoCD UI | ☐ |
| Push | 레지스트리 푸시 | `docker pull ...` | ☐ |
| Update | Infra Repo 커밋 | `git log` | ☐ |

### Infra Repo 변경 확인

```bash
cd infra-repo
git pull

# kustomization.yaml에서 이미지 태그 확인
cat overlays/staging/kustomization.yaml | grep newTag

# 예상: newTag: abc1234 (최신 커밋 SHA)
```

## 🧪 Part 2: CD 테스트 (ArgoCD)

### 자동 동기화 확인

```bash
# ArgoCD 앱 상태
argocd app get myapp-staging

# 예상 출력:
# Name:               argocd/myapp-staging
# Project:            gitops-portfolio
# Status:             Synced
# Health:             Healthy
# Sync Status:        Synced to main (abc1234)

# Pod 상태
kubectl get pods -n staging -l app=myapp

# 이미지 버전 확인
kubectl get deployment staging-myapp -n staging -o jsonpath='{.spec.template.spec.containers[0].image}'
```

### Self-Heal 테스트

```bash
# 수동으로 replicas 변경
kubectl scale deployment staging-myapp -n staging --replicas=1

# 30초 후 ArgoCD가 자동 복구
kubectl get deployment staging-myapp -n staging -w

# 원래 replicas (2)로 복구되어야 함
```

### 롤백 테스트

```bash
# 히스토리 확인
argocd app history myapp-staging

# 이전 버전으로 롤백
argocd app rollback myapp-staging 1

# 또는 Git revert
cd infra-repo
git revert HEAD
git push

# ArgoCD 자동 Sync 확인
argocd app get myapp-staging
```

## 🧪 Part 3: 시크릿 테스트 (Vault + ESO)

### Vault 시크릿 확인

```bash
# Vault에서 시크릿 조회
kubectl exec -n vault vault-0 -- vault kv get secret/myapp/staging

# 예상 출력:
# ====== Data ======
# Key           Value
# ---           -----
# api_key       staging-api-key
# db_host       staging-db.example.com
# db_password   staging-secret
```

### ExternalSecret 상태 확인

```bash
# ExternalSecret 상태
kubectl get externalsecret -n staging

# 예상 출력:
# NAME            STORE           REFRESH   STATUS         READY
# myapp-secrets   vault-backend   1h        SecretSynced   True

# 상세 정보
kubectl describe externalsecret myapp-secrets -n staging
```

### K8s Secret 확인

```bash
# 생성된 Secret 확인
kubectl get secret myapp-secrets -n staging -o yaml

# 값 디코딩
kubectl get secret myapp-secrets -n staging -o jsonpath='{.data.DB_PASSWORD}' | base64 -d

# 예상: staging-secret
```

### 시크릿 변경 동기화 테스트

```bash
# Vault에서 시크릿 업데이트
kubectl exec -n vault vault-0 -- vault kv put secret/myapp/staging \
  db_password="new-staging-secret" \
  db_host="staging-db.example.com" \
  api_key="staging-api-key"

# 1시간 대기 또는 강제 새로고침
kubectl annotate externalsecret myapp-secrets -n staging force-sync=$(date +%s)

# K8s Secret 업데이트 확인
kubectl get secret myapp-secrets -n staging -o jsonpath='{.data.DB_PASSWORD}' | base64 -d
```

## 🧪 Part 4: 카나리 배포 테스트 (Argo Rollouts)

### 새 버전 배포

```bash
# 이미지 업데이트로 Rollout 트리거
kubectl argo rollouts set image myapp myapp=docker.io/YOUR_USER/myapp:v1.1.0 -n production
```

### Rollout 모니터링

```bash
# 실시간 상태 확인
kubectl argo rollouts get rollout myapp -n production -w

# 예상 출력:
# Name:            myapp
# Namespace:       production
# Status:          ॥ Paused
# Strategy:        Canary
#   Step:          1/9
#   SetWeight:     10
#   ActualWeight:  10
# Images:          docker.io/YOUR_USER/myapp:v1.0.0 (stable)
#                  docker.io/YOUR_USER/myapp:v1.1.0 (canary)
```

### 각 단계 진행

```bash
# 다음 단계로 수동 진행
kubectl argo rollouts promote myapp -n production

# 전체 완료 (모든 단계 스킵)
kubectl argo rollouts promote myapp --full -n production
```

### 롤백 테스트

```bash
# 배포 중단 (즉시 롤백)
kubectl argo rollouts abort myapp -n production

# 상태 확인 (stable로 복구)
kubectl argo rollouts get rollout myapp -n production
```
