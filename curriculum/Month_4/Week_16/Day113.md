# Day 113: Vault Kubernetes 인증

## 오늘의 목표

토스플레이스 연결점: "Vault를 이용한 시크릿 관리"
"보안 컴플라이언스를 고려한 클라우드 인프라 설계"

## Part 1: Kubernetes 인증 개념 (45분)

### 1.1 Vault 인증 방식

```
Vault 인증 방식 종류:

1. Token
   - 직접 토큰 사용
   - 간단하지만 토큰 관리 필요

2. Kubernetes (K8s)
   - ServiceAccount 토큰으로 인증
   - Pod가 자동으로 인증
   - 권장 방식

3. AppRole
   - 애플리케이션용 Role ID + Secret ID
   - CI/CD 파이프라인에서 사용

4. AWS/GCP/Azure
   - 클라우드 IAM 연동
   - 인스턴스 메타데이터로 인증
```

### 1.2 Kubernetes 인증 흐름

```
K8s Auth 흐름:

1. Pod 시작
   └─> ServiceAccount 토큰 마운트
       (/var/run/secrets/kubernetes.io/serviceaccount/token)

2. Pod → Vault 인증 요청
   └─> ServiceAccount JWT 토큰 전송

3. Vault → K8s API 검증
   └─> TokenReview API로 토큰 유효성 확인

4. Vault → 정책 적용
   └─> 역할(Role)에 연결된 정책 확인

5. Vault → 클라이언트 토큰 발급
   └─> Pod가 시크릿 조회 가능

┌─────────────────────────────────────────────────────────────────┐
│  Pod (ServiceAccount: myapp)                                    │
│  ┌───────────────────────────────────────────────────────────┐ │
│  │ 1. SA Token으로 Vault 인증 요청                            │ │
│  │    vault login -method=kubernetes role=myapp-role          │ │
│  └───────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
           │
           │ 2. JWT Token
           ▼
┌─────────────────────────────────────────────────────────────────┐
│  Vault                                                           │
│  ┌───────────────────────────────────────────────────────────┐ │
│  │ 3. K8s API에 TokenReview 요청                              │ │
│  │ 4. 역할(Role) 확인 → 정책(Policy) 확인                     │ │
│  │ 5. Vault Token 발급                                        │ │
│  └───────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
           │
           │ 3. TokenReview
           ▼
┌─────────────────────────────────────────────────────────────────┐
│  Kubernetes API Server                                           │
│  ┌───────────────────────────────────────────────────────────┐ │
│  │ ServiceAccount 토큰 검증                                   │ │
│  └───────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 핵심 구성요소

| 구성요소 | 설명 |
|---------|------|
| **Auth Method** | kubernetes (K8s 인증 활성화) |
| **Role** | ServiceAccount와 정책을 연결 |
| **Policy** | 시크릿 접근 권한 정의 |
| **ServiceAccount** | Pod에 할당된 K8s 계정 |

## Part 2: Vault Kubernetes 인증 설정 (1시간)

### 실습 1: Vault 설치 (Helm)

```bash
# Vault Helm 저장소 추가
helm repo add hashicorp https://helm.releases.hashicorp.com
helm repo update

# Namespace 생성
kubectl create namespace vault

# Vault 설치 (Dev 모드)
helm install vault hashicorp/vault \
  -n vault \
  --set "server.dev.enabled=true" \
  --set "server.dev.devRootToken=root"

# Pod 확인
kubectl get pods -n vault

# Vault UI 접속 (선택)
kubectl port-forward svc/vault -n vault 8200:8200 &
echo "Vault UI: http://localhost:8200 (Token: root)"
```

### 실습 2: Kubernetes 인증 활성화

```bash
# Vault Pod에 접속
kubectl exec -it vault-0 -n vault -- /bin/sh

# Vault 로그인 (Dev 모드)
vault login root

# Kubernetes 인증 활성화
vault auth enable kubernetes

# Kubernetes 인증 설정
vault write auth/kubernetes/config \
  kubernetes_host="https://kubernetes.default.svc:443" \
  token_reviewer_jwt="$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  kubernetes_ca_cert="$(cat /var/run/secrets/kubernetes.io/serviceaccount/ca.crt)" \
  issuer="https://kubernetes.default.svc.cluster.local"

# 설정 확인
vault read auth/kubernetes/config

exit
```

### 실습 3: 테스트용 시크릿 생성

```bash
# Vault Pod에서
kubectl exec -it vault-0 -n vault -- /bin/sh

vault login root

# KV 시크릿 엔진 활성화
vault secrets enable -path=secret kv-v2

# 시크릿 생성
vault kv put secret/myapp/config \
  db_host="mysql.default.svc" \
  db_user="appuser" \
  db_password="s3cr3tP@ss" \
  api_key="my-api-key-12345"

# 시크릿 확인
vault kv get secret/myapp/config

exit
```

## Part 3: 정책 및 역할 설정 (1시간)

### 실습 4: Vault 정책 생성

```bash
kubectl exec -it vault-0 -n vault -- /bin/sh

vault login root

# 정책 생성 (HCL 형식)
vault policy write myapp-policy - <<EOF
path "secret/data/myapp/*" {
  capabilities = ["read", "list"]
}
EOF

# 정책 확인
vault policy read myapp-policy

# 정책 목록
vault policy list

exit
```

### 실습 5: Kubernetes 역할 생성

```bash
kubectl exec -it vault-0 -n vault -- /bin/sh

vault login root

# Kubernetes 역할 생성
vault write auth/kubernetes/role/myapp-role \
  bound_service_account_names=myapp-sa \
  bound_service_account_namespaces=default \
  policies=myapp-policy \
  ttl=1h

# 역할 확인
vault read auth/kubernetes/role/myapp-role

exit
```

**역할 파라미터 설명:**

| 파라미터 | 설명 |
|---------|------|
| bound_service_account_names | 허용된 ServiceAccount 이름 |
| bound_service_account_namespaces | 허용된 Namespace |
| policies | 연결된 정책 |
| ttl | 토큰 유효 시간 |

### 실습 6: ServiceAccount 생성

```bash
# ServiceAccount 생성
kubectl create serviceaccount myapp-sa

# 확인
kubectl get serviceaccount myapp-sa -o yaml
```

## Part 4: Pod에서 시크릿 조회 테스트 (1시간 15분)

### 실습 7: 테스트 Pod 배포

```bash
# 테스트 Pod (Vault CLI 포함)
kubectl apply -f - <<EOF
apiVersion: v1
kind: Pod
metadata:
  name: vault-test
spec:
  serviceAccountName: myapp-sa
  containers:
  - name: vault-test
    image: hashicorp/vault:latest
    command: ["sleep", "3600"]
    env:
    - name: VAULT_ADDR
      value: "http://vault.vault.svc:8200"
EOF

# Pod 상태 확인
kubectl get pod vault-test

# Pod 접속
kubectl exec -it vault-test -- /bin/sh
```

### 실습 8: Pod에서 Vault 인증

```bash
# Pod 내부에서

# ServiceAccount 토큰 확인
cat /var/run/secrets/kubernetes.io/serviceaccount/token | head -c 100

# Kubernetes 인증으로 Vault 로그인
vault write auth/kubernetes/login \
  role=myapp-role \
  jwt="$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)"

# 출력 예시:
# Key                  Value
# ---                  -----
# token                hvs.XXXXXXXXX
# token_accessor       xxx
# token_duration       1h
# token_policies       ["default" "myapp-policy"]

# 발급된 토큰으로 로그인
export VAULT_TOKEN=<위에서 받은 token>

# 시크릿 조회
vault kv get secret/myapp/config

# 특정 필드만 조회
vault kv get -field=db_password secret/myapp/config

exit
```

### 실습 9: 스크립트로 자동화

```bash
# 자동 인증 스크립트
kubectl exec -it vault-test -- /bin/sh -c '
# Vault 주소 설정
export VAULT_ADDR="http://vault.vault.svc:8200"

# K8s 인증으로 토큰 발급
VAULT_TOKEN=$(vault write -field=token auth/kubernetes/login \
  role=myapp-role \
  jwt="$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)")

export VAULT_TOKEN

# 시크릿 조회
echo "=== Secrets ==="
vault kv get -format=json secret/myapp/config | jq -r ".data.data"
'
```

### 실습 10: 애플리케이션 통합 예시

```bash
# Init Container로 시크릿 가져오기
kubectl apply -f - <<EOF
apiVersion: v1
kind: Pod
metadata:
  name: app-with-secrets
spec:
  serviceAccountName: myapp-sa
  
  initContainers:
  - name: vault-init
    image: hashicorp/vault:latest
    env:
    - name: VAULT_ADDR
      value: "http://vault.vault.svc:8200"
    command:
    - /bin/sh
    - -c
    - |
      # Vault 인증
      VAULT_TOKEN=\$(vault write -field=token auth/kubernetes/login \
        role=myapp-role \
        jwt="\$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)")
      
      export VAULT_TOKEN
      
      # 시크릿을 파일로 저장
      vault kv get -field=db_password secret/myapp/config > /secrets/db_password
      vault kv get -field=api_key secret/myapp/config > /secrets/api_key
    volumeMounts:
    - name: secrets
      mountPath: /secrets
  
  containers:
  - name: app
    image: nginx
    volumeMounts:
    - name: secrets
      mountPath: /app/secrets
      readOnly: true
    command:
    - /bin/sh
    - -c
    - |
      echo "DB Password: \$(cat /app/secrets/db_password)"
      echo "API Key: \$(cat /app/secrets/api_key)"
      sleep 3600
  
  volumes:
  - name: secrets
    emptyDir:
      medium: Memory
EOF

# 로그 확인
kubectl logs app-with-secrets -c app
```

## 면접 대비

**Q: Vault Kubernetes 인증의 장점은?**
> "Pod가 ServiceAccount 토큰을 사용하여 자동으로 Vault에 인증합니다. 시크릿을 하드코딩하거나 수동으로 토큰을 관리할 필요가 없어 보안이 강화됩니다."

**Q: Vault 정책은 어떻게 작성하나요?**
> "HCL 형식으로 path와 capabilities를 정의합니다. path는 시크릿 경로, capabilities는 read, list, create 등 허용 작업을 지정합니다."
