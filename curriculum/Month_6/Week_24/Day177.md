# 🚀 토스플레이스 DevOps 인프라 클론

> AWS 기반 프로덕션 수준 Cloud Native DevOps 플랫폼

[![Terraform](https://img.shields.io/badge/Terraform-1.6+-623CE4?logo=terraform)](https://www.terraform.io/)

## 📋 프로젝트 개요

토스플레이스 DevOps Engineer 포지션 준비를 위해 **실제 프로덕션 환경과 동일한 수준**의 Cloud Native 인프라를 구축한 프로젝트입니다.

### 주요 특징

- ✅ **Infrastructure as Code**: 전체 인프라를 Terraform으로 코드화
- ✅ **Service Mesh**: Istio 기반 트래픽 관리 및 mTLS 보안
- ✅ **GitOps**: ArgoCD를 통한 선언적 배포 자동화
- ✅ **Observability**: Prometheus + Thanos + Grafana 모니터링 스택
- ✅ **High Availability**: 멀티 AZ 구성으로 고가용성 확보

## 🚀 Quick Start

### 사전 요구사항

- AWS CLI 설정 완료
- Terraform 1.6+
- kubectl
- Helm 3.x
- istioctl

### 1. 레포지토리 클론

```bash
git clone https://github.com/YOUR_USERNAME/tossplace-infra-clone
cd tossplace-infra-clone
```

### 2. AWS 인프라 배포

```bash
# Backend 리소스 생성 (최초 1회)
cd infrastructure/global/backend
terraform init && terraform apply

# Dev 환경 배포
cd ../environments/dev
terraform init
terraform apply
```

### 3. EKS 클러스터 접속

```bash
aws eks update-kubeconfig --name tossplace-clone-dev --region ap-northeast-2
kubectl get nodes
```

### 4. 플랫폼 컴포넌트 설치

```bash
./scripts/setup.sh
```

# 📐 아키텍처 상세 문서

## 개요

이 문서는 토스플레이스 인프라 클론 프로젝트의 상세 아키텍처를 설명합니다.

## 네트워크 아키텍처

### VPC 설계

```
VPC: 10.0.0.0/16

├── Public Subnets (인터넷 접근 가능)
│   ├── 10.0.0.0/24 (AZ-a) - ALB, NAT Gateway
│   ├── 10.0.1.0/24 (AZ-b)
│   └── 10.0.2.0/24 (AZ-c)
│
├── Private Subnets (NAT 통해 아웃바운드만)
│   ├── 10.0.10.0/24 (AZ-a) - EKS Nodes
│   ├── 10.0.11.0/24 (AZ-b)
│   └── 10.0.12.0/24 (AZ-c)
│
└── Database Subnets (완전 격리)
    ├── 10.0.20.0/24 (AZ-a) - RDS, ElastiCache
    ├── 10.0.21.0/24 (AZ-b)
    └── 10.0.22.0/24 (AZ-c)
```

### 트래픽 흐름

```
[사용자] → [ALB] → [Istio Ingress Gateway] → [VirtualService] 
        → [Service] → [Pod with Envoy Sidecar]
```

## EKS 클러스터 설계

### Node Groups

| 이름 | 용도 | 인스턴스 | 스케일링 |
|------|------|---------|---------|
| general | 일반 워크로드 | t3.large | 3-10 |
| spot | 비용 최적화 | t3.medium | 1-5 (SPOT) |

### Addons

- **vpc-cni**: Pod 네트워킹
- **coredns**: 클러스터 DNS
- **kube-proxy**: 서비스 프록시
- **aws-ebs-csi-driver**: 영구 볼륨

## Istio Service Mesh 설계

### 컴포넌트

- **istiod**: Control Plane (HA: 2 replicas)
- **Ingress Gateway**: 외부 트래픽 진입점 (HPA: 2-10)
- **Egress Gateway**: 외부 트래픽 출구점

### 보안 정책

- **mTLS**: STRICT 모드 (모든 서비스 간 암호화)
- **AuthorizationPolicy**: 서비스 간 접근 제어

## 모니터링 아키텍처

```
[App] → [Prometheus] → [Thanos Sidecar] → [S3]
                                  ↓
        [Thanos Query] ← [Thanos Store Gateway]
              ↓
          [Grafana]
```

### 데이터 보존

| 해상도 | 보존 기간 |
|-------|----------|
| Raw (15s) | 30일 |
| 5분 | 90일 |
| 1시간 | 1년 |

## CI/CD 파이프라인

```
[GitHub] → [GitHub Actions] → [ECR] → [ArgoCD] → [EKS]
    │                                     ↓
    └─────────── Image Tag Update ────────┘
```

## 보안 설계

### 네트워크 보안

- VPC Flow Logs 활성화
- Security Group 최소 권한
- Network Policy 적용

### 인증/인가

- IRSA (IAM Roles for Service Accounts)
- ArgoCD RBAC
- Istio AuthorizationPolicy

### 암호화

- EKS Secrets KMS 암호화
- RDS 저장 데이터 암호화
- S3 SSE-KMS
- mTLS (서비스 간 통신)

# 🚀 배포 가이드

## 1. 사전 요구사항

### 필수 도구

```bash
# AWS CLI
aws --version  # 2.x 이상

# Terraform
terraform version  # 1.6.x 이상

# kubectl
kubectl version --client  # 1.28.x

# Helm
helm version  # 3.x

# istioctl
istioctl version  # 1.20.x
```

### AWS 권한

배포에 필요한 IAM 권한:

- `AmazonEKSClusterPolicy`
- `AmazonVPCFullAccess`
- `AmazonRDSFullAccess`
- `AmazonS3FullAccess`
- `IAMFullAccess`

## 2. 인프라 배포

### Step 1: Backend 생성

```bash
cd infrastructure/global/backend
terraform init
terraform apply -auto-approve
```

### Step 2: Dev 환경 배포

```bash
cd ../environments/dev

# backend.tf의 버킷 이름 업데이트
terraform init
terraform plan -out=tfplan
terraform apply tfplan
```

### Step 3: 배포 확인

```bash
# 출력 확인
terraform output

# EKS 접속
$(terraform output -raw kubeconfig_command)

# 노드 확인
kubectl get nodes
```

## 3. 플랫폼 컴포넌트 설치

### Istio 설치

```bash
istioctl install -f istio/install.yaml -y
kubectl label namespace default istio-injection=enabled
```

### ArgoCD 설치

```bash
kubectl create namespace argocd
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/v2.9.3/manifests/ha/install.yaml
```

### 모니터링 스택 설치

```bash
helm install prometheus prometheus-community/kube-prometheus-stack \
  -n monitoring --create-namespace \
  -f monitoring/prometheus-values.yaml
```

## 4. 애플리케이션 배포

### ArgoCD Application 생성

```bash
kubectl apply -f kubernetes/argocd/application.yaml
```

### 배포 상태 확인

```bash
argocd app get frontend
argocd app sync frontend
```

## 5. 검증

### 인프라 검증

```bash
# 모든 Pod 확인
kubectl get pods -A

# Istio 상태
istioctl analyze

# ArgoCD 상태
argocd app list
```

### 접속 테스트

```bash
# Grafana
kubectl port-forward svc/prometheus-grafana -n monitoring 3000:80

# ArgoCD
kubectl port-forward svc/argocd-server -n argocd 8080:443

# Kiali
kubectl port-forward svc/kiali -n istio-system 20001:20001
```

## 6. 정리

```bash
# ArgoCD 앱 삭제
argocd app delete frontend --cascade

# Helm 릴리스 삭제
helm uninstall prometheus -n monitoring

# Istio 삭제
istioctl uninstall --purge

# Terraform 삭제
cd infrastructure/environments/dev
terraform destroy
```
