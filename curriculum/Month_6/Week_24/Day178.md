## 🛠️ Part 1: 인프라 검증 (1시간)

### Terraform State 검증

```bash
# 리소스 목록 확인
cd infrastructure/environments/dev
terraform state list

# 예상 출력:
# module.vpc.aws_vpc.main
# module.vpc.aws_subnet.public[0]
# module.vpc.aws_subnet.private[0]
# module.eks.aws_eks_cluster.main
# module.eks.aws_eks_node_group.main["general"]
# module.rds.aws_db_instance.main
# ...

# 리소스 개수 확인
terraform state list | wc -l
# 예상: 50개 이상

# Plan 확인 (No changes 여야 함)
terraform plan

# 예상 출력:
# No changes. Your infrastructure matches the configuration.
```

### AWS 리소스 직접 확인

```bash
# VPC 확인
aws ec2 describe-vpcs \
  --filters "Name=tag:Project,Values=tossplace-clone" \
  --query 'Vpcs[*].{VpcId:VpcId,CidrBlock:CidrBlock}' \
  --output table

# EKS 클러스터 확인
aws eks describe-cluster \
  --name tossplace-clone-dev \
  --query 'cluster.{Name:name,Status:status,Version:version}'

# 예상 출력:
# {
#     "Name": "tossplace-clone-dev",
#     "Status": "ACTIVE",
#     "Version": "1.28"
# }

# RDS 확인
aws rds describe-db-instances \
  --db-instance-identifier tossplace-clone-dev-db \
  --query 'DBInstances[0].{Status:DBInstanceStatus,Endpoint:Endpoint.Address}'

# Node Group 확인
aws eks describe-nodegroup \
  --cluster-name tossplace-clone-dev \
  --nodegroup-name general \
  --query 'nodegroup.{Status:status,DesiredSize:scalingConfig.desiredSize}'
```

### 체크리스트 - 인프라

| 항목 | 명령어 | 예상 결과 | 확인 |
|------|--------|----------|------|
| VPC | `aws ec2 describe-vpcs` | 1개 VPC | ☐ |
| Subnets | `aws ec2 describe-subnets` | 9개 (3 tier × 3 AZ) | ☐ |
| NAT Gateway | `aws ec2 describe-nat-gateways` | 1개 (dev) | ☐ |
| EKS Cluster | `aws eks describe-cluster` | ACTIVE | ☐ |
| Node Group | `aws eks describe-nodegroup` | ACTIVE, 2 nodes | ☐ |
| RDS | `aws rds describe-db-instances` | available | ☐ |

## 🛠️ Part 2: Kubernetes 검증 (30분)

### 클러스터 상태 확인

```bash
# 노드 상태
kubectl get nodes -o wide

# 예상 출력:
# NAME                                            STATUS   ROLES    AGE   VERSION
# ip-10-0-10-xxx.ap-northeast-2.compute.internal  Ready    <none>   1d    v1.28.x
# ip-10-0-11-xxx.ap-northeast-2.compute.internal  Ready    <none>   1d    v1.28.x

# 시스템 Pod 상태
kubectl get pods -n kube-system

# 모든 네임스페이스 Pod
kubectl get pods -A | grep -v Running
# (출력이 없어야 정상)

# 리소스 사용량
kubectl top nodes
kubectl top pods -A
```

### 핵심 컴포넌트 확인

```bash
# CoreDNS 테스트
kubectl run -it --rm debug --image=busybox --restart=Never -- nslookup kubernetes.default

# 예상 출력:
# Name:      kubernetes.default
# Address 1: 172.20.0.1 kubernetes.default.svc.cluster.local

# EBS CSI Driver 테스트
cat << EOF | kubectl apply -f -
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: test-pvc
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: gp3
  resources:
    requests:
      storage: 1Gi
EOF

kubectl get pvc test-pvc
# STATUS가 Bound여야 함

# 정리
kubectl delete pvc test-pvc
```

## 🛠️ Part 3: Istio 검증 (30분)

### Istio 상태 확인

```bash
# Control Plane 상태
istioctl version
istioctl proxy-status

# 설정 분석
istioctl analyze -A

# 예상 출력:
# ✔ No validation issues found when analyzing namespace: default.
# ✔ No validation issues found when analyzing namespace: istio-system.
```

### mTLS 검증

```bash
# mTLS 상태 확인 (앱이 배포된 경우)
istioctl authn tls-check <pod-name>.tossplace-app

# 예상 출력:
# HOST:PORT                                STATUS     SERVER        CLIENT     AUTHN POLICY     DESTINATION RULE
# frontend.tossplace-app.svc:80            OK         STRICT        STRICT     default/         frontend/

# PeerAuthentication 확인
kubectl get peerauthentication -A
```

### 트래픽 관리 테스트

```bash
# VirtualService 확인
kubectl get virtualservices -n tossplace-app

# DestinationRule 확인
kubectl get destinationrules -n tossplace-app

# 트래픽 시뮬레이션 (앱이 있는 경우)
kubectl run -it --rm load-test --image=curlimages/curl -- \
  sh -c 'for i in $(seq 1 100); do curl -s frontend.tossplace-app.svc/health; done'
```

## 🛠️ Part 4: ArgoCD 검증 (30분)

### ArgoCD 상태 확인

```bash
# Pod 상태
kubectl get pods -n argocd

# Application 상태
argocd app list

# 예상 출력:
# NAME       CLUSTER                         NAMESPACE      PROJECT    STATUS  HEALTH   SYNCPOLICY  CONDITIONS
# frontend   https://kubernetes.default.svc  tossplace-app  tossplace  Synced  Healthy  Auto        <none>

# 동기화 테스트
argocd app sync frontend
argocd app get frontend

# 히스토리 확인
argocd app history frontend
```

### Self-Heal 테스트

```bash
# 수동으로 리소스 변경
kubectl scale deployment frontend -n tossplace-app --replicas=1

# ArgoCD가 자동으로 원복하는지 확인 (Self-heal 활성화 시)
sleep 30
kubectl get deployment frontend -n tossplace-app

# 원래 replicas로 복구되어야 함
```

## 🛠️ Part 5: 모니터링 검증 (30분)

### Prometheus 검증

```bash
# Pod 상태
kubectl get pods -n monitoring | grep prometheus

# Targets 확인
kubectl port-forward svc/prometheus-kube-prometheus-prometheus -n monitoring 9090:9090 &

# 브라우저에서 http://localhost:9090/targets 확인
# 모든 타겟이 UP 상태여야 함

# PromQL 테스트
curl -s 'localhost:9090/api/v1/query?query=up' | jq '.data.result | length'
# 10개 이상의 타겟
```

### Thanos 검증

```bash
# Thanos 컴포넌트 확인
kubectl get pods -n monitoring | grep thanos

# Thanos Query 접속
kubectl port-forward svc/thanos-query -n monitoring 10902:9090 &

# Stores 확인
curl -s 'localhost:10902/api/v1/stores' | jq '.data'
```

### Grafana 검증

```bash
# Grafana 접속
kubectl port-forward svc/prometheus-grafana -n monitoring 3000:80 &

# 브라우저에서 http://localhost:3000
# 대시보드가 정상 로드되는지 확인
```

### AlertManager 검증

```bash
# AlertManager 상태
kubectl port-forward svc/prometheus-kube-prometheus-alertmanager -n monitoring 9093:9093 &

# 현재 알림 확인
curl -s localhost:9093/api/v2/alerts | jq '.[].labels.alertname'
```

## 🛠️ Part 6: 장애 시나리오 테스트 (1시간)

### 시나리오 1: Pod 강제 종료

```bash
# Pod 삭제 테스트
kubectl delete pod -l app=frontend -n tossplace-app

# 자동 복구 확인
kubectl get pods -n tossplace-app -w

# 예상: 새 Pod가 자동 생성됨
```

### 시나리오 2: Node 장애 시뮬레이션

```bash
# 노드 Drain
NODE=$(kubectl get nodes -o jsonpath='{.items[0].metadata.name}')
kubectl drain $NODE --ignore-daemonsets --delete-emptydir-data

# Pod 재배치 확인
kubectl get pods -A -o wide

# 노드 복구
kubectl uncordon $NODE
```

### 시나리오 3: Circuit Breaker 테스트

```bash
# 백엔드 오류 주입 (Istio Fault Injection)
cat << EOF | kubectl apply -f -
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: backend-fault
  namespace: tossplace-app
spec:
  hosts:
  - backend
  http:
  - fault:
      abort:
        percentage:
          value: 50
        httpStatus: 500
    route:
    - destination:
        host: backend
EOF

# 요청 테스트
for i in $(seq 1 20); do
  curl -s -o /dev/null -w "%{http_code}\n" http://frontend.tossplace-app.svc/api/health
done

# 50% 정도가 500 에러여야 함

# 정리
kubectl delete virtualservice backend-fault -n tossplace-app
```

### 시나리오 4: 롤백 테스트

```bash
# ArgoCD에서 이전 버전으로 롤백
argocd app rollback frontend 1

# 롤백 확인
argocd app history frontend
kubectl get deployment frontend -n tossplace-app -o jsonpath='{.spec.template.spec.containers[0].image}'
```
