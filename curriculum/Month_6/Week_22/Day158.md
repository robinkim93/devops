```

│                                                             │
```

## 📚 Part 2: Terraform 핵심 개념 (30분)

### Terraform 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│  Terraform 워크플로우                                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Configuration Files (*.tf)                                 │
│         │                                                   │
│         ▼                                                   │
│  ┌─────────────┐                                           │
│  │ terraform   │  ←── Providers (AWS, GCP, Azure...)       │
│  │   CLI       │                                           │
│  └─────────────┘                                           │
│         │                                                   │
│    ┌────┴────┐                                             │
│    ▼         ▼                                              │
│ ┌──────┐  ┌──────────┐                                     │
│ │ Plan │  │ State    │                                     │
│ │      │  │ (현재상태)│                                     │
│ └──────┘  └──────────┘                                     │
│    │                                                        │
│    ▼                                                        │
│ ┌──────────────────────────┐                               │
│ │   Cloud Infrastructure   │                               │
│ │   (AWS, GCP, Azure)      │                               │
│ └──────────────────────────┘                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 핵심 구성 요소

| 구성 요소 | 설명 | 예시 |
|-----------|------|------|
| **Provider** | 클라우드 플랫폼 플러그인 | AWS, GCP, Azure |
| **Resource** | 실제 인프라 리소스 | EC2, VPC, S3 |
| **Data Source** | 기존 리소스 조회 | AMI ID 조회 |
| **Variable** | 입력 변수 | region, instance_type |
| **Output** | 출력 값 | IP 주소, ARN |
| **Module** | 재사용 가능한 설정 묶음 | VPC 모듈, EKS 모듈 |
| **State** | 현재 인프라 상태 저장 | terraform.tfstate |

### Terraform 명령어 워크플로우

```bash
# 1. 초기화 - Provider 다운로드
terraform init

# 2. 포맷팅 - 코드 스타일 통일
terraform fmt

# 3. 검증 - 문법 오류 확인
terraform validate

# 4. 계획 - 변경 사항 미리보기
terraform plan

# 5. 적용 - 실제 인프라 생성
terraform apply

# 6. 조회 - 현재 상태 확인
terraform show

# 7. 삭제 - 인프라 제거
terraform destroy
```

```hcl

      version = "~> 5.0"

  region = var.aws_region
  
  default_tags {
    tags = {
      Environment = var.environment
      Project     = "toss-devops-training"
      ManagedBy   = "terraform"
    }
  }
}
```

## 🛠️ Part 4: 실습 - AWS 리소스 생성 (45분)

### 실습 4: VPC 생성

```hcl
# main.tf
# VPC 생성
resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  enable_dns_support   = true
  
  tags = {
    Name = "${var.project_name}-vpc"
  }
}

# 퍼블릭 서브넷
resource "aws_subnet" "public" {
  count             = 2
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.${count.index + 1}.0/24"
  availability_zone = data.aws_availability_zones.available.names[count.index]
  
  map_public_ip_on_launch = true
  
  tags = {
    Name = "${var.project_name}-public-${count.index + 1}"
    Type = "public"
  }
}

# 프라이빗 서브넷
resource "aws_subnet" "private" {
  count             = 2
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.${count.index + 10}.0/24"
  availability_zone = data.aws_availability_zones.available.names[count.index]
  
  tags = {
    Name = "${var.project_name}-private-${count.index + 1}"
    Type = "private"
  }
}

# 인터넷 게이트웨이
resource "aws_internet_gateway" "main" {
  vpc_id = aws_vpc.main.id
  
  tags = {
    Name = "${var.project_name}-igw"
  }
}

# 가용 영역 데이터 소스
data "aws_availability_zones" "available" {
  state = "available"
}
```

### 실습 5: EC2 인스턴스 생성

```hcl
# ec2.tf
# 최신 Amazon Linux 2 AMI 조회
data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]
  
  filter {
    name   = "name"
    values = ["amzn2-ami-hvm-*-x86_64-gp2"]
  }
}

# 보안 그룹
resource "aws_security_group" "web" {
  name        = "${var.project_name}-web-sg"
  description = "Security group for web servers"
  vpc_id      = aws_vpc.main.id
  
  ingress {
    description = "HTTP"
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  
  ingress {
    description = "HTTPS"
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  
  ingress {
    description = "SSH"
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = [var.my_ip]
  }
  
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
  
  tags = {
    Name = "${var.project_name}-web-sg"
  }
}

# EC2 인스턴스
resource "aws_instance" "web" {
  ami           = data.aws_ami.amazon_linux.id
  instance_type = var.instance_type
  subnet_id     = aws_subnet.public[0].id
  
  vpc_security_group_ids = [aws_security_group.web.id]
  key_name               = var.key_name
  
  user_data = <<-EOF
              #!/bin/bash
              yum update -y
              yum install -y httpd
              systemctl start httpd
              systemctl enable httpd
              echo "<h1>Hello from Terraform - $(hostname)</h1>" > /var/www/html/index.html
              EOF
  
  tags = {
    Name = "${var.project_name}-web-server"
  }
}
```

## 🛠️ Part 5: Terraform State 관리 (30분)

### State 파일의 중요성

```
┌─────────────────────────────────────────────────────────────┐
│  Terraform State                                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  terraform.tfstate 파일에 저장되는 정보:                    │
│  - 생성된 모든 리소스의 현재 상태                           │
│  - 리소스 간 의존성                                         │
│  - 메타데이터 (ID, ARN 등)                                  │
│                                                             │
│  ⚠️ 주의사항:                                               │
│  - State 파일에는 민감 정보 포함 가능                       │
│  - 로컬 저장 시 협업 어려움                                 │
│  - 반드시 Remote Backend 사용 권장                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Remote Backend 설정 (S3)

```hcl
# backend.tf
terraform {
  backend "s3" {
    bucket         = "toss-devops-terraform-state"
    key            = "dev/terraform.tfstate"
    region         = "ap-northeast-2"
    encrypt        = true
    dynamodb_table = "terraform-locks"
  }
}
```

### State 관리 명령어

```bash
# State 목록 조회
terraform state list

# 특정 리소스 상태 확인
terraform state show aws_instance.web

# State에서 리소스 제거 (삭제 아님)
terraform state rm aws_instance.web

# State 이동 (리소스 이름 변경 시)
terraform state mv aws_instance.web aws_instance.web_server

# State 가져오기 (기존 리소스 import)
terraform import aws_instance.web i-1234567890abcdef0

# State 새로고침
terraform refresh
```

## 📝 면접 대비 질문

### Q1: Terraform의 State 파일은 왜 중요한가요?
> "State 파일은 Terraform이 관리하는 인프라의 현재 상태를 저장합니다. 이 파일이 없으면 Terraform은 어떤 리소스가 이미 생성되었는지 알 수 없어, 중복 생성이나 의도치 않은 삭제가 발생할 수 있습니다. 팀 협업 시에는 S3 + DynamoDB를 사용한 Remote Backend로 State를 공유하고 락킹을 구현합니다."

### Q2: terraform plan과 apply의 차이점은?
> "plan은 현재 State와 코드를 비교하여 어떤 변경이 일어날지 미리 보여주는 dry-run입니다. apply는 실제로 변경을 수행합니다. CI/CD 파이프라인에서는 plan 결과를 리뷰한 후 승인받아 apply하는 프로세스를 권장합니다."

### Q3: IaC의 장점을 실무 관점에서 설명해주세요.
> "첫째, 인프라 변경 이력이 Git에 남아 감사(audit)가 용이합니다. 둘째, 코드 리뷰를 통해 실수를 사전에 방지할 수 있습니다. 셋째, 동일한 코드로 dev/staging/prod 환경을 일관되게 구성할 수 있습니다. 토스플레이스처럼 결제 시스템을 운영하는 환경에서는 인프라 변경의 추적과 롤백 가능성이 매우 중요합니다."
