## 📚 Part 1: State란?

### State의 역할

```
terraform.tfstate 파일이 하는 일:

1. 리소스 매핑
   - Terraform 코드 ↔ 실제 AWS 리소스 연결
   - aws_instance.example → i-1234567890abcdef0

2. 메타데이터 저장
   - 리소스 의존성
   - Provider 정보

3. 성능 최적화
   - API 호출 최소화 (캐싱)
   - 대규모 인프라에서 필수

4. 협업 기반
   - 팀원 간 상태 공유
```

### State 파일 구조

```json
{
  "version": 4,
  "terraform_version": "1.6.6",
  "serial": 5,
  "lineage": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "outputs": {
    "vpc_id": {
      "value": "vpc-0abc123def456789",
      "type": "string"
    }
  },
  "resources": [
    {
      "mode": "managed",
      "type": "aws_vpc",
      "name": "main",
      "provider": "provider[\"registry.terraform.io/hashicorp/aws\"]",
      "instances": [
        {
          "schema_version": 1,
          "attributes": {
            "id": "vpc-0abc123def456789",
            "cidr_block": "10.0.0.0/16",
            "enable_dns_hostnames": true,
            "tags": {
              "Name": "main-vpc"
            }
          }
        }
      ]
    }
  ]
}
```

### Local State의 문제점

```
⚠️ Local State (terraform.tfstate) 문제:

1. 협업 불가
   - 각자 로컬에 다른 State
   - 충돌 발생

2. 보안 취약
   - 민감 정보 평문 저장 (비밀번호 등)
   - 로컬 파일 유출 위험

3. 데이터 손실
   - 실수로 삭제
   - 디스크 장애

4. 동시 수정
   - 여러 명이 동시 apply
   - State 손상 가능
```

## 📚 Part 2: Remote Backend

### Remote Backend 장점

```
✅ Remote Backend 해결책:

1. 중앙 집중화
   - 팀 전체가 같은 State 공유
   - S3, GCS, Azure Blob 등

2. State Locking
   - 동시 수정 방지
   - DynamoDB (AWS), Consul 등

3. 암호화
   - 저장 시 암호화 (SSE)
   - 전송 시 암호화 (TLS)

4. 버전 관리
   - S3 버저닝으로 이력 보관
   - 롤백 가능
```

### S3 + DynamoDB Backend 아키텍처

```
┌──────────────────────────────────────────────────────────────────────┐
│                     Remote Backend Architecture                       │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   Developer A      Developer B       CI/CD Pipeline                  │
│       │                │                   │                         │
│       └────────────────┼───────────────────┘                         │
│                        │                                             │
│                        ▼                                             │
│               ┌─────────────────┐                                    │
│               │   DynamoDB      │  ← Lock Table                      │
│               │   (Locking)     │    동시 수정 방지                   │
│               └────────┬────────┘                                    │
│                        │                                             │
│                        ▼                                             │
│               ┌─────────────────┐                                    │
│               │   S3 Bucket     │  ← State Storage                   │
│               │   (Versioning)  │    암호화, 버전 관리               │
│               └─────────────────┘                                    │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## 🛠️ Part 3: Backend 리소스 생성

### Step 1: Backend용 Terraform 코드

```bash
mkdir -p ~/terraform-study/day160/backend
cd ~/terraform-study/day160/backend
```

```hcl
# backend/main.tf
terraform {
  required_version = ">= 1.6.0"
  
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = "ap-northeast-2"
}

# S3 Bucket for State
resource "aws_s3_bucket" "terraform_state" {
  bucket = "tossplace-terraform-state-${data.aws_caller_identity.current.account_id}"

  lifecycle {
    prevent_destroy = true  # 실수로 삭제 방지
  }

  tags = {
    Name        = "Terraform State"
    Environment = "global"
    ManagedBy   = "terraform"
  }
}

# S3 버저닝 활성화
resource "aws_s3_bucket_versioning" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id
  
  versioning_configuration {
    status = "Enabled"
  }
}

# S3 암호화 설정
resource "aws_s3_bucket_server_side_encryption_configuration" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"
    }
  }
}

# 퍼블릭 접근 차단
resource "aws_s3_bucket_public_access_block" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id

  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

# DynamoDB Table for Locking
resource "aws_dynamodb_table" "terraform_locks" {
  name         = "terraform-locks"
  billing_mode = "PAY_PER_REQUEST"
  hash_key     = "LockID"

  attribute {
    name = "LockID"
    type = "S"
  }

  tags = {
    Name        = "Terraform Lock Table"
    Environment = "global"
    ManagedBy   = "terraform"
  }
}

# 현재 계정 ID
data "aws_caller_identity" "current" {}

# 출력
output "s3_bucket_name" {
  value = aws_s3_bucket.terraform_state.id
}

output "dynamodb_table_name" {
  value = aws_dynamodb_table.terraform_locks.name
}
```

## 🛠️ Part 4: Backend 설정

### 프로젝트에 Backend 설정

```hcl
# versions.tf (실제 프로젝트)
terraform {
  required_version = ">= 1.6.0"
  
  # Remote Backend 설정
  backend "s3" {
    bucket         = "tossplace-terraform-state-123456789012"
    key            = "prod/terraform.tfstate"  # State 파일 경로
    region         = "ap-northeast-2"
    encrypt        = true
    dynamodb_table = "terraform-locks"
  }
  
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}
```

### 환경별 State 분리

```
S3 Bucket 구조:

tossplace-terraform-state-123456789012/
├── global/
│   └── terraform.tfstate      # 공통 리소스 (S3, IAM)
├── dev/
│   ├── vpc/terraform.tfstate  # Dev VPC
│   ├── eks/terraform.tfstate  # Dev EKS
│   └── rds/terraform.tfstate  # Dev RDS
├── staging/
│   ├── vpc/terraform.tfstate
│   ├── eks/terraform.tfstate
│   └── rds/terraform.tfstate
└── prod/
    ├── vpc/terraform.tfstate
    ├── eks/terraform.tfstate
    └── rds/terraform.tfstate
```

### Backend 설정 동적화 (Partial Configuration)

```hcl
# versions.tf - 공통 부분만 정의
terraform {
  backend "s3" {
    # bucket, key는 init 시 전달
    region         = "ap-northeast-2"
    encrypt        = true
    dynamodb_table = "terraform-locks"
  }
}
```

```bash
# 환경별로 다른 State 파일 사용
terraform init \
  -backend-config="bucket=tossplace-terraform-state-123456789012" \
  -backend-config="key=dev/vpc/terraform.tfstate"

terraform init \
  -backend-config="bucket=tossplace-terraform-state-123456789012" \
  -backend-config="key=prod/vpc/terraform.tfstate"
```

## 📚 Part 5: State 명령어

### state list

```bash
# 모든 리소스 목록
terraform state list

# 예상 출력:
# aws_vpc.main
# aws_subnet.public[0]
# aws_subnet.public[1]
# aws_subnet.private[0]
# aws_subnet.private[1]
# module.eks.aws_eks_cluster.this[0]

# 필터링
terraform state list | grep vpc
terraform state list 'module.vpc'
```

### state show

```bash
# 특정 리소스 상세 정보
terraform state show aws_vpc.main

# 예상 출력:
# resource "aws_vpc" "main" {
#     arn                              = "arn:aws:ec2:ap-northeast-2:123456789012:vpc/vpc-0abc123"
#     cidr_block                       = "10.0.0.0/16"
#     enable_dns_hostnames             = true
#     enable_dns_support               = true
#     id                               = "vpc-0abc123def456789"
#     instance_tenancy                 = "default"
#     ...
# }

# 모듈 내 리소스
terraform state show 'module.vpc.aws_subnet.public[0]'
```

### state mv (이동/이름 변경)

```bash
# 리소스 이름 변경
terraform state mv aws_instance.old aws_instance.new

# 모듈로 이동
terraform state mv aws_vpc.main module.vpc.aws_vpc.main

# 예시: 리팩토링 시
# 코드에서 이름 변경 후, state도 업데이트
# 리소스 재생성 방지
```

### state rm (State에서 제거)

```bash
# State에서만 제거 (실제 리소스는 유지)
terraform state rm aws_instance.example

# 언제 사용?
# - 리소스를 Terraform 관리에서 제외할 때
# - 다른 State로 이동할 때
# - 잘못된 리소스 정리

# 주의: 실제 AWS 리소스는 삭제되지 않음!
```

### state pull / push

```bash
# Remote State를 로컬로 가져오기
terraform state pull > backup.tfstate

# 로컬 State를 Remote로 업로드 (위험!)
terraform state push backup.tfstate
```

### state replace-provider

```bash
# Provider 변경 (드물게 사용)
terraform state replace-provider \
  registry.terraform.io/hashicorp/aws \
  registry.terraform.io/-/aws
```

## 🔍 Part 6: State Locking

### Lock 작동 원리

```
┌─────────────────────────────────────────────────────────────┐
│                    State Locking Flow                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   User A: terraform apply                                   │
│      │                                                      │
│      ├──► DynamoDB: Lock 획득 시도                          │
│      │       └─► LockID: "tossplace/prod/terraform.tfstate" │
│      │       └─► Lock 성공 ✓                                │
│      │                                                      │
│      ├──► S3: State 읽기                                    │
│      │                                                      │
│      ├──► AWS API: 리소스 변경                              │
│      │                                                      │
│   User B: terraform apply (동시 실행 시도)                  │
│      │                                                      │
│      └──► DynamoDB: Lock 획득 시도                          │
│              └─► Lock 실패 ✗                                │
│              └─► "Error: Error acquiring the state lock"    │
│                                                             │
│   User A: 작업 완료                                         │
│      │                                                      │
│      ├──► S3: State 저장                                    │
│      └──► DynamoDB: Lock 해제                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Lock 강제 해제

```bash
# Lock 오류 발생 시
# Error: Error acquiring the state lock
# 
# Lock Info:
#   ID:        xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
#   Path:      tossplace-terraform-state/prod/terraform.tfstate
#   Operation: OperationTypeApply
#   Who:       user@hostname
#   Created:   2026-01-08 10:30:00.000000000 +0000 UTC

# 강제 해제 (주의해서 사용!)
terraform force-unlock xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

# 확인 후 해제
terraform force-unlock -force xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

## 🔍 트러블슈팅

### 문제 1: State Lock 오류

```
Error: Error acquiring the state lock
```

**원인**: 이전 apply가 비정상 종료

**해결**:
```bash
# 1. 다른 사람이 작업 중인지 확인
# 2. 확인 후 강제 해제
terraform force-unlock <LOCK_ID>
```

### 문제 2: State 손상

```bash
# State 백업 복구
aws s3api list-object-versions \
  --bucket tossplace-terraform-state \
  --prefix prod/terraform.tfstate

# 특정 버전 복구
aws s3api get-object \
  --bucket tossplace-terraform-state \
  --key prod/terraform.tfstate \
  --version-id <VERSION_ID> \
  recovered.tfstate

terraform state push recovered.tfstate
```

## 🔑 핵심 명령어

```bash
# State 조회
terraform state list                    # 리소스 목록
terraform state show <resource>         # 상세 정보

# State 조작
terraform state mv <src> <dst>          # 이동/이름변경
terraform state rm <resource>           # State에서 제거
terraform state pull                    # Remote → Local
terraform state push                    # Local → Remote

# Lock
terraform force-unlock <LOCK_ID>        # Lock 강제 해제

# Backend
terraform init -reconfigure             # Backend 재설정
terraform init -migrate-state           # State 마이그레이션
```
