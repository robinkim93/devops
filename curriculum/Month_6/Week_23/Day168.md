## 📚 Part 1: 핵심 개념 (40분)

### GitOps 인프라란?

```
┌─────────────────────────────────────────────────────────────┐
│  GitOps 인프라 = Git이 Single Source of Truth              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  기존 방식                                           │   │
│  │  개발자 → terraform apply → AWS                     │   │
│  │  (누가, 언제, 왜 변경했는지 추적 어려움)             │   │
│  └─────────────────────────────────────────────────────┘   │
│                           ↓                                 │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  GitOps 방식                                         │   │
│  │  개발자 → PR → 리뷰 → Merge → CI/CD → AWS           │   │
│  │  (모든 변경이 Git에 기록, 리뷰 필수)                 │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  장점:                                                      │
│  ✅ 모든 변경사항 추적 가능                                │
│  ✅ 코드 리뷰로 실수 방지                                  │
│  ✅ 롤백 용이 (git revert)                                 │
│  ✅ 컴플라이언스 감사 대응                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 왜 DevOps 엔지니어가 알아야 하나?

```
┌─────────────────────────────────────────────────────────────┐
│  실제 장애 사례                                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  🚨 사고: "누군가 프로덕션 DB 인스턴스 타입 변경"           │
│                                                             │
│  ❌ 기존 방식의 문제:                                       │
│  - 누가 변경했는지 모름                                     │
│  - 왜 변경했는지 히스토리 없음                              │
│  - terraform state와 실제 리소스 불일치                     │
│  - 롤백 방법 불명확                                         │
│                                                             │
│  ✅ GitOps 방식의 해결:                                     │
│  - PR 히스토리로 변경자/이유 확인                           │
│  - git revert로 즉시 롤백 가능                              │
│  - PR 없이는 프로덕션 변경 불가능                           │
│  - 감사 로그 자동 생성                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Terraform CI/CD 워크플로우

```
┌─────────────────────────────────────────────────────────────────────────┐
│  PR 기반 Terraform 워크플로우                                           │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. Feature Branch 생성                                                 │
│  ┌─────────────┐                                                        │
│  │  개발자     │ git checkout -b feature/update-eks                     │
│  │  코드 수정  │ → terraform fmt → commit → push                        │
│  └──────┬──────┘                                                        │
│         │                                                               │
│  2. PR 생성 → 자동 Plan 실행                                            │
│  ┌──────▼──────────────────────────────────────────────────────────┐   │
│  │  GitHub Actions                                                   │   │
│  │  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐   │   │
│  │  │  Init   │→│ Validate│→│  Lint   │→│ Security│→│  Plan   │   │   │
│  │  └─────────┘ └─────────┘ └─────────┘ └─────────┘ └────┬────┘   │   │
│  └───────────────────────────────────────────────────────┼─────────┘   │
│         │                                                 │             │
│  3. Plan 결과 PR 코멘트                                   │             │
│  ┌──────▼──────────────────────────────────────────────────────────┐   │
│  │  PR Comment                                                       │   │
│  │  "Plan: 2 to add, 1 to change, 0 to destroy"                     │   │
│  │  [Show Plan Details]                                              │   │
│  └──────────────────────────────────────────────────────────────────┘   │
│         │                                                               │
│  4. 리뷰 & 승인                                                         │
│  ┌──────▼──────┐                                                        │
│  │  리뷰어     │ 코드 리뷰 + Plan 확인 + Approve                        │
│  └──────┬──────┘                                                        │
│         │                                                               │
│  5. Merge → 자동 Apply                                                  │
│  ┌──────▼──────────────────────────────────────────────────────────┐   │
│  │  GitHub Actions (main branch)                                     │   │
│  │  ┌─────────┐ ┌─────────┐ ┌─────────┐                             │   │
│  │  │  Plan   │→│ Approval│→│  Apply  │→ 인프라 변경                │   │
│  │  └─────────┘ └─────────┘ └─────────┘                             │   │
│  └──────────────────────────────────────────────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### CI/CD 도구 비교

| 도구 | 특징 | 장점 | 단점 |
|------|------|------|------|
| **GitHub Actions** | GitHub 네이티브 | 설정 간단, 무료 tier | 복잡한 워크플로우 제한 |
| **Atlantis** | PR 자동화 전문 | Plan 자동화 우수 | 별도 서버 필요 |
| **Terraform Cloud** | HashiCorp 공식 | 완전 관리형 | 비용, 벤더 종속 |
| **Spacelift** | 엔터프라이즈급 | 고급 기능 | 높은 비용 |

### 실습 1: 기본 Terraform 워크플로우 (25분)

**목표**: PR에서 자동 Plan 실행

```bash
# GitHub Actions 워크플로우 생성
cat > .github/workflows/terraform.yml << 'EOF'
name: Terraform CI/CD

on:
  push:
    branches:
      - main
    paths:
      - 'environments/**'
      - 'modules/**'
  pull_request:
    branches:
      - main
    paths:
      - 'environments/**'
      - 'modules/**'

env:
  TF_VERSION: 1.6.0
  AWS_REGION: ap-northeast-2

permissions:
  contents: read
  pull-requests: write
  id-token: write  # OIDC 인증용

jobs:
  # ========================================
  # PR에서 실행: Plan + Comment
  # ========================================
  plan:
    name: Terraform Plan
    runs-on: ubuntu-latest
    if: github.event_name == 'pull_request'
    
    strategy:
      matrix:
        environment: [dev, prod]
    
    steps:
      - name: Checkout
        uses: actions/checkout@v4
    
      - name: Setup Terraform
        uses: hashicorp/setup-terraform@v3
        with:
          terraform_version: ${{ env.TF_VERSION }}
          
      - name: Configure AWS Credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ${{ env.AWS_REGION }}
          
      - name: Terraform Init
        id: init
        working-directory: environments/${{ matrix.environment }}
        run: terraform init
        
      - name: Terraform Format Check
        id: fmt
        working-directory: environments/${{ matrix.environment }}
        run: terraform fmt -check -recursive
        continue-on-error: true
        
      - name: Terraform Validate
        id: validate
        working-directory: environments/${{ matrix.environment }}
        run: terraform validate -no-color
        
      - name: Terraform Plan
        id: plan
        working-directory: environments/${{ matrix.environment }}
        run: |
          terraform plan -no-color -out=tfplan 2>&1 | tee plan.txt
          echo "PLAN<<EOF" >> $GITHUB_OUTPUT
          cat plan.txt >> $GITHUB_OUTPUT
          echo "EOF" >> $GITHUB_OUTPUT
        continue-on-error: true
        
      - name: Create Plan Summary
        id: summary
        working-directory: environments/${{ matrix.environment }}
        run: |
          if grep -q "No changes" plan.txt; then
            echo "status=no-changes" >> $GITHUB_OUTPUT
          elif grep -q "to add" plan.txt; then
            ADDS=$(grep -oP '\d+(?= to add)' plan.txt || echo "0")
            CHANGES=$(grep -oP '\d+(?= to change)' plan.txt || echo "0")
            DESTROYS=$(grep -oP '\d+(?= to destroy)' plan.txt || echo "0")
            echo "status=changes" >> $GITHUB_OUTPUT
            echo "adds=$ADDS" >> $GITHUB_OUTPUT
            echo "changes=$CHANGES" >> $GITHUB_OUTPUT
            echo "destroys=$DESTROYS" >> $GITHUB_OUTPUT
          fi
          
      - name: Comment on PR
        uses: actions/github-script@v7
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
          script: |
            const env = '${{ matrix.environment }}';
            const planOutcome = '${{ steps.plan.outcome }}';
            const planOutput = `${{ steps.plan.outputs.PLAN }}`;
            const fmtOutcome = '${{ steps.fmt.outcome }}';
            const validateOutcome = '${{ steps.validate.outcome }}';
            const status = '${{ steps.summary.outputs.status }}';
            
            let emoji = '✅';
            if (planOutcome === 'failure') emoji = '❌';
            else if (status === 'changes') emoji = '⚠️';
            
            let summary = '';
            if (status === 'no-changes') {
              summary = '📋 **No infrastructure changes detected**';
            } else if (status === 'changes') {
              summary = `📊 **Changes Detected**
              - ➕ Add: ${{ steps.summary.outputs.adds }}
              - 🔄 Change: ${{ steps.summary.outputs.changes }}
              - ➖ Destroy: ${{ steps.summary.outputs.destroys }}`;
            }
            
            const body = `## ${emoji} Terraform Plan - ${env.toUpperCase()}
            
            | Check | Status |
            |-------|--------|
            | Format | ${fmtOutcome === 'success' ? '✅ Passed' : '❌ Failed'} |
            | Validate | ${validateOutcome === 'success' ? '✅ Passed' : '❌ Failed'} |
            | Plan | ${planOutcome === 'success' ? '✅ Success' : '❌ Failed'} |
            
            ${summary}
            
            <details>
            <summary>📝 Click to expand Plan Output</summary>
            
            \`\`\`hcl
            ${planOutput.substring(0, 60000)}
            \`\`\`
            
            </details>
            
            ---
            *Workflow: ${{ github.workflow }} | Run: ${{ github.run_id }}*
            `;
            
            // 기존 코멘트 찾기
            const { data: comments } = await github.rest.issues.listComments({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
            });
            
            const botComment = comments.find(comment => 
              comment.user.type === 'Bot' && 
              comment.body.includes(`Terraform Plan - ${env.toUpperCase()}`)
            );
            
            if (botComment) {
              await github.rest.issues.updateComment({
                owner: context.repo.owner,
                repo: context.repo.repo,
                comment_id: botComment.id,
                body: body
              });
            } else {
              await github.rest.issues.createComment({
                owner: context.repo.owner,
                repo: context.repo.repo,
                issue_number: context.issue.number,
                body: body
              });
            }
            
  # ========================================
  # main 브랜치 Push: Apply
  # ========================================
  apply:
    name: Terraform Apply
    runs-on: ubuntu-latest
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    
    strategy:
      matrix:
        environment: [dev, prod]
      max-parallel: 1  # 순차 실행 (dev → prod)
      
    environment:
      name: ${{ matrix.environment }}  # Environment Protection Rules 적용
      
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        
      - name: Setup Terraform
        uses: hashicorp/setup-terraform@v3
        with:
          terraform_version: ${{ env.TF_VERSION }}
          
      - name: Configure AWS Credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ${{ env.AWS_REGION }}
    
    - name: Terraform Init
        working-directory: environments/${{ matrix.environment }}
      run: terraform init
    
      - name: Terraform Apply
        working-directory: environments/${{ matrix.environment }}
        run: terraform apply -auto-approve
EOF
```

**분석 포인트**:
- PR 시 자동으로 `terraform plan` 실행
- Plan 결과가 PR 코멘트로 표시
- main 머지 시에만 `apply` 실행
- 환경별로 순차 적용 (dev → prod)

### 실습 3: Atlantis 스타일 워크플로우 (25분)

**목표**: PR 코멘트로 Plan/Apply 제어

```bash
# atlantis-style.yml - PR 코멘트 기반 트리거
cat > .github/workflows/atlantis-style.yml << 'EOF'
name: Atlantis-style Terraform

on:
  issue_comment:
    types: [created]

jobs:
  parse-command:
    name: Parse Command
    runs-on: ubuntu-latest
    if: github.event.issue.pull_request && startsWith(github.event.comment.body, 'atlantis')
    
    outputs:
      command: ${{ steps.parse.outputs.command }}
      environment: ${{ steps.parse.outputs.environment }}
      
    steps:
      - name: Parse Comment
        id: parse
        run: |
          COMMENT="${{ github.event.comment.body }}"
          
          # atlantis plan -d environments/dev
          # atlantis apply -d environments/prod
          
          if echo "$COMMENT" | grep -q "atlantis plan"; then
            echo "command=plan" >> $GITHUB_OUTPUT
          elif echo "$COMMENT" | grep -q "atlantis apply"; then
            echo "command=apply" >> $GITHUB_OUTPUT
          fi
          
          if echo "$COMMENT" | grep -q "environments/dev"; then
            echo "environment=dev" >> $GITHUB_OUTPUT
          elif echo "$COMMENT" | grep -q "environments/prod"; then
            echo "environment=prod" >> $GITHUB_OUTPUT
          fi
          
  terraform-plan:
    name: Terraform Plan
    needs: parse-command
    if: needs.parse-command.outputs.command == 'plan'
    runs-on: ubuntu-latest
    
    steps:
      - name: Checkout PR
        uses: actions/checkout@v4
        with:
          ref: refs/pull/${{ github.event.issue.number }}/merge
          
      - name: Setup Terraform
        uses: hashicorp/setup-terraform@v3
        
      - name: React to Comment
        uses: actions/github-script@v7
        with:
          script: |
            github.rest.reactions.createForIssueComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              comment_id: context.payload.comment.id,
              content: 'rocket'
            });
    
    - name: Terraform Plan
        id: plan
        working-directory: environments/${{ needs.parse-command.outputs.environment }}
        run: |
          terraform init
          terraform plan -no-color -out=tfplan 2>&1 | tee plan.txt
          
      - name: Comment Plan Result
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const plan = fs.readFileSync('environments/${{ needs.parse-command.outputs.environment }}/plan.txt', 'utf8');
            
            github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body: `## 📋 Terraform Plan - ${{ needs.parse-command.outputs.environment }}
              
              \`\`\`hcl
              ${plan.substring(0, 60000)}
              \`\`\`
              
              ---
              To apply, comment: \`atlantis apply -d environments/${{ needs.parse-command.outputs.environment }}\`
              `
            });

  terraform-apply:
    name: Terraform Apply
    needs: parse-command
    if: needs.parse-command.outputs.command == 'apply'
    runs-on: ubuntu-latest
    
    environment:
      name: ${{ needs.parse-command.outputs.environment }}
      
    steps:
      - name: Checkout PR
        uses: actions/checkout@v4
        with:
          ref: refs/pull/${{ github.event.issue.number }}/merge
          
      - name: Setup Terraform
        uses: hashicorp/setup-terraform@v3
    
    - name: Terraform Apply
        working-directory: environments/${{ needs.parse-command.outputs.environment }}
        run: |
          terraform init
          terraform apply -auto-approve
          
      - name: Comment Apply Result
        uses: actions/github-script@v7
        with:
          script: |
            github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body: `## ✅ Terraform Apply Complete - ${{ needs.parse-command.outputs.environment }}
              
              Infrastructure changes have been applied successfully!
              `
            });
EOF
```

**사용법**:
```
# PR에서 코멘트
atlantis plan -d environments/dev    # Plan 실행
atlantis apply -d environments/dev   # Apply 실행
```

### 실습 4: State Lock 및 동시성 관리 (20분)

**목표**: 동시 Apply 방지 및 Lock 관리

```bash
# DynamoDB Lock 테이블 생성
cat > global/state-management/main.tf << 'EOF'
# Terraform State Management

# S3 Bucket for State
resource "aws_s3_bucket" "terraform_state" {
  bucket = "tossplace-terraform-state-${data.aws_caller_identity.current.account_id}"
  
  lifecycle {
    prevent_destroy = true
  }
  
  tags = {
    Name        = "Terraform State"
    Environment = "global"
    ManagedBy   = "Terraform"
  }
}

resource "aws_s3_bucket_versioning" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id
  versioning_configuration {
    status = "Enabled"
  }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "aws:kms"
    }
  }
}

resource "aws_s3_bucket_public_access_block" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id

  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

# DynamoDB for State Locking
resource "aws_dynamodb_table" "terraform_lock" {
  name         = "terraform-lock"
  billing_mode = "PAY_PER_REQUEST"
  hash_key     = "LockID"

  attribute {
    name = "LockID"
    type = "S"
  }

  tags = {
    Name        = "Terraform Lock"
    Environment = "global"
    ManagedBy   = "Terraform"
  }
}

data "aws_caller_identity" "current" {}

output "state_bucket" {
  value = aws_s3_bucket.terraform_state.bucket
}

output "lock_table" {
  value = aws_dynamodb_table.terraform_lock.name
}
EOF
```

```bash
# GitHub Actions에서 Lock 충돌 처리
cat > .github/workflows/lock-handling.yml << 'EOF'
name: Handle Terraform Lock

on:
  workflow_dispatch:
    inputs:
      action:
        description: 'Action to perform'
        required: true
        type: choice
        options:
          - list-locks
          - force-unlock
      lock_id:
        description: 'Lock ID (for force-unlock)'
        required: false

jobs:
  manage-locks:
    runs-on: ubuntu-latest
    
    steps:
      - name: Configure AWS
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ap-northeast-2
          
      - name: List Locks
        if: inputs.action == 'list-locks'
        run: |
          echo "📋 Current Terraform Locks:"
          aws dynamodb scan --table-name terraform-lock \
            --query 'Items[*]' \
            --output table
            
      - name: Force Unlock
        if: inputs.action == 'force-unlock' && inputs.lock_id != ''
        run: |
          echo "⚠️ Force unlocking: ${{ inputs.lock_id }}"
          aws dynamodb delete-item \
            --table-name terraform-lock \
            --key '{"LockID": {"S": "${{ inputs.lock_id }}"}}'
          echo "✅ Lock removed"
EOF
```

### 실습 5: Drift Detection 자동화 (10분)

**목표**: 정기적으로 인프라 Drift 감지

```bash
# drift-detection.yml
cat > .github/workflows/drift-detection.yml << 'EOF'
name: Drift Detection

on:
  schedule:
    - cron: '0 9 * * *'  # 매일 오전 9시 (KST 18시)
  workflow_dispatch:

jobs:
  detect-drift:
    runs-on: ubuntu-latest
    
    strategy:
      matrix:
        environment: [dev, staging, prod]
        
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        
      - name: Setup Terraform
        uses: hashicorp/setup-terraform@v3
        
      - name: Configure AWS
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ap-northeast-2
          
      - name: Detect Drift
        id: drift
        working-directory: environments/${{ matrix.environment }}
        run: |
          terraform init
          terraform plan -detailed-exitcode -no-color > drift.txt 2>&1 || EXIT_CODE=$?
          
          if [ "$EXIT_CODE" == "2" ]; then
            echo "drift=true" >> $GITHUB_OUTPUT
            echo "::warning::Drift detected in ${{ matrix.environment }}"
          else
            echo "drift=false" >> $GITHUB_OUTPUT
          fi
          
      - name: Notify Slack on Drift
        if: steps.drift.outputs.drift == 'true'
        uses: slackapi/slack-github-action@v1
        with:
          payload: |
            {
              "text": "🚨 Infrastructure Drift Detected!",
              "blocks": [
                {
                  "type": "section",
                  "text": {
                    "type": "mrkdwn",
                    "text": "*Environment:* ${{ matrix.environment }}\n*Repository:* ${{ github.repository }}\n*Details:* Check the workflow run for details."
                  }
                }
              ]
            }
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}
EOF
```

### 시나리오 1: Apply 중 실패

```yaml
# 롤백 워크플로우
name: Terraform Rollback

on:
  workflow_dispatch:
    inputs:
      environment:
        required: true
        type: choice
        options: [dev, staging, prod]
      commit_sha:
        description: 'Commit SHA to rollback to'
        required: true

jobs:
  rollback:
    runs-on: ubuntu-latest
    environment: ${{ inputs.environment }}
    
    steps:
      - name: Checkout specific commit
        uses: actions/checkout@v4
        with:
          ref: ${{ inputs.commit_sha }}
          
      - name: Apply previous state
        working-directory: environments/${{ inputs.environment }}
        run: |
          terraform init
          terraform apply -auto-approve
```
