# 📅 Day 166: Terraform Import 실전 가이드

## 🎯 오늘의 목표

> **토스플레이스 최우선 요건**: "IaC 경험" + "인프라에 대한 오너십"

기존에 수동으로 생성된 AWS 리소스를 Terraform으로 가져와 **코드화(IaC)**하는 것은 DevOps 엔지니어의 핵심 업무입니다. 토스플레이스처럼 빠르게 성장하는 조직에서는 레거시 인프라를 체계적으로 관리하는 역량이 필수입니다.

## 📚 Part 1: 핵심 개념 (40분)

### Terraform Import란?

```
┌─────────────────────────────────────────────────────────────┐
│  Terraform Import = 기존 리소스 → Terraform State로 가져오기│
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────────┐       ┌─────────────────┐             │
│  │  AWS Console    │       │   Terraform     │             │
│  │  에서 수동 생성  │  →→→  │   State로 관리  │             │
│  └─────────────────┘       └─────────────────┘             │
│                                                             │
│  Import 후:                                                 │
│  1. 리소스가 State에 등록됨                                 │
│  2. 코드 작성 필요 (자동 생성 X - Terraform 1.5 이전)       │
│  3. 이후 terraform apply로 관리 가능                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 왜 DevOps 엔지니어가 알아야 하나?

```
┌─────────────────────────────────────────────────────────────┐
│  실제 장애 상황                                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  🚨 문제 상황:                                              │
│  "새벽에 긴급 장애 대응으로 Console에서 Security Group 수정"│
│  "다음날 terraform apply하니 변경사항이 롤백됨"             │
│                                                             │
│  📊 원인:                                                   │
│  - Console 변경사항이 Terraform State에 반영되지 않음       │
│  - Terraform은 코드 기준으로 리소스를 되돌림 (Drift)        │
│                                                             │
│  ✅ 해결책:                                                 │
│  1. 변경된 리소스를 Import하거나                            │
│  2. 코드를 현재 상태와 동기화                               │
│  3. 앞으로는 Terraform으로만 변경                           │
│                                                             │
│  → "모든 인프라 변경은 코드로" 원칙 수립                    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Import 방법 비교

| 방법 | Terraform 버전 | 특징 | 장점 |
|------|---------------|------|------|
| **terraform import** 명령어 | 모든 버전 | CLI에서 실행 | 단순, 빠름 |
| **Import Block** | 1.5+ | HCL로 선언 | 코드화, 재현 가능 |
| **-generate-config-out** | 1.5+ | 코드 자동 생성 | 수동 작성 최소화 |

### Import 워크플로우

```
┌─────────────────────────────────────────────────────────────┐
│  Import 단계별 프로세스                                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Step 1: 리소스 식별                                        │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  aws ec2 describe-instances --instance-ids i-xxx    │   │
│  │  → 리소스 ID, 현재 설정값 확인                       │   │
│  └─────────────────────────────────────────────────────┘   │
│                           ↓                                 │
│  Step 2: 빈 리소스 블록 작성                                │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  resource "aws_instance" "imported" {}              │   │
│  └─────────────────────────────────────────────────────┘   │
│                           ↓                                 │
│  Step 3: Import 실행                                        │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  terraform import aws_instance.imported i-xxx       │   │
│  └─────────────────────────────────────────────────────┘   │
│                           ↓                                 │
│  Step 4: 코드 작성/생성                                     │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  terraform plan → 차이점 확인 → 코드 수정           │   │
│  └─────────────────────────────────────────────────────┘   │
│                           ↓                                 │
│  Step 5: 검증                                               │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  terraform plan → "No changes" 확인                 │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 실습 1: 기본 Import 명령어 (20분)

**목표**: terraform import 명령어로 EC2 인스턴스 가져오기

```bash
# 1. 테스트용 EC2 인스턴스 생성 (Console 또는 CLI)
aws ec2 run-instances \
  --image-id ami-0c55b159cbfafe1f0 \
  --instance-type t3.micro \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=import-test}]' \
  --query 'Instances[0].InstanceId' \
  --output text

# 예상 출력: i-0abc123def456789

# 2. 인스턴스 ID 저장
INSTANCE_ID="i-0abc123def456789"  # 실제 ID로 변경
```

```bash
# 3. Terraform 설정 파일 생성
cat > main.tf << 'EOF'
terraform {
  required_version = ">= 1.0.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = "ap-northeast-2"
}

# 빈 리소스 블록 (Import 대상)
resource "aws_instance" "imported" {
  # Import 후 채워질 예정
}
EOF

# 4. 초기화
terraform init
```

```bash
# 5. Import 실행
terraform import aws_instance.imported $INSTANCE_ID

# 예상 출력:
# aws_instance.imported: Importing from ID "i-0abc123def456789"...
# aws_instance.imported: Import prepared!
#   Prepared aws_instance for import
# aws_instance.imported: Refreshing state... [id=i-0abc123def456789]
# 
# Import successful!
# 
# The resources that were imported are shown above. These resources are now in
# your Terraform state and will henceforth be managed by Terraform.
```

```bash
# 6. State 확인
terraform state list

# 예상 출력:
# aws_instance.imported

terraform state show aws_instance.imported

# 예상 출력:
# resource "aws_instance" "imported" {
#     ami                          = "ami-0c55b159cbfafe1f0"
#     instance_type                = "t3.micro"
#     ...
# }
```

**분석 포인트**:
- Import는 State만 업데이트, 코드는 변경되지 않음
- `terraform plan`을 실행하면 코드와 State의 차이가 표시됨
- 이 차이를 없애기 위해 코드를 수정해야 함

### 실습 2: Import Block 사용 (Terraform 1.5+) (25분)

**목표**: 선언적 Import Block으로 리소스 가져오기

```bash
# 1. 기존 VPC 정보 확인
VPC_ID=$(aws ec2 describe-vpcs \
  --filters "Name=tag:Name,Values=default" \
  --query 'Vpcs[0].VpcId' \
  --output text)

echo "VPC ID: $VPC_ID"
```

```bash
# 2. Import Block으로 Import 정의
cat > import.tf << 'EOF'
# Import Block 방식 (Terraform 1.5+)
import {
  to = aws_vpc.imported
  id = "vpc-0abc123def456789"  # 실제 VPC ID로 변경
}

# 실제 리소스 정의는 여전히 필요
resource "aws_vpc" "imported" {
  # 코드를 직접 작성하거나 -generate-config-out 사용
}
EOF
```

```bash
# 3. 코드 자동 생성 (핵심 기능!)
terraform plan -generate-config-out=generated.tf

# 예상 출력:
# Planning failed. Terraform encountered an error while generating this plan.
# 
# ... 하지만 generated.tf 파일이 생성됨!
```

```bash
# 4. 생성된 코드 확인
cat generated.tf

# 예상 출력:
# resource "aws_vpc" "imported" {
#   cidr_block           = "172.31.0.0/16"
#   enable_dns_hostnames = true
#   enable_dns_support   = true
#   instance_tenancy     = "default"
#   tags                 = {
#     "Name" = "default"
#   }
#   tags_all             = {
#     "Name" = "default"
#   }
# }
```

```bash
# 5. import.tf 삭제 (Import 완료 후)
rm import.tf

# 6. Plan 확인 (No changes여야 함)
terraform plan

# 예상 출력:
# aws_vpc.imported: Refreshing state... [id=vpc-0abc123def456789]
# 
# No changes. Your infrastructure matches the configuration.
```

**분석 포인트**:
- Import Block은 코드로 관리되어 Git에 기록 가능
- `-generate-config-out`으로 수동 코드 작성 최소화
- Import 완료 후 Import Block은 삭제해도 됨

### 실습 3: 복잡한 리소스 Import (30분)

**목표**: Security Group, IAM Role 등 의존성 있는 리소스 Import

```bash
# 1. Security Group Import
cat > sg_import.tf << 'EOF'
# 기존 Security Group 가져오기
import {
  to = aws_security_group.imported
  id = "sg-0abc123def456789"  # 실제 SG ID로 변경
}

# 모든 규칙을 개별적으로 관리하려면
import {
  to = aws_vpc_security_group_ingress_rule.rule1
  id = "sgr-0abc123def456789"  # 규칙 ID
}
EOF
```

```bash
# 2. IAM Role Import (주의: 여러 리소스 필요)
cat > iam_import.tf << 'EOF'
# IAM Role은 여러 컴포넌트로 구성됨

# Role 자체
import {
  to = aws_iam_role.imported
  id = "MyExistingRole"
}

# Inline Policy
import {
  to = aws_iam_role_policy.imported_inline
  id = "MyExistingRole:InlinePolicyName"
}

# Attached Policy
import {
  to = aws_iam_role_policy_attachment.imported_attachment
  id = "MyExistingRole/arn:aws:iam::aws:policy/AmazonEKSClusterPolicy"
}
EOF
```

```bash
# 3. EKS 클러스터 Import (가장 복잡한 케이스)
cat > eks_import.tf << 'EOF'
# EKS는 많은 의존성을 가짐

# 클러스터
import {
  to = aws_eks_cluster.imported
  id = "my-cluster"
}

# Node Group
import {
  to = aws_eks_node_group.imported
  id = "my-cluster:my-node-group"
}

# OIDC Provider
import {
  to = aws_iam_openid_connect_provider.imported
  id = "arn:aws:iam::123456789012:oidc-provider/oidc.eks.ap-northeast-2.amazonaws.com/id/EXAMPLED539D4633E53DE1B716D3041E"
}

# Add-ons
import {
  to = aws_eks_addon.vpc_cni
  id = "my-cluster:vpc-cni"
}

import {
  to = aws_eks_addon.coredns
  id = "my-cluster:coredns"
}
EOF
```

**분석 포인트**:
- 복잡한 리소스는 여러 Import Block 필요
- IAM은 Role, Policy, Attachment가 분리됨
- EKS는 Cluster, NodeGroup, Addons, OIDC 등 많은 컴포넌트

### 실습 4: 대규모 Import 자동화 (25분)

**목표**: 스크립트로 대량 Import 자동화

```bash
# 1. Import 스크립트 작성
cat > bulk_import.sh << 'EOF'
#!/bin/bash
set -e

# 색상 정의
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
NC='\033[0m'

echo -e "${YELLOW}🔍 대규모 Import 시작${NC}"

# 모든 EC2 인스턴스 ID 조회
echo -e "\n${GREEN}Step 1: EC2 인스턴스 조회${NC}"
INSTANCES=$(aws ec2 describe-instances \
  --filters "Name=instance-state-name,Values=running" \
  --query 'Reservations[].Instances[].InstanceId' \
  --output text)

# Import Block 생성
echo -e "\n${GREEN}Step 2: Import Block 생성${NC}"
cat > ec2_imports.tf << IMPORT_EOF
# Auto-generated Import Blocks
# Generated at: $(date)

IMPORT_EOF

counter=1
for instance_id in $INSTANCES; do
  echo "  Processing: $instance_id"
  
  # 인스턴스 이름 조회
  name=$(aws ec2 describe-tags \
    --filters "Name=resource-id,Values=$instance_id" "Name=key,Values=Name" \
    --query 'Tags[0].Value' \
    --output text 2>/dev/null || echo "instance_$counter")
  
  # Import Block 추가
  cat >> ec2_imports.tf << BLOCK_EOF

import {
  to = aws_instance.${name//[-.]/_}
  id = "$instance_id"
}

resource "aws_instance" "${name//[-.]/_}" {
  # To be generated
}
BLOCK_EOF
  
  ((counter++))
done

echo -e "\n${GREEN}Step 3: 코드 생성${NC}"
terraform init
terraform plan -generate-config-out=ec2_generated.tf

echo -e "\n${GREEN}✅ Import 완료!${NC}"
echo "  - Import Blocks: ec2_imports.tf"
echo "  - Generated Code: ec2_generated.tf"
echo ""
echo "다음 단계:"
echo "  1. ec2_generated.tf 검토 및 수정"
echo "  2. terraform plan으로 확인"
echo "  3. ec2_imports.tf 삭제"
EOF

chmod +x bulk_import.sh
```

```bash
# 2. Terraformer 사용 (대안)
# 전체 AWS 리소스를 자동으로 Import하는 도구

# 설치 (macOS)
brew install terraformer

# 전체 VPC 리소스 Import
terraformer import aws \
  --resources=vpc,subnet,security_group \
  --regions=ap-northeast-2

# 예상 출력 구조:
# generated/
# └── aws/
#     └── vpc/
#         ├── provider.tf
#         ├── vpc.tf
#         ├── subnet.tf
#         └── security_group.tf
```

## 📊 Part 3: 장애 시나리오 실습 (20분)

### 시나리오 1: Import 후 Plan에서 차이 발생

```bash
# 문제 상황
terraform plan

# 출력:
# ~ resource "aws_instance" "imported" {
#     ~ tags = {
#         - "CreatedBy" = "Console" -> null
#       }
#   }

# 해결: 코드에 누락된 속성 추가
# 또는 lifecycle ignore_changes 사용

resource "aws_instance" "imported" {
  # ... 기존 설정 ...
  
  lifecycle {
    ignore_changes = [
      tags["CreatedBy"],  # Console에서 추가된 태그 무시
    ]
  }
}
```

### 시나리오 2: Import 대상 리소스가 이미 State에 존재

```bash
# 에러:
# Error: Resource already managed by Terraform
#
# Terraform is already managing a remote object for
# aws_instance.imported. To import to this address you must first
# remove the existing object from the state.

# 해결 1: State에서 제거 후 재 Import
terraform state rm aws_instance.imported
terraform import aws_instance.imported i-xxx

# 해결 2: 다른 이름으로 Import
terraform import aws_instance.imported_v2 i-xxx
```

### 시나리오 3: Import 실패 - 권한 부족

```bash
# 에러:
# Error: error reading EC2 Instance (i-xxx): UnauthorizedOperation

# 원인: IAM 권한 부족
# 해결: 필요한 권한 추가
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "ec2:DescribeInstances",
                "ec2:DescribeTags",
                "ec2:DescribeSecurityGroups",
                "ec2:DescribeVpcs",
                "ec2:DescribeSubnets"
            ],
            "Resource": "*"
        }
    ]
}
```
