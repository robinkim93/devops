## 🎯 오늘의 목표

## 📚 Part 1: 핵심 개념 (40분)

### Workspace란?

```
┌─────────────────────────────────────────────────────────────┐
│  Terraform Workspace = 동일 코드 + 다른 State              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  같은 main.tf로 dev, staging, prod 환경을 각각 관리        │
│                                                             │
│  ┌──────────────────────────────────────────────────────┐  │
│  │                    main.tf                            │  │
│  │  (VPC, EKS, RDS 정의)                                 │  │
│  └───────────────┬──────────────┬───────────────────────┘  │
│                  │              │              │            │
│           ┌──────┴───┐   ┌──────┴───┐   ┌──────┴───┐       │
│           │   dev    │   │ staging  │   │   prod   │       │
│           │  state   │   │  state   │   │  state   │       │
│           └──────────┘   └──────────┘   └──────────┘       │
│                                                             │
│  각 Workspace는 독립적인 State 파일을 가짐                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 왜 DevOps 엔지니어가 알아야 하나?

```
┌─────────────────────────────────────────────────────────────┐
│  실제 장애 상황                                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  🚨 문제 상황:                                              │
│  "prod 환경에 적용할 변경사항을 실수로 dev에 적용"          │
│                                                             │
│  📊 원인 분석:                                              │
│  - 환경 분리 없이 단일 State로 모든 환경 관리               │
│  - terraform apply 시 환경 확인 프로세스 부재               │
│                                                             │
│  ✅ 해결책: Workspace 도입                                  │
│  1. 각 환경별 독립 State 관리                               │
│  2. 환경별 변수 자동 적용                                   │
│  3. CI/CD에서 환경 검증 자동화                              │
│                                                             │
│  → 휴먼 에러 방지 + 환경 간 격리 보장                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Workspace vs Directory 구조

| 방식 | 장점 | 단점 | 적합한 경우 |
|------|------|------|------------|
| **Workspace** | 코드 중복 없음, 간단 | 환경별 차이 표현 제한적 | 환경별 차이가 적을 때 |
| **Directory** | 완전한 분리, 유연성 | 코드 중복, 동기화 필요 | 환경별 구성이 다를 때 |
| **Terragrunt** | DRY 원칙, 모듈화 | 학습 곡선 | 대규모 인프라 |

### Workspace State 관리

```
┌─────────────────────────────────────────────────────────────┐
│  S3 Backend + Workspace                                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  s3://terraform-state-bucket/                               │
│  ├── env:/                                                  │
│  │   ├── dev/                                               │
│  │   │   └── terraform.tfstate                              │
│  │   ├── staging/                                           │
│  │   │   └── terraform.tfstate                              │
│  │   └── prod/                                              │
│  │       └── terraform.tfstate                              │
│  └── terraform.tfstate  (default workspace)                 │
│                                                             │
│  각 환경의 State가 자동으로 분리되어 저장됨                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 실습 1: Workspace 기본 사용법 (15분)

**목표**: Workspace 생성, 전환, 삭제 마스터

```bash
# 1. 현재 Workspace 확인
terraform workspace list

# 예상 출력:
# * default

# 2. 새 Workspace 생성
terraform workspace new dev
terraform workspace new staging
terraform workspace new prod

# 예상 출력:
# Created and switched to workspace "dev"!

# 3. Workspace 목록 확인
terraform workspace list

# 예상 출력:
# * prod
#   default
#   dev
#   staging

# 4. Workspace 전환
terraform workspace select dev

# 5. 현재 Workspace 확인
terraform workspace show

# 예상 출력:
# dev

# 6. Workspace 삭제 (주의: 해당 환경의 리소스가 있으면 삭제 불가)
# terraform workspace delete staging
```

**분석 포인트**:
- `*` 표시는 현재 활성 Workspace
- default Workspace는 삭제 불가
- 리소스가 있는 Workspace는 삭제 전 `terraform destroy` 필요

### 실습 2: 환경별 변수 설정 (25분)

**목표**: Workspace에 따라 다른 설정 적용

```bash
# 프로젝트 구조 생성
cat > main.tf << 'EOF'
terraform {
  required_version = ">= 1.0.0"
  
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
  
  # Remote Backend 설정 (실제 환경)
  # backend "s3" {
  #   bucket         = "tossplace-terraform-state"
  #   key            = "infrastructure/terraform.tfstate"
  #   region         = "ap-northeast-2"
  #   encrypt        = true
  #   dynamodb_table = "terraform-lock"
  # }
}

provider "aws" {
  region = var.aws_region
  
  default_tags {
    tags = {
      Environment = local.environment
      ManagedBy   = "Terraform"
      Project     = "tossplace"
    }
  }
}
EOF
```

```bash
# 변수 정의
cat > variables.tf << 'EOF'
variable "aws_region" {
  description = "AWS 리전"
  type        = string
  default     = "ap-northeast-2"
}

variable "project_name" {
  description = "프로젝트 이름"
  type        = string
  default     = "tossplace"
}
EOF
```

```bash
# 환경별 설정 (locals.tf)
cat > locals.tf << 'EOF'
locals {
  # 현재 Workspace를 환경으로 사용
  environment = terraform.workspace
  
  # 환경별 설정 맵
  env_config = {
    dev = {
      instance_type     = "t3.micro"
      min_size         = 1
      max_size         = 3
      desired_capacity = 1
      db_instance_class = "db.t3.micro"
      enable_monitoring = false
    }
    staging = {
      instance_type     = "t3.small"
      min_size         = 2
      max_size         = 5
      desired_capacity = 2
      db_instance_class = "db.t3.small"
      enable_monitoring = true
    }
    prod = {
      instance_type     = "t3.medium"
      min_size         = 3
      max_size         = 10
      desired_capacity = 3
      db_instance_class = "db.t3.medium"
      enable_monitoring = true
  }
}

  # 현재 환경의 설정 가져오기
  config = local.env_config[local.environment]
  
  # 공통 태그
  common_tags = {
    Environment = local.environment
    Project     = var.project_name
    ManagedBy   = "Terraform"
  }
}
EOF
```

**예상 결과**:
- `terraform workspace select dev` 시 `t3.micro` 사용
- `terraform workspace select prod` 시 `t3.medium` 사용

### 실습 3: 환경별 VPC 구성 (30분)

**목표**: Workspace별로 다른 CIDR 블록의 VPC 생성

```bash
# VPC 모듈 (vpc.tf)
cat > vpc.tf << 'EOF'
# 환경별 CIDR 블록 정의
locals {
  vpc_cidrs = {
    dev     = "10.0.0.0/16"
    staging = "10.1.0.0/16"
    prod    = "10.2.0.0/16"
  }
  
  availability_zones = ["ap-northeast-2a", "ap-northeast-2b", "ap-northeast-2c"]
}

# VPC 생성
resource "aws_vpc" "main" {
  cidr_block           = local.vpc_cidrs[local.environment]
  enable_dns_hostnames = true
  enable_dns_support   = true
  
  tags = merge(local.common_tags, {
    Name = "${var.project_name}-${local.environment}-vpc"
  })
}

# Public Subnets
resource "aws_subnet" "public" {
  count             = length(local.availability_zones)
  vpc_id            = aws_vpc.main.id
  cidr_block        = cidrsubnet(aws_vpc.main.cidr_block, 4, count.index)
  availability_zone = local.availability_zones[count.index]
  
  map_public_ip_on_launch = true
  
  tags = merge(local.common_tags, {
    Name = "${var.project_name}-${local.environment}-public-${count.index + 1}"
    Type = "public"
    "kubernetes.io/role/elb" = "1"
  })
}

# Private Subnets
resource "aws_subnet" "private" {
  count             = length(local.availability_zones)
  vpc_id            = aws_vpc.main.id
  cidr_block        = cidrsubnet(aws_vpc.main.cidr_block, 4, count.index + 4)
  availability_zone = local.availability_zones[count.index]
  
  tags = merge(local.common_tags, {
    Name = "${var.project_name}-${local.environment}-private-${count.index + 1}"
    Type = "private"
    "kubernetes.io/role/internal-elb" = "1"
  })
}

# Internet Gateway
resource "aws_internet_gateway" "main" {
  vpc_id = aws_vpc.main.id
  
  tags = merge(local.common_tags, {
    Name = "${var.project_name}-${local.environment}-igw"
  })
}

# NAT Gateway (prod에서만 다중 AZ)
resource "aws_eip" "nat" {
  count  = local.environment == "prod" ? length(local.availability_zones) : 1
  domain = "vpc"
  
  tags = merge(local.common_tags, {
    Name = "${var.project_name}-${local.environment}-nat-eip-${count.index + 1}"
  })
}

resource "aws_nat_gateway" "main" {
  count         = local.environment == "prod" ? length(local.availability_zones) : 1
  allocation_id = aws_eip.nat[count.index].id
  subnet_id     = aws_subnet.public[count.index].id
  
  tags = merge(local.common_tags, {
    Name = "${var.project_name}-${local.environment}-nat-${count.index + 1}"
  })
  
  depends_on = [aws_internet_gateway.main]
}
EOF
```

**분석 포인트**:
- dev: `10.0.0.0/16`
- staging: `10.1.0.0/16`
- prod: `10.2.0.0/16`
- prod 환경만 다중 AZ NAT Gateway (비용 최적화)

### 실습 5: CI/CD 환경 검증 스크립트 (10분)

**목표**: 배포 전 환경 검증 자동화

```bash
# validate-workspace.sh
cat > validate-workspace.sh << 'EOF'
#!/bin/bash
set -e

# 현재 Workspace 확인
WORKSPACE=$(terraform workspace show)
BRANCH=${GITHUB_REF_NAME:-$(git branch --show-current)}

echo "🔍 Environment Validation"
echo "========================="
echo "Current Workspace: $WORKSPACE"
echo "Git Branch: $BRANCH"

# 브랜치-환경 매핑 검증
case $BRANCH in
  develop)
    EXPECTED_WORKSPACE="dev"
    ;;
  staging)
    EXPECTED_WORKSPACE="staging"
    ;;
  main|master)
    EXPECTED_WORKSPACE="prod"
    ;;
  *)
    echo "⚠️  Unknown branch: $BRANCH"
    exit 0
    ;;
esac

if [ "$WORKSPACE" != "$EXPECTED_WORKSPACE" ]; then
  echo "❌ ERROR: Branch '$BRANCH' should use workspace '$EXPECTED_WORKSPACE'"
  echo "   Current workspace is '$WORKSPACE'"
  echo ""
  echo "   Fix: terraform workspace select $EXPECTED_WORKSPACE"
  exit 1
fi

echo "✅ Workspace validation passed!"
echo "   Branch '$BRANCH' → Workspace '$WORKSPACE'"
EOF

chmod +x validate-workspace.sh
```

### 시나리오 3: Workspace 간 리소스 참조

```bash
# prod에서 dev VPC를 참조해야 하는 경우 (VPC Peering 등)

# terraform_remote_state 사용
cat > data.tf << 'EOF'
data "terraform_remote_state" "dev" {
  backend = "s3"
  
  config = {
    bucket = "tossplace-terraform-state"
    key    = "env:/dev/infrastructure/terraform.tfstate"
    region = "ap-northeast-2"
  }
}

# VPC Peering 생성
resource "aws_vpc_peering_connection" "dev_to_prod" {
  count = local.environment == "prod" ? 1 : 0
  
  vpc_id        = aws_vpc.main.id
  peer_vpc_id   = data.terraform_remote_state.dev.outputs.vpc_id
  auto_accept   = true
  
  tags = merge(local.common_tags, {
    Name = "dev-to-prod-peering"
  })
}
EOF
```
