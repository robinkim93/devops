## 🛠️ Part 2: 필수 CLI 명령어 복습 (1시간)

### VPC 명령어

```bash
# VPC 목록
aws ec2 describe-vpcs \
  --query 'Vpcs[].[VpcId,CidrBlock,Tags[?Key==`Name`].Value|[0]]' \
  --output table

# 서브넷 목록
aws ec2 describe-subnets \
  --filters "Name=vpc-id,Values=vpc-xxx" \
  --query 'Subnets[].[SubnetId,CidrBlock,AvailabilityZone]' \
  --output table

# 보안 그룹 조회
aws ec2 describe-security-groups \
  --group-ids sg-xxx \
  --query 'SecurityGroups[0].IpPermissions'
```

### IAM 명령어

```bash
# 사용자 목록
aws iam list-users \
  --query 'Users[].[UserName,CreateDate]' \
  --output table

# Role 목록
aws iam list-roles \
  --query 'Roles[].[RoleName,Arn]' \
  --output table

# Role의 정책 확인
aws iam list-attached-role-policies \
  --role-name my-role

# IRSA 설정 확인
aws eks describe-cluster \
  --name my-cluster \
  --query 'cluster.identity.oidc'
```

### EKS 명령어

```bash
# 클러스터 목록
aws eks list-clusters

# 클러스터 상세 정보
aws eks describe-cluster \
  --name my-cluster \
  --query 'cluster.{Name:name,Status:status,Version:version,Endpoint:endpoint}'

# 노드 그룹 목록
aws eks list-nodegroups \
  --cluster-name my-cluster

# kubeconfig 업데이트
aws eks update-kubeconfig \
  --name my-cluster \
  --region ap-northeast-2
```

### S3 명령어

```bash
# 버킷 목록
aws s3 ls

# 버킷 내용
aws s3 ls s3://my-bucket/

# 파일 작업
aws s3 cp local.txt s3://my-bucket/
aws s3 sync ./local-dir s3://my-bucket/backup/

# 버킷 설정 확인
aws s3api get-bucket-versioning --bucket my-bucket
aws s3api get-bucket-encryption --bucket my-bucket
```

### RDS 명령어

```bash
# 인스턴스 목록
aws rds describe-db-instances \
  --query 'DBInstances[].[DBInstanceIdentifier,Engine,DBInstanceStatus]' \
  --output table

# 스냅샷 생성
aws rds create-db-snapshot \
  --db-instance-identifier my-db \
  --db-snapshot-identifier my-snapshot

# Read Replica 상태
aws rds describe-db-instances \
  --query 'DBInstances[?ReadReplicaSourceDBInstanceIdentifier!=`null`].[DBInstanceIdentifier,ReadReplicaSourceDBInstanceIdentifier]'
```

### CloudWatch 명령어

```bash
# 알람 목록
aws cloudwatch describe-alarms \
  --query 'MetricAlarms[].[AlarmName,StateValue]' \
  --output table

# 메트릭 조회
aws cloudwatch get-metric-statistics \
  --namespace AWS/EC2 \
  --metric-name CPUUtilization \
  --dimensions Name=InstanceId,Value=i-xxx \
  --start-time $(date -u -d '1 hour ago' +%Y-%m-%dT%H:%M:%SZ) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%SZ) \
  --period 300 \
  --statistics Average

# 로그 조회
aws logs tail /aws/eks/my-cluster/cluster --since 1h
```

## 🛠️ Part 3: 실전 시나리오 문제 (1.5시간)

### 시나리오 1: 신규 서비스 배포 환경 구성

```
📋 상황: 새로운 마이크로서비스를 배포해야 합니다.
필요한 작업:
1. 서비스 전용 IAM Role 생성 (S3 접근 필요)
2. EKS에 서비스 계정 연동
3. 배포 확인
```

**해결 과정:**

```bash
# 1. IAM Policy 생성
cat << 'EOF' > s3-policy.json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::my-bucket",
        "arn:aws:s3:::my-bucket/*"
      ]
    }
  ]
}
EOF

aws iam create-policy \
  --policy-name MyServiceS3Policy \
  --policy-document file://s3-policy.json

# 2. IAM Role 생성 (IRSA용)
OIDC_PROVIDER=$(aws eks describe-cluster \
  --name my-cluster \
  --query 'cluster.identity.oidc.issuer' \
  --output text | sed 's|https://||')

cat << EOF > trust-policy.json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::ACCOUNT_ID:oidc-provider/${OIDC_PROVIDER}"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "${OIDC_PROVIDER}:sub": "system:serviceaccount:default:my-service-sa"
        }
      }
    }
  ]
}
EOF

aws iam create-role \
  --role-name MyServiceRole \
  --assume-role-policy-document file://trust-policy.json

# 3. K8s ServiceAccount 생성
kubectl create serviceaccount my-service-sa \
  --namespace default

kubectl annotate serviceaccount my-service-sa \
  --namespace default \
  eks.amazonaws.com/role-arn=arn:aws:iam::ACCOUNT_ID:role/MyServiceRole
```

### 시나리오 3: 보안 감사

```
📋 상황: 지난 24시간 동안의 보안 관련 활동을 감사해야 합니다.
확인 항목:
1. IAM 정책 변경
2. 보안 그룹 변경
3. 비정상 API 호출
```

**해결 과정:**

```bash
# 1. IAM 정책 변경 확인
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventSource,AttributeValue=iam.amazonaws.com \
  --start-time $(date -d '24 hours ago' +%Y-%m-%dT%H:%M:%SZ) \
  --query 'Events[?contains(EventName, `Policy`)].[EventTime,EventName,Username]' \
  --output table

# 2. 보안 그룹 변경 확인
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventSource,AttributeValue=ec2.amazonaws.com \
  --start-time $(date -d '24 hours ago' +%Y-%m-%dT%H:%M:%SZ) \
  --query 'Events[?contains(EventName, `SecurityGroup`)].[EventTime,EventName,Username]' \
  --output table

# 3. 실패한 API 호출 확인
aws cloudtrail lookup-events \
  --start-time $(date -d '24 hours ago' +%Y-%m-%dT%H:%M:%SZ) \
  --query 'Events[?contains(CloudTrailEvent, `errorCode`)].[EventTime,EventName,Username]' \
  --output table
```

## 📝 Part 4: 면접 대비 질문 (30분)

### Q1: EKS에서 Pod가 S3에 접근하려면 어떻게 설정하나요?
> "IRSA(IAM Roles for Service Accounts)를 사용합니다. EKS 클러스터의 OIDC Provider를 IAM에 등록하고, S3 접근 권한이 있는 IAM Role을 생성합니다. 이 Role의 Trust Policy에 특정 ServiceAccount만 assume할 수 있도록 설정하고, Kubernetes ServiceAccount에 IAM Role ARN을 annotation으로 추가합니다."

### Q2: RDS Multi-AZ 장애 조치 과정을 설명해주세요.
> "Primary 인스턴스 장애 시 자동으로 Standby가 승격됩니다. DNS 엔드포인트는 동일하게 유지되며, 60-120초 내에 전환됩니다. 동기 복제를 사용하므로 데이터 손실이 없습니다. 애플리케이션은 연결 재시도 로직만 있으면 자동으로 새 Primary에 연결됩니다."

### Q3: VPC 설계 시 고려사항은?
> "첫째, CIDR 블록은 충분히 크게 설정합니다. 둘째, 퍼블릭/프라이빗 서브넷을 분리하고, 각 AZ에 배치합니다. 셋째, NAT Gateway로 프라이빗 서브넷의 아웃바운드 트래픽을 처리합니다. 넷째, Security Group과 NACL로 네트워크 접근을 제어합니다. 다섯째, VPC Peering이나 Transit Gateway로 다른 VPC와 연결합니다."

### Q4: CloudWatch와 Prometheus를 언제 각각 사용하나요?
> "CloudWatch는 AWS 네이티브 서비스(EC2, RDS, S3 등)의 인프라 메트릭과 로그에 사용합니다. Prometheus는 Kubernetes 워크로드와 애플리케이션 메트릭에 사용합니다. 토스플레이스에서는 AWS 리소스는 CloudWatch, EKS 내 서비스는 Prometheus + Thanos + Grafana 스택으로 모니터링합니다."
