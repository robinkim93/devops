## 📚 Part 1: 핵심 개념 (1시간)

### IAM 구성 요소

```
┌─────────────────────────────────────────────────────────────┐
│  IAM 구성 요소                                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  User (사용자)                                              │
│  └─ 개별 사람/서비스 계정                                   │
│     └─ Access Key + Secret Key (프로그래밍 접근)            │
│                                                             │
│  Group (그룹)                                               │
│  └─ User 집합                                               │
│     └─ 그룹에 Policy 연결 → 모든 멤버에 적용                │
│                                                             │
│  Role (역할)                                                │
│  └─ 임시 자격증명                                           │
│     └─ EC2, Lambda, EKS Pod가 assume                        │
│     └─ Cross-account 접근                                   │
│                                                             │
│  Policy (정책)                                              │
│  └─ JSON으로 권한 정의                                      │
│     └─ Managed Policy / Inline Policy                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### IAM Policy 구조

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowS3Read",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::my-bucket",
        "arn:aws:s3:::my-bucket/*"
      ],
      "Condition": {
        "IpAddress": {
          "aws:SourceIp": "10.0.0.0/8"
        }
      }
    }
  ]
}
```

## 🛠️ Part 2: 실습 (2시간)

### 실습 1: IAM 정보 조회 (30분)

```bash
# 현재 사용자 정보
aws sts get-caller-identity

# IAM 사용자 목록
aws iam list-users --output table

# IAM 그룹 목록
aws iam list-groups --output table

# IAM 역할 목록
aws iam list-roles --query 'Roles[].{Name:RoleName,Arn:Arn}' --output table

# 사용자에 연결된 정책
aws iam list-attached-user-policies --user-name myuser
```

### 실습 2: IAM Policy 분석 (30분)

```bash
# 관리형 정책 조회
aws iam list-policies --scope Local --query 'Policies[].{Name:PolicyName,Arn:Arn}'

# 정책 상세 내용 조회
aws iam get-policy-version \
  --policy-arn arn:aws:iam::123456789012:policy/MyPolicy \
  --version-id v1
```

### 실습 3: EKS용 IAM Role 이해 (IRSA) (30분)

```yaml
# Kubernetes ServiceAccount with IAM Role
apiVersion: v1
kind: ServiceAccount
metadata:
  name: my-app
  namespace: default
  annotations:
    eks.amazonaws.com/role-arn: arn:aws:iam::123456789012:role/my-app-role
```

```json
// Trust Policy for IRSA
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::123456789012:oidc-provider/oidc.eks.region.amazonaws.com/id/EXAMPLED539D4633E53DE1B716D3041E"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "oidc.eks.region.amazonaws.com/id/EXAMPLED539D4633E53DE1B716D3041E:sub": "system:serviceaccount:default:my-app"
        }
      }
    }
  ]
}
```

### 실습 4: 자주 사용하는 Policy 작성 (30분)

```json
// S3 Read Only
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::my-bucket",
        "arn:aws:s3:::my-bucket/*"
      ]
    }
  ]
}

// EKS Full Access
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "eks:*",
      "Resource": "*"
    }
  ]
}

// RDS Read Only
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "rds:Describe*",
        "rds:List*"
      ],
      "Resource": "*"
    }
  ]
}
```
