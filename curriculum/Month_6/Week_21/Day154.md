## Part 1: EKS 개요 (1시간)

### 1.1 EKS란?

```
EKS (Elastic Kubernetes Service):
- AWS에서 제공하는 관리형 Kubernetes 서비스
- Control Plane을 AWS가 관리
- Worker Node는 EC2 또는 Fargate
- AWS 서비스와 긴밀한 통합

관리형 vs 자체 관리:

자체 관리 K8s:
┌─────────────────────────────────────────────────┐
│  사용자가 모두 관리                              │
│  - Control Plane 설치/운영                      │
│  - etcd 백업                                    │
│  - 업그레이드                                   │
│  - 고가용성 구성                                │
│  - 보안 패치                                    │
└─────────────────────────────────────────────────┘

EKS (관리형):
┌─────────────────────────────────────────────────┐
│  AWS가 관리         │  사용자가 관리            │
│  - Control Plane    │  - Worker Node            │
│  - etcd             │  - 애플리케이션           │
│  - 업그레이드       │  - 네트워킹 (일부)        │
│  - 고가용성         │  - 모니터링               │
│  - 보안 패치        │  - 로깅                   │
└─────────────────────────────────────────────────┘
```

### 1.3 EKS 노드 유형

| 유형 | 설명 | 사용 사례 |
|------|------|----------|
| **Managed Node Groups** | AWS가 EC2 관리 | 일반적인 워크로드 |
| **Self-managed Nodes** | 사용자가 EC2 관리 | 커스텀 AMI 필요 시 |
| **Fargate** | 서버리스 컨테이너 | 간헐적/소규모 워크로드 |

## Part 2: EKS 구성요소 상세 (1시간)

### 2.1 Control Plane

```
EKS Control Plane 특징:

1. 고가용성
   - 3개 AZ에 분산
   - 자동 복구
   - SLA 99.95%

2. 자동 관리
   - 버전 업그레이드
   - 보안 패치
   - etcd 백업

3. 통합
   - IAM 인증
   - CloudWatch 로깅
   - VPC 네트워킹
```

### 2.2 Managed Node Groups

```
Managed Node Group:

┌─────────────────────────────────────────────────────────────┐
│                    Node Group                                │
│                                                             │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐         │
│  │   EC2       │  │   EC2       │  │   EC2       │         │
│  │   Node      │  │   Node      │  │   Node      │         │
│  │             │  │             │  │             │         │
│  │ - kubelet   │  │ - kubelet   │  │ - kubelet   │         │
│  │ - kube-proxy│  │ - kube-proxy│  │ - kube-proxy│         │
│  │ - containerd│  │ - containerd│  │ - containerd│         │
│  └─────────────┘  └─────────────┘  └─────────────┘         │
│                                                             │
│  Auto Scaling Group (ASG)                                   │
│  - Min: 2, Max: 10, Desired: 3                             │
│                                                             │
└─────────────────────────────────────────────────────────────┘

특징:
- AWS가 EC2 프로비저닝/업그레이드 관리
- Auto Scaling Group 기반
- Amazon Linux 2 또는 Bottlerocket AMI
```

### 2.3 Fargate

```
EKS + Fargate:

┌─────────────────────────────────────────────────────────────┐
│                    Fargate                                   │
│                                                             │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐         │
│  │   Pod       │  │   Pod       │  │   Pod       │         │
│  │   (격리됨)  │  │   (격리됨)  │  │   (격리됨)  │         │
│  └─────────────┘  └─────────────┘  └─────────────┘         │
│                                                             │
│  - EC2 관리 불필요                                          │
│  - Pod 단위 격리                                            │
│  - Pod 단위 과금                                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘

제한사항:
- DaemonSet 사용 불가
- 특권 컨테이너 불가
- GPU 지원 안됨
- hostNetwork/hostPort 불가
```

### 2.4 AWS 통합 서비스

| 서비스 | EKS 통합 |
|--------|----------|
| IAM | IRSA (IAM Roles for Service Accounts) |
| ELB | AWS Load Balancer Controller |
| EBS | EBS CSI Driver |
| EFS | EFS CSI Driver |
| VPC | VPC CNI Plugin |
| CloudWatch | Container Insights |

## Part 3: CLI 실습 (1시간)

### 실습 1: eksctl 설치

```bash
# macOS
brew tap weaveworks/tap
brew install weaveworks/tap/eksctl

# Linux
curl --silent --location "https://github.com/weaveworks/eksctl/releases/latest/download/eksctl_$(uname -s)_amd64.tar.gz" | tar xz -C /tmp
sudo mv /tmp/eksctl /usr/local/bin

# 버전 확인
eksctl version
```

### 실습 2: 클러스터 생성 (예시)

```bash
# 기본 클러스터 생성
eksctl create cluster \
  --name my-cluster \
  --region ap-northeast-2 \
  --version 1.28 \
  --nodegroup-name standard-workers \
  --node-type t3.medium \
  --nodes 3 \
  --nodes-min 2 \
  --nodes-max 5 \
  --managed

# 또는 설정 파일 사용
cat << 'EOF' > cluster.yaml
apiVersion: eksctl.io/v1alpha5
kind: ClusterConfig

metadata:
  name: my-cluster
  region: ap-northeast-2
  version: "1.28"

managedNodeGroups:
  - name: standard-workers
    instanceType: t3.medium
    desiredCapacity: 3
    minSize: 2
    maxSize: 5
    volumeSize: 50
    ssh:
      allow: true
      publicKeyName: my-key
    labels:
      role: worker
    tags:
      Environment: dev

  - name: spot-workers
    instanceType: t3.large
    spot: true
    desiredCapacity: 2
    minSize: 0
    maxSize: 10
    labels:
      role: spot-worker
EOF

# 설정 파일로 생성
eksctl create cluster -f cluster.yaml
```

### 실습 3: kubectl 설정

```bash
# kubeconfig 업데이트
aws eks update-kubeconfig --name my-cluster --region ap-northeast-2

# 클러스터 확인
kubectl cluster-info
kubectl get nodes

# 노드 상세
kubectl describe nodes
```

### 실습 4: 클러스터 정보 확인

```bash
# eksctl로 클러스터 목록
eksctl get cluster

# 노드 그룹 목록
eksctl get nodegroup --cluster my-cluster

# AWS CLI로 확인
aws eks describe-cluster --name my-cluster --query 'cluster.status'
aws eks list-nodegroups --cluster-name my-cluster
```

## Part 4: 운영 (1시간)

### 실습 5: 노드 스케일링

```bash
# 노드 그룹 스케일링
eksctl scale nodegroup \
  --cluster my-cluster \
  --name standard-workers \
  --nodes 5 \
  --nodes-min 3 \
  --nodes-max 10

# 확인
kubectl get nodes
```

### 실습 6: 클러스터 업그레이드

```bash
# 현재 버전 확인
kubectl version

# Control Plane 업그레이드 (AWS 콘솔 또는 CLI)
eksctl upgrade cluster --name my-cluster --version 1.29

# 노드 그룹 업그레이드
eksctl upgrade nodegroup \
  --cluster my-cluster \
  --name standard-workers \
  --kubernetes-version 1.29
```

### 실습 7: Add-on 관리

```bash
# 설치된 Add-on 목록
aws eks list-addons --cluster-name my-cluster

# VPC CNI Add-on 설치
aws eks create-addon \
  --cluster-name my-cluster \
  --addon-name vpc-cni \
  --addon-version v1.15.0-eksbuild.2

# CoreDNS Add-on 설치
aws eks create-addon \
  --cluster-name my-cluster \
  --addon-name coredns

# kube-proxy Add-on 설치
aws eks create-addon \
  --cluster-name my-cluster \
  --addon-name kube-proxy
```

### 실습 8: 클러스터 삭제

```bash
# 클러스터 삭제 (모든 리소스 포함)
eksctl delete cluster --name my-cluster

# 또는 설정 파일 사용
eksctl delete cluster -f cluster.yaml
```

## 면접 대비 핵심 포인트

**Q1: EKS의 장점은?**
> "Control Plane을 AWS가 관리하므로 운영 부담이 줄고, IAM, ELB, EBS 등 AWS 서비스와 긴밀하게 통합됩니다. 3개 AZ에 분산되어 고가용성이 보장됩니다."

**Q2: Managed Node Group과 Fargate의 차이는?**
> "Managed Node Group은 EC2 기반으로 AWS가 프로비저닝을 관리하지만 노드가 존재합니다. Fargate는 서버리스로 Pod 단위로 격리되며 EC2 관리가 필요 없지만, DaemonSet 사용이 불가합니다."

**Q3: EKS 업그레이드 순서는?**
> "먼저 Control Plane을 업그레이드하고, 그 다음 Node Group을 업그레이드합니다. 한 번에 한 마이너 버전씩 업그레이드해야 합니다."
