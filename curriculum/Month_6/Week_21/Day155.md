### S3 스토리지 클래스

| 클래스 | 특징 | 사용 사례 | 비용 |
|--------|------|----------|------|
| **Standard** | 자주 접근 | 활성 데이터 | 가장 높음 |
| **Intelligent-Tiering** | 자동 티어링 | 접근 패턴 불규칙 | 자동 최적화 |
| **Standard-IA** | 비활성, 즉시 접근 | 백업, DR | 중간 |
| **One Zone-IA** | 단일 AZ | 재생성 가능 데이터 | 낮음 |
| **Glacier Instant** | 아카이브, 즉시 접근 | 분기별 접근 | 낮음 |
| **Glacier Flexible** | 아카이브, 분~시간 | 연간 접근 | 매우 낮음 |
| **Glacier Deep Archive** | 장기 아카이브 | 규정 준수 | 가장 낮음 |

### S3 버전 관리

```bash
# 버전 관리 활성화
aws s3api put-bucket-versioning \
  --bucket my-bucket \
  --versioning-configuration Status=Enabled

# 버전 목록 조회
aws s3api list-object-versions \
  --bucket my-bucket \
  --prefix myfile.txt

# 특정 버전 다운로드
aws s3api get-object \
  --bucket my-bucket \
  --key myfile.txt \
  --version-id "abc123" \
  myfile-old.txt

# 삭제된 객체 복원 (삭제 마커 제거)
aws s3api delete-object \
  --bucket my-bucket \
  --key myfile.txt \
  --version-id "delete-marker-id"
```

### S3 암호화

```bash
# 서버 측 암호화 (SSE-S3)
aws s3 cp file.txt s3://my-bucket/ \
  --sse AES256

# KMS 암호화 (SSE-KMS)
aws s3 cp file.txt s3://my-bucket/ \
  --sse aws:kms \
  --sse-kms-key-id alias/my-key

# 버킷 기본 암호화 설정
aws s3api put-bucket-encryption \
  --bucket my-bucket \
  --server-side-encryption-configuration '{
    "Rules": [{
      "ApplyServerSideEncryptionByDefault": {
        "SSEAlgorithm": "aws:kms",
        "KMSMasterKeyID": "alias/my-key"
      }
    }]
  }'
```

### S3 수명 주기 정책

```json
// lifecycle-policy.json
{
  "Rules": [
    {
      "ID": "TransitionToIA",
      "Status": "Enabled",
      "Filter": {
        "Prefix": "logs/"
      },
      "Transitions": [
        {
          "Days": 30,
          "StorageClass": "STANDARD_IA"
        },
        {
          "Days": 90,
          "StorageClass": "GLACIER"
        }
      ],
      "Expiration": {
        "Days": 365
      }
    },
    {
      "ID": "DeleteOldVersions",
      "Status": "Enabled",
      "Filter": {},
      "NoncurrentVersionTransitions": [
        {
          "NoncurrentDays": 30,
          "StorageClass": "GLACIER"
        }
      ],
      "NoncurrentVersionExpiration": {
        "NoncurrentDays": 90
      }
    }
  ]
}
```

```bash
# 수명 주기 정책 적용
aws s3api put-bucket-lifecycle-configuration \
  --bucket my-bucket \
  --lifecycle-configuration file://lifecycle-policy.json
```

### RDS CLI 실습

```bash
# RDS 인스턴스 목록
aws rds describe-db-instances \
  --query 'DBInstances[].[DBInstanceIdentifier,Engine,DBInstanceStatus,Endpoint.Address]' \
  --output table

# 인스턴스 상세 정보
aws rds describe-db-instances \
  --db-instance-identifier my-db \
  --query 'DBInstances[0].{
    ID:DBInstanceIdentifier,
    Class:DBInstanceClass,
    Engine:Engine,
    Version:EngineVersion,
    Status:DBInstanceStatus,
    MultiAZ:MultiAZ,
    Storage:AllocatedStorage,
    Endpoint:Endpoint.Address
  }'

# 스냅샷 생성
aws rds create-db-snapshot \
  --db-instance-identifier my-db \
  --db-snapshot-identifier my-db-snapshot-$(date +%Y%m%d)

# 스냅샷 목록
aws rds describe-db-snapshots \
  --db-instance-identifier my-db \
  --query 'DBSnapshots[].[DBSnapshotIdentifier,Status,SnapshotCreateTime]' \
  --output table

# Read Replica 생성
aws rds create-db-instance-read-replica \
  --db-instance-identifier my-db-replica \
  --source-db-instance-identifier my-db \
  --db-instance-class db.t3.medium

# 파라미터 그룹 조회
aws rds describe-db-parameters \
  --db-parameter-group-name my-parameter-group \
  --query 'Parameters[?ParameterName==`max_connections`]'
```

### RDS 모니터링 메트릭

```bash
# CloudWatch에서 RDS 메트릭 조회
# CPU 사용률
aws cloudwatch get-metric-statistics \
  --namespace AWS/RDS \
  --metric-name CPUUtilization \
  --dimensions Name=DBInstanceIdentifier,Value=my-db \
  --start-time $(date -u -d '1 hour ago' +%Y-%m-%dT%H:%M:%SZ) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%SZ) \
  --period 300 \
  --statistics Average

# 주요 모니터링 메트릭
# - CPUUtilization: CPU 사용률
# - FreeableMemory: 사용 가능한 메모리
# - DatabaseConnections: 활성 연결 수
# - ReadIOPS/WriteIOPS: I/O 작업 수
# - ReadLatency/WriteLatency: I/O 지연 시간
# - FreeStorageSpace: 남은 스토리지
# - ReplicaLag: 복제 지연 (Read Replica)
```

### Thanos를 위한 S3 설정

```bash
# Thanos 저장용 버킷 생성
aws s3 mb s3://toss-thanos-storage --region ap-northeast-2

# 버킷 정책 설정
cat << 'EOF' > thanos-bucket-policy.json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:role/thanos-role"
      },
      "Action": [
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::toss-thanos-storage",
        "arn:aws:s3:::toss-thanos-storage/*"
      ]
    }
  ]
}
EOF

aws s3api put-bucket-policy \
  --bucket toss-thanos-storage \
  --policy file://thanos-bucket-policy.json

# 암호화 활성화
aws s3api put-bucket-encryption \
  --bucket toss-thanos-storage \
  --server-side-encryption-configuration '{
    "Rules": [{
      "ApplyServerSideEncryptionByDefault": {
        "SSEAlgorithm": "AES256"
      }
    }]
  }'
```

### RDS 백업 및 복원 실습

```bash
# 자동 백업 설정 확인
aws rds describe-db-instances \
  --db-instance-identifier my-db \
  --query 'DBInstances[0].{
    BackupRetention:BackupRetentionPeriod,
    BackupWindow:PreferredBackupWindow,
    LatestRestorableTime:LatestRestorableTime
  }'

# Point-in-Time Recovery
aws rds restore-db-instance-to-point-in-time \
  --source-db-instance-identifier my-db \
  --target-db-instance-identifier my-db-restored \
  --restore-time 2024-01-15T10:00:00Z

# 스냅샷에서 복원
aws rds restore-db-instance-from-db-snapshot \
  --db-instance-identifier my-db-from-snapshot \
  --db-snapshot-identifier my-db-snapshot-20240115
```

## 📝 면접 대비 질문

### Q1: S3 스토리지 클래스를 어떻게 선택하나요?
> "접근 빈도와 비용을 고려합니다. 자주 접근하는 활성 데이터는 Standard, 30일 이상 접근하지 않는 데이터는 Standard-IA, 규정 준수용 장기 보관은 Glacier를 사용합니다. 접근 패턴이 불규칙하면 Intelligent-Tiering이 자동으로 최적화해줍니다."

### Q2: RDS Multi-AZ와 Read Replica의 차이는?
> "Multi-AZ는 고가용성을 위한 것으로, Primary 장애 시 자동으로 Standby로 전환됩니다. 동기 복제를 사용하고 읽기 요청을 처리하지 않습니다. Read Replica는 읽기 성능 향상을 위한 것으로, 비동기 복제를 사용하며 읽기 요청을 분산 처리합니다. 두 가지를 함께 사용하여 가용성과 성능을 모두 확보합니다."
