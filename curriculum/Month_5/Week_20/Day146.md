## 📚 Part 1: 핵심 개념 (30분)

### Alerting 파이프라인

```
┌─────────────────────────────────────────────────────────────┐
│  Prometheus Alerting Pipeline                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. Alert Rule 평가 (15초마다)                              │
│     PrometheusRule 조건 확인                                │
│                          ↓                                  │
│  2. 상태 전이                                               │
│     Inactive → Pending → Firing                            │
│     - Pending: for 기간 대기                                │
│     - Firing: 알림 발송                                     │
│                          ↓                                  │
│  3. Alertmanager 처리                                       │
│     - Grouping: 관련 알림 묶기                              │
│     - Inhibition: 알림 억제                                 │
│     - Routing: 채널별 전송                                  │
│                          ↓                                  │
│  4. 알림 발송                                               │
│     Slack, Email, PagerDuty                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Alert 설계 Best Practices

| 원칙 | 설명 | 예시 |
|------|------|------|
| Symptom 기반 | 사용자 영향 지표 모니터링 | CPU 대신 응답시간 |
| Actionable | 대응 방법이 명확 | Runbook 링크 포함 |
| 적절한 for | 노이즈 방지 | Critical 5분, Warning 10분 |
| Severity 분리 | 대응 우선순위 | critical, warning |

## 🛠️ Part 2: 실습 (2.5시간)

### 실습 1: Alert Rules 작성 (45분)

**목표**: Golden Signals 기반 Alert 정의

```yaml
# manifests/alerting-rules/sample-app-alerts.yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: sample-app-alerts
  namespace: monitoring
  labels:
    release: prometheus
spec:
  groups:
  - name: sample-app.alerts
    rules:
    # Error Rate Alert
    - alert: SampleAppHighErrorRate
      expr: sample_app:http_error_ratio:rate5m > 0.05
      for: 5m
      labels:
        severity: critical
        service: sample-app
      annotations:
        summary: "High error rate on {{ $labels.service }}"
        description: "Error rate is {{ $value | humanizePercentage }} (threshold: 5%)"
        runbook_url: "https://wiki.example.com/runbook/high-error-rate"
    
    # Latency Alert
    - alert: SampleAppHighLatency
      expr: sample_app:http_request_duration_seconds:p99 > 1
      for: 5m
      labels:
        severity: critical
        service: sample-app
      annotations:
        summary: "High P99 latency on {{ $labels.service }}"
        description: "P99 latency is {{ $value | humanizeDuration }} (threshold: 1s)"
    
    # Availability Alert
    - alert: SampleAppDown
      expr: up{job="sample-app"} == 0
      for: 1m
      labels:
        severity: critical
        service: sample-app
      annotations:
        summary: "{{ $labels.service }} is down"
    
    # SLO Alert
    - alert: SampleAppErrorBudgetLow
      expr: sample_app:error_budget_remaining:ratio < 0.2
      for: 5m
      labels:
        severity: warning
        service: sample-app
        slo: availability
      annotations:
        summary: "Error budget running low for {{ $labels.service }}"
        description: "Only {{ $value | humanizePercentage }} of error budget remaining"
```

```bash
# 적용
kubectl apply -f manifests/alerting-rules/sample-app-alerts.yaml

# 확인
kubectl get prometheusrules -n monitoring
kubectl describe prometheusrule sample-app-alerts -n monitoring
```

### 실습 2: Alertmanager 설정 (45분)

**목표**: 알림 라우팅 및 수신자 설정

```yaml
# manifests/alertmanager/alertmanager-config.yaml
apiVersion: monitoring.coreos.com/v1alpha1
kind: AlertmanagerConfig
metadata:
  name: sample-app-alertmanager-config
  namespace: monitoring
  labels:
    release: prometheus
spec:
  route:
    groupBy: ['alertname', 'service']
    groupWait: 30s
    groupInterval: 5m
    repeatInterval: 4h
    receiver: 'default'
    routes:
    - match:
        severity: critical
      receiver: 'slack-critical'
    - match:
        severity: warning
      receiver: 'slack-warning'
  
  receivers:
  - name: 'default'
  - name: 'slack-critical'
    slackConfigs:
    - apiURL:
        name: slack-webhook-secret
        key: webhook-url
      channel: '#alerts-critical'
      sendResolved: true
      title: '🚨 [{{ .Status | toUpper }}] {{ .CommonLabels.alertname }}'
      text: |
        *Service:* {{ .CommonLabels.service }}
        *Description:* {{ .CommonAnnotations.description }}
        *Runbook:* {{ .CommonAnnotations.runbook_url }}
  - name: 'slack-warning'
    slackConfigs:
    - apiURL:
        name: slack-webhook-secret
        key: webhook-url
      channel: '#alerts-warning'
      sendResolved: true
  
  inhibitRules:
  - sourceMatch:
      severity: critical
    targetMatch:
      severity: warning
    equal: ['alertname', 'service']
```

```bash
# Slack Webhook Secret 생성
kubectl create secret generic slack-webhook-secret \
  -n monitoring \
  --from-literal=webhook-url="https://hooks.slack.com/services/YOUR/WEBHOOK/URL"

# 적용
kubectl apply -f manifests/alertmanager/alertmanager-config.yaml
```

### 실습 3: 알림 테스트 (30분)

```bash
# 1. Prometheus Alerts UI 확인
kubectl port-forward -n monitoring svc/prometheus-kube-prometheus-prometheus 9090:9090 &
# http://localhost:9090/alerts

# 2. Alertmanager UI 확인
kubectl port-forward -n monitoring svc/prometheus-kube-prometheus-alertmanager 9093:9093 &
# http://localhost:9093

# 3. 에러 발생시켜 Alert Firing 확인
kubectl run error-generator --image=busybox --restart=Never -- sh -c "
while true; do
    wget -q -O- http://sample-app/error || true
    sleep 0.05
done
"

# 4. 5분 후 Alert 상태 확인 (Inactive → Pending → Firing)

# 5. 정리
kubectl delete pod error-generator
```

- Alert 상태 전이 확인
- Alertmanager에서 그룹핑 확인
- 알림 발송 확인
