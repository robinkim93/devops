## 📚 Part 1: 핵심 개념 (30분)

### Prometheus Operator란?

```
┌─────────────────────────────────────────────────────────────┐
│  기존 방식 vs Prometheus Operator                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [기존 방식]                                                 │
│  - prometheus.yml에 모든 타겟 수동 정의                     │
│  - 새 서비스 추가 시 설정 파일 수정 필요                    │
│  - Prometheus 재시작 필요                                   │
│                                                             │
│  [Prometheus Operator 방식]                                 │
│  - ServiceMonitor CRD로 타겟 선언                           │
│  - 라벨 기반 자동 서비스 발견                               │
│  - Hot reload (재시작 불필요)                               │
│  - GitOps 친화적                                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### kube-prometheus-stack 포함 컴포넌트

| 컴포넌트 | 역할 |
|---------|------|
| Prometheus Operator | CRD 컨트롤러 |
| Prometheus | 메트릭 서버 |
| Alertmanager | 알림 관리 |
| Grafana | 시각화 |
| node-exporter | 노드 메트릭 |
| kube-state-metrics | K8s 오브젝트 상태 |

### 토스플레이스 설정 기준

| 설정 항목 | 개발 환경 | 프로덕션 환경 |
|----------|----------|-------------|
| Retention | 7일 | 15일 |
| Replicas | 1 | 2 |
| Storage | 10Gi | 100Gi |
| Thanos Sidecar | 비활성화 | 활성화 |

## 🛠️ Part 2: 실습 (2.5시간)

### 사전 준비

```bash
# Kubernetes 클러스터 확인
kubectl cluster-info
kubectl get nodes

# Helm 설치 확인
helm version

# monitoring 네임스페이스 생성
kubectl create namespace monitoring
```

### 실습 1: Helm 저장소 추가 (10분)

```bash
# 저장소 추가
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update

# 차트 확인
helm search repo prometheus-community/kube-prometheus-stack
```

### 실습 2: Values 파일 작성 (30분)

```yaml
# prometheus-values.yaml
prometheus:
  prometheusSpec:
    retention: 15d
    retentionSize: "45GB"
    storageSpec:
      volumeClaimTemplate:
        spec:
          accessModes: ["ReadWriteOnce"]
          resources:
            requests:
              storage: 50Gi
    resources:
      requests:
        cpu: 500m
        memory: 2Gi
    serviceMonitorSelectorNilUsesHelmValues: false
    serviceMonitorSelector: {}
    serviceMonitorNamespaceSelector: {}
    ruleSelectorNilUsesHelmValues: false
    scrapeInterval: 15s
    thanos:
      create: false  # 나중에 활성화

alertmanager:
  alertmanagerSpec:
    storage:
      volumeClaimTemplate:
        spec:
          accessModes: ["ReadWriteOnce"]
          resources:
            requests:
              storage: 10Gi

grafana:
  adminPassword: "admin123"
  persistence:
    enabled: true
    size: 10Gi
  sidecar:
    dashboards:
      enabled: true
      searchNamespace: ALL

nodeExporter:
  enabled: true

kubeStateMetrics:
  enabled: true

defaultRules:
  create: true
```

### 실습 3: Stack 설치 (20분)

```bash
# 설치
helm install prometheus prometheus-community/kube-prometheus-stack \
  -n monitoring \
  -f prometheus-values.yaml \
  --wait

# 설치 확인
kubectl get pods -n monitoring -w
```


### 실습 5: 서비스 접근 (30분)

```bash
# Prometheus UI (9090 포트)
kubectl port-forward -n monitoring svc/prometheus-kube-prometheus-prometheus 9090:9090 &

# Grafana UI (3000 포트)
kubectl port-forward -n monitoring svc/prometheus-grafana 3000:80 &

# Alertmanager UI (9093 포트)
```

**Prometheus UI에서 확인할 것**:
```
1. Status > Targets - 모든 타겟이 UP 상태인지
2. Status > Configuration - 스크랩 설정 확인
3. Graph - up 쿼리로 타겟 상태 확인
```

### 실습 6: 기본 쿼리 테스트 (30분)

```promql
# 1. 모든 타겟 상태 확인
up

# 2. 노드 CPU 사용률 (%)
100 - (avg by (instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# 3. 노드 메모리 사용률 (%)
100 * (1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)

# 4. Pod CPU 사용량
sum(rate(container_cpu_usage_seconds_total{container!=""}[5m])) by (pod, namespace)

# 5. API Server 요청률
sum(rate(apiserver_request_total[5m])) by (verb)
```

**분석 포인트**:
- `rate()`: Counter 메트릭의 초당 증가율
- `irate()`: 순간 증가율 (더 민감)
- `avg by (label)`: 레이블별 평균
