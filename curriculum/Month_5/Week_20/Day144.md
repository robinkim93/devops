## 📚 Part 1: 핵심 개념 (30분)

### ServiceMonitor vs 정적 설정

```
┌─────────────────────────────────────────────────────────────┐
│  ServiceMonitor의 동작 원리                                  │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [기존 prometheus.yml 방식]                                  │
│  scrape_configs:                                            │
│    - job_name: 'myapp'                                      │
│      static_configs:                                        │
│        - targets: ['10.0.0.1:8080']  ← Pod IP 변경 시 수정 │
│                                                             │
│  [ServiceMonitor 방식]                                      │
│  kind: ServiceMonitor                                       │
│  spec:                                                      │
│    selector:                                                │
│      matchLabels:                                           │
│        app: myapp           ← 라벨 기반 자동 발견           │
│    endpoints:                                               │
│    - port: metrics          ← 자동 타겟 추가                │
│                                                             │
│  장점:                                                      │
│  - Pod 스케일 시 자동 타겟 추가/제거                        │
│  - Hot reload (Prometheus 재시작 불필요)                    │
│  - GitOps 친화적                                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Recording Rules란?

```
문제 상황:
- 대시보드에서 복잡한 PromQL 실행 시 느림
- 같은 계산을 여러 대시보드에서 반복
- SLO 계산에 30일 데이터 필요 → 매번 계산 비효율

Recording Rule로 사전 계산:
  record: myapp:http_error_ratio:rate5m
  expr: sum(rate(http_requests_total{status=~"5.."}[5m])) / ...

효과:
- 15초마다 결과를 새 메트릭으로 저장
- 대시보드에서는 저장된 메트릭만 조회 → 빠름
```

### Recording Rule 명명 규칙

```
# 규칙: level:metric:operations
myapp:http_requests:rate5m          # 서비스의 초당 요청수
myapp:http_error_ratio:rate5m       # 서비스의 에러율
namespace:pod_cpu:usage             # 네임스페이스별 CPU 사용량
```

## 🛠️ Part 2: 실습 (2.5시간)

### 실습 1: 테스트 애플리케이션 배포 (30분)

```yaml
# manifests/sample-app/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: sample-app
  namespace: default
  labels:
    app: sample-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: sample-app
  template:
    metadata:
      labels:
        app: sample-app
    spec:
      containers:
      - name: app
        image: quay.io/brancz/prometheus-example-app:v0.3.0
        ports:
        - name: http
          containerPort: 8080
        - name: metrics
          containerPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: sample-app
  labels:
    app: sample-app
spec:
  selector:
    app: sample-app
  ports:
  - name: http
    port: 80
    targetPort: 8080
  - name: metrics
    port: 8080
    targetPort: 8080
```

```bash
kubectl apply -f manifests/sample-app/deployment.yaml
kubectl get pods -l app=sample-app

# 메트릭 엔드포인트 테스트
kubectl port-forward svc/sample-app 8080:8080 &
curl http://localhost:8080/metrics
```

### 실습 2: ServiceMonitor 작성 (30분)

```yaml
# manifests/servicemonitors/sample-app-servicemonitor.yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: sample-app
  namespace: monitoring
  labels:
    app: sample-app
    release: prometheus
spec:
  selector:
    matchLabels:
      app: sample-app
  namespaceSelector:
    matchNames:
    - default
  endpoints:
  - port: metrics
    interval: 15s
    path: /metrics
    relabelings:
    - sourceLabels: [__meta_kubernetes_pod_name]
      targetLabel: pod
    - sourceLabels: [__meta_kubernetes_namespace]
      targetLabel: namespace
```

```bash
kubectl apply -f manifests/servicemonitors/sample-app-servicemonitor.yaml
kubectl get servicemonitor -n monitoring
```

### 실습 3: Recording Rules 작성 (40분)

```yaml
# manifests/recording-rules/sample-app-recording-rules.yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: sample-app-recording-rules
  namespace: monitoring
  labels:
    release: prometheus
spec:
  groups:
  - name: sample-app.recording
    interval: 15s
    rules:
    # Traffic (요청률)
    - record: sample_app:http_requests:rate5m
      expr: sum(rate(http_requests_total{job="sample-app"}[5m])) by (pod)
      labels:
        service: sample-app
    
    - record: sample_app:http_requests_total:rate5m
      expr: sum(rate(http_requests_total{job="sample-app"}[5m]))
      labels:
        service: sample-app
    
    # Errors (에러율)
    - record: sample_app:http_errors:rate5m
      expr: sum(rate(http_requests_total{job="sample-app",code=~"5.."}[5m]))
      labels:
        service: sample-app
    
    - record: sample_app:http_error_ratio:rate5m
      expr: |
        sum(rate(http_requests_total{job="sample-app",code=~"5.."}[5m]))
        /
        sum(rate(http_requests_total{job="sample-app"}[5m]))
      labels:
        service: sample-app
    
    # Latency (지연시간)
    - record: sample_app:http_request_duration_seconds:p50
      expr: histogram_quantile(0.50, sum(rate(http_request_duration_seconds_bucket{job="sample-app"}[5m])) by (le))
      labels:
        service: sample-app
    
    - record: sample_app:http_request_duration_seconds:p90
      expr: histogram_quantile(0.90, sum(rate(http_request_duration_seconds_bucket{job="sample-app"}[5m])) by (le))
      labels:
        service: sample-app
    
    - record: sample_app:http_request_duration_seconds:p99
      expr: histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket{job="sample-app"}[5m])) by (le))
      labels:
        service: sample-app
```

```bash
kubectl apply -f manifests/recording-rules/sample-app-recording-rules.yaml
kubectl get prometheusrules -n monitoring
```

## 🔑 핵심 YAML 구조

```yaml
# ServiceMonitor 필수 필드
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
spec:
  selector:
    matchLabels:
      app: myapp
  namespaceSelector:
    matchNames: [default]
  endpoints:
  - port: metrics
    interval: 15s

# PrometheusRule 필수 필드
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
spec:
  groups:
  - name: myapp.rules
    rules:
    - record: myapp:metric:aggregation
      expr: sum(rate(original_metric[5m]))
```
