# 📅 Day 147: Thanos 연동 (장기 저장)

## 🎯 오늘의 목표

> **토스플레이스 연결점**: "Thanos로 장기 데이터 저장" - 90일 이상 메트릭 보관

### 1.3 Thanos 컴포넌트 상세

| 컴포넌트 | 역할 | 필수 여부 | 설명 |
|---------|------|----------|------|
| **Sidecar** | 데이터 업로드 | ✅ 필수 | Prometheus 옆에서 데이터를 S3로 업로드 |
| **Store Gateway** | S3 데이터 조회 | ✅ 필수 | Object Storage의 과거 데이터 조회 |
| **Query (Querier)** | 통합 쿼리 | ✅ 필수 | Sidecar + Store의 데이터 통합 조회 |
| **Compactor** | 압축/다운샘플링 | 권장 | 저장 효율화, 쿼리 성능 향상 |
| **Query Frontend** | 쿼리 캐싱 | 선택 | 쿼리 결과 캐싱, 분할 실행 |
| **Ruler** | 알림 규칙 | 선택 | 장기 데이터 기반 알림 |
| **Receiver** | 원격 쓰기 | 선택 | remote_write 수신 (Sidecar 대안) |

### 1.4 데이터 흐름

```
┌─────────────────────────────────────────────────────────────────────┐
│  Thanos 데이터 흐름                                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  1. 실시간 데이터 (최근 2시간)                                      │
│  ┌─────────────────────────────────────────────────────────────┐    │
│  │  Prometheus → Sidecar → Thanos Query → Grafana              │    │
│  │                 ↑                                            │    │
│  │       StoreAPI (gRPC)로 실시간 데이터 제공                  │    │
│  └─────────────────────────────────────────────────────────────┘    │
│                                                                      │
│  2. 장기 데이터 저장                                                │
│  ┌─────────────────────────────────────────────────────────────┐    │
│  │  Prometheus → Sidecar → S3 (2시간 블록 단위 업로드)         │    │
│  │                                                              │    │
│  │  Prometheus TSDB:                                            │    │
│  │  [Block 1: 00:00-02:00] → S3 업로드                         │    │
│  │  [Block 2: 02:00-04:00] → S3 업로드                         │    │
│  │  [Block 3: 04:00-현재]  → 아직 로컬                         │    │
│  └─────────────────────────────────────────────────────────────┘    │
│                                                                      │
│  3. 과거 데이터 조회                                                │
│  ┌─────────────────────────────────────────────────────────────┐    │
│  │  Grafana → Thanos Query → Store Gateway → S3                │    │
│  │                                                              │    │
│  │  Store Gateway가 S3의 인덱스를 메모리에 캐시                │    │
│  │  필요한 블록만 S3에서 읽어서 반환                           │    │
│  └─────────────────────────────────────────────────────────────┘    │
│                                                                      │
│  4. 데이터 압축 및 다운샘플링 (Compactor)                           │
│  ┌─────────────────────────────────────────────────────────────┐    │
│  │  • 작은 블록들을 큰 블록으로 합침 (저장 효율)               │    │
│  │  • 오래된 데이터는 5m, 1h 해상도로 다운샘플링              │    │
│  │  • 예: 30일 이상 → 5분 해상도로 저장                       │    │
│  │        90일 이상 → 1시간 해상도로 저장                      │    │
│  └─────────────────────────────────────────────────────────────┘    │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

## 🛠️ Part 2: 실습 (2시간)

### 실습 1: Object Storage 설정 (30분)

로컬 환경에서는 MinIO(S3 호환 스토리지)를 사용합니다.

```bash
# MinIO Helm 저장소 추가
helm repo add minio https://charts.min.io/
helm repo update

# MinIO 설치
helm install minio minio/minio \
  -n monitoring \
  --set rootUser=minioadmin \
  --set rootPassword=minioadmin123 \
  --set persistence.size=10Gi \
  --set mode=standalone \
  --set resources.requests.memory=256Mi

# MinIO Pod 확인
kubectl get pods -n monitoring -l app=minio

# MinIO 서비스 확인
kubectl get svc -n monitoring | grep minio
```

**MinIO 버킷 생성**:
```bash
# MinIO Client 설치 (mc)
# macOS
brew install minio/stable/mc
# Linux
wget https://dl.min.io/client/mc/release/linux-amd64/mc
chmod +x mc && sudo mv mc /usr/local/bin/

# MinIO 포트 포워딩
kubectl port-forward -n monitoring svc/minio 9000:9000 &

# MinIO 설정
mc alias set myminio http://localhost:9000 minioadmin minioadmin123

# thanos 버킷 생성
mc mb myminio/thanos

# 버킷 확인
mc ls myminio
```

**Thanos Object Store 설정 파일**:
```yaml
# thanos-objstore-secret.yaml
cat << 'EOF' > thanos-objstore.yaml
type: S3
config:
  bucket: thanos
  endpoint: minio.monitoring.svc.cluster.local:9000
  access_key: minioadmin
  secret_key: minioadmin123
  insecure: true
EOF

# Secret 생성
kubectl create secret generic thanos-objstore-secret \
  -n monitoring \
  --from-file=objstore.yml=thanos-objstore.yaml

# 확인
kubectl get secret thanos-objstore-secret -n monitoring
```

### 실습 2: Prometheus Thanos Sidecar 활성화 (30분)

kube-prometheus-stack에서 Thanos Sidecar를 활성화합니다.

```yaml
# prometheus-thanos-values.yaml
cat << 'EOF' > prometheus-thanos-values.yaml
prometheus:
  prometheusSpec:
    # Thanos Sidecar 활성화
    thanos:
      create: true
      objectStorageConfig:
        existingSecret:
          name: thanos-objstore-secret
          key: objstore.yml
    
    # 외부 라벨 (멀티 클러스터 구분용)
    externalLabels:
      cluster: toss-cluster-1
      environment: production
    
    # Prometheus 설정
    retention: 2d              # 로컬 retention 단축 (Thanos가 장기 저장)
    retentionSize: 10GB
    
    # Sidecar가 데이터 읽을 수 있도록 설정
    disableCompaction: true    # Thanos Compactor가 대신 수행
    
  # Thanos Sidecar Service (Query가 연결)
  thanosService:
    enabled: true
  
  thanosServiceMonitor:
    enabled: true
EOF

# Prometheus Stack 업그레이드
helm upgrade prometheus prometheus-community/kube-prometheus-stack \
  -n monitoring \
  -f prometheus-thanos-values.yaml

# Sidecar 확인 (Prometheus Pod에 2개 컨테이너)
kubectl get pods -n monitoring -l app.kubernetes.io/name=prometheus
kubectl describe pod prometheus-prometheus-kube-prometheus-prometheus-0 -n monitoring | grep -A 5 "thanos"
```

**Sidecar 동작 확인**:
```bash
# Sidecar 로그 확인
kubectl logs prometheus-prometheus-kube-prometheus-prometheus-0 -n monitoring -c thanos-sidecar --tail=20

# Sidecar가 S3에 데이터 업로드하는지 확인 (2시간 후)
mc ls myminio/thanos
# 블록 디렉토리들이 보여야 함 (예: 01ABCD...)
```

### 실습 3: Thanos 컴포넌트 설치 (45분)

Bitnami Thanos Helm Chart를 사용합니다.

```yaml
# thanos-values.yaml
cat << 'EOF' > thanos-values.yaml
# Object Store 설정
existingObjstoreSecret: thanos-objstore-secret
existingObjstoreSecretItems:
  - key: objstore.yml
    path: objstore.yml

# Query (필수)
query:
  enabled: true
  replicaCount: 1
  
  # Prometheus Sidecar에 연결
  stores:
    # Prometheus Sidecar (실시간 데이터)
    - dnssrv+_grpc._tcp.prometheus-kube-prometheus-thanos-discovery.monitoring.svc.cluster.local
  
  # 쿼리 설정
  extraFlags:
    - --query.auto-downsampling
    - --query.partial-response
  
  resources:
    requests:
      cpu: 100m
      memory: 256Mi
    limits:
      cpu: 500m
      memory: 1Gi

# Store Gateway (필수 - S3 과거 데이터)
storegateway:
  enabled: true
  replicaCount: 1
  
  resources:
    requests:
      cpu: 100m
      memory: 256Mi
    limits:
      cpu: 500m
      memory: 1Gi
  
  persistence:
    enabled: true
    size: 5Gi          # 인덱스 캐시

# Compactor (권장)
compactor:
  enabled: true
  
  # Retention 설정
  retentionResolutionRaw: 30d      # 원본 데이터 30일
  retentionResolution5m: 90d       # 5분 해상도 90일
  retentionResolution1h: 1y        # 1시간 해상도 1년
  
  # 리소스
  resources:
    requests:
      cpu: 100m
      memory: 256Mi
  
  persistence:
    enabled: true
    size: 10Gi

# Query Frontend (선택 - 쿼리 캐싱)
queryFrontend:
  enabled: true
  replicaCount: 1
  
  # 쿼리 분할 (긴 시간 범위 쿼리 최적화)
  extraFlags:
    - --query-range.split-interval=24h
    - --query-range.max-retries-per-request=3

# Ruler는 비활성화 (Prometheus에서 Alert 관리)
ruler:
  enabled: false

# Receiver는 비활성화 (Sidecar 사용)
receive:
  enabled: false
EOF

# Thanos 설치
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update

helm install thanos bitnami/thanos \
  -n monitoring \
  -f thanos-values.yaml

# Pod 확인
kubectl get pods -n monitoring -l app.kubernetes.io/name=thanos
```

**설치 확인**:
```bash
# 모든 Thanos 컴포넌트 상태
kubectl get pods -n monitoring -l app.kubernetes.io/name=thanos

# 예상 출력:
# NAME                                    READY   STATUS    RESTARTS   AGE
# thanos-compactor-xxx                    1/1     Running   0          1m
# thanos-query-xxx                        1/1     Running   0          1m
# thanos-query-frontend-xxx               1/1     Running   0          1m
# thanos-storegateway-0                   1/1     Running   0          1m

# Query 로그 확인 (Store 연결 상태)
kubectl logs -n monitoring -l app.kubernetes.io/component=query --tail=30
```

## 💡 면접 대비 핵심 포인트

### Q1: Thanos의 주요 컴포넌트와 역할을 설명해주세요.

**A**: "Sidecar는 Prometheus 옆에서 데이터를 S3로 업로드하고 실시간 데이터를 제공합니다. Store Gateway는 S3의 과거 데이터를 조회합니다. Query는 Sidecar와 Store Gateway의 데이터를 통합 조회하고 중복을 제거합니다. Compactor는 블록을 합치고 다운샘플링하여 저장 효율을 높입니다."

### Q2: Prometheus만 쓰지 않고 Thanos를 도입한 이유는?

**A**: "Prometheus는 로컬 디스크에만 데이터를 저장하므로 장기 보관에 한계가 있습니다. 토스플레이스처럼 90일 이상 메트릭을 보관해야 할 때 Thanos를 사용하면 S3에 무제한 저장이 가능합니다. 또한 여러 클러스터의 Prometheus 데이터를 하나의 Query로 통합 조회할 수 있어 글로벌 뷰를 제공합니다."

### Q3: Thanos의 다운샘플링은 어떻게 동작하나요?

**A**: "Compactor가 S3의 블록을 주기적으로 처리합니다. 원본(raw) 데이터는 30일간 유지하고, 30일이 지나면 5분 해상도로 다운샘플링하여 90일까지 보관합니다. 90일이 지나면 1시간 해상도로 다시 다운샘플링하여 1년간 보관합니다. 이를 통해 저장 공간을 크게 절약하면서도 장기 트렌드 분석이 가능합니다."
