# 📅 Day 129: Grafana 대시보드 심화 - 변수와 템플릿

## 🎯 오늘의 목표

> **토스플레이스 연결점**: "수백 개 서비스를 하나의 대시보드로 관리"

같은 대시보드를 서비스마다 복사하는 것은 비효율적입니다. **Variables(변수)**를 사용하면 하나의 템플릿으로 모든 서비스를 동적으로 모니터링할 수 있습니다.

## 📚 Part 1: 핵심 개념 (40분)

### Variables란?

```
┌─────────────────────────────────────────────────────────────┐
│  Variables = 대시보드의 동적 필터                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  대시보드 상단 드롭다운:                                     │
│  ┌──────────────────────────────────────────────┐          │
│  │ namespace: [ default ▼]  pod: [ api-xxx ▼]  │          │
│  └──────────────────────────────────────────────┘          │
│                                                             │
│  쿼리에서 변수 사용:                                         │
│  rate(http_requests_total{namespace="$namespace"}[5m])     │
│                                                             │
│  장점:                                                       │
│  - 하나의 대시보드로 모든 서비스 모니터링                    │
│  - 드롭다운으로 쉽게 전환                                    │
│  - URL 파라미터로 직접 접근 가능                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 변수 종류

| 타입 | 설명 | 사용 케이스 |
|------|------|------------|
| **Query** | 데이터 소스에서 값 조회 | namespace, pod, service 목록 |
| **Custom** | 직접 값 정의 | 환경 (dev, staging, prod) |
| **Constant** | 고정 값 | 클러스터 이름 |
| **Data source** | 데이터 소스 선택 | 멀티 클러스터 |
| **Interval** | 시간 간격 | $__interval, $__rate_interval |
| **Text box** | 사용자 입력 | 검색어, 필터 |

### Query 변수 문법

```
┌─────────────────────────────────────────────────────────────┐
│  label_values() - 레이블 값 목록 조회                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  # 모든 namespace                                           │
│  label_values(namespace)                                    │
│                                                             │
│  # 특정 메트릭의 namespace                                   │
│  label_values(kube_pod_info, namespace)                     │
│                                                             │
│  # 필터링된 값 (특정 namespace의 pod)                        │
│  label_values(kube_pod_info{namespace="$namespace"}, pod)  │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│  query_result() - 쿼리 결과를 값으로                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  # 메모리 사용량 TOP 10 Pod                                  │
│  query_result(topk(10, sum(container_memory_usage_bytes)    │
│    by (pod)))                                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 변수 연쇄 (Chaining)

```
┌─────────────────────────────────────────────────────────────┐
│  변수 간 의존 관계 설정                                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1단계 변수 - cluster:                                       │
│  label_values(kube_pod_info, cluster)                       │
│                                                             │
│  2단계 변수 - namespace (cluster에 의존):                    │
│  label_values(kube_pod_info{cluster="$cluster"}, namespace) │
│                                                             │
│  3단계 변수 - pod (namespace에 의존):                        │
│  label_values(kube_pod_info{cluster="$cluster",             │
│    namespace="$namespace"}, pod)                            │
│                                                             │
│  결과:                                                       │
│  cluster 선택 → namespace 목록 자동 업데이트                 │
│  namespace 선택 → pod 목록 자동 업데이트                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 변수 옵션

| 옵션 | 설명 |
|------|------|
| **Multi-value** | 여러 값 동시 선택 |
| **Include All option** | "All" 옵션 추가 |
| **Custom all value** | All 선택 시 사용할 값 (.+ 정규식) |
| **Regex** | 값 필터링 정규식 |
| **Sort** | 값 정렬 방식 |
| **Refresh** | 값 갱신 시점 |

### 실습 1: Query 변수 생성 (25분)

**목표**: Namespace와 Pod 선택 변수 만들기

```
1. 대시보드 → 우상단 ⚙️ (Settings) → Variables
2. "Add variable" 클릭
```

**변수 1: namespace**

```
설정:
- Name: namespace
- Type: Query
- Data source: Prometheus
- Query: label_values(kube_pod_info, namespace)
- Regex: (필요시 필터링)
- Sort: Alphabetical (asc)
- Multi-value: ✓ 체크
- Include All option: ✓ 체크
- Custom all value: .+
- Refresh: On dashboard load

Preview 확인 후 "Apply" 클릭
```

**변수 2: pod (namespace에 의존)**

```
설정:
- Name: pod
- Type: Query
- Data source: Prometheus
- Query: label_values(kube_pod_info{namespace=~"$namespace"}, pod)
- Sort: Alphabetical (asc)
- Multi-value: ✓ 체크
- Include All option: ✓ 체크
- Custom all value: .+
- Refresh: On time range change

"Apply" 클릭
```

**테스트**:
```
1. 대시보드로 돌아가기
2. 상단에 namespace, pod 드롭다운 확인
3. namespace 선택 시 pod 목록이 변경되는지 확인
```

### 실습 2: 변수를 사용하는 패널 생성 (25분)

**목표**: 변수를 활용한 동적 패널 만들기

**패널 1: 선택된 Pod의 CPU 사용량**

```promql
# Query
sum(rate(container_cpu_usage_seconds_total{
  namespace=~"$namespace",
  pod=~"$pod",
  container!=""
}[5m])) by (pod)

# Legend
{{ pod }}
```

**패널 2: 선택된 Pod의 메모리 사용량**

```promql
# Query
sum(container_memory_usage_bytes{
  namespace=~"$namespace",
  pod=~"$pod",
  container!=""
}) by (pod)

# Settings
- Unit: bytes (IEC)
- Legend: {{ pod }}
```

**패널 3: 선택된 네임스페이스의 총 리소스**

```promql
# CPU Total
sum(rate(container_cpu_usage_seconds_total{
  namespace=~"$namespace",
  container!=""
}[5m]))

# Memory Total
sum(container_memory_usage_bytes{
  namespace=~"$namespace",
  container!=""
})
```

### 실습 3: Interval 변수 사용 (15분)

**목표**: 동적 시간 간격 설정

**변수 생성**:
```
- Name: interval
- Type: Interval
- Values: 1m,5m,10m,30m,1h
- Auto option: ✓ 체크
```

**쿼리에서 사용**:
```promql
# 기존
rate(http_requests_total[5m])

# 변수 사용
rate(http_requests_total[$interval])

# 또는 자동 간격 (권장)
rate(http_requests_total[$__rate_interval])
```

**$__rate_interval vs $__interval**:
```
$__interval: 화면 해상도 기반 자동 계산
$__rate_interval: rate() 함수에 최적화된 간격 (scrape_interval * 4)

→ rate(), irate()에는 $__rate_interval 사용 권장
```

### 실습 5: 대시보드 as Code (JSON) (20분)

**목표**: 대시보드를 코드로 관리

**JSON 내보내기**:
```
1. 대시보드 → Share (공유) → Export
2. "Export for sharing externally" 체크
3. "Save to file" 클릭
```

**JSON 구조**:
```json
{
  "dashboard": {
    "title": "My Service Dashboard",
    "uid": "abc123",
    "tags": ["kubernetes", "service"],
    "timezone": "browser",
    "templating": {
      "list": [
        {
          "name": "namespace",
          "type": "query",
          "query": "label_values(kube_pod_info, namespace)",
          "multi": true,
          "includeAll": true
        }
      ]
    },
    "panels": [
      {
        "title": "CPU Usage",
        "type": "timeseries",
        "gridPos": {"x": 0, "y": 0, "w": 12, "h": 8},
        "targets": [
          {
            "expr": "sum(rate(container_cpu_usage_seconds_total{namespace=~\"$namespace\"}[5m])) by (pod)",
            "legendFormat": "{{ pod }}"
          }
        ]
      }
    ]
  }
}
```

**ConfigMap으로 대시보드 배포**:
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-dashboard
  namespace: monitoring
  labels:
    grafana_dashboard: "1"    # Grafana가 이 label로 찾음
data:
  my-dashboard.json: |
    {
      "title": "My Service Dashboard",
      "panels": [...],
      "templating": {...}
    }
```

```bash
# 적용
kubectl apply -f my-dashboard-configmap.yaml

# Grafana가 자동으로 로드 (몇 분 소요)
# 또는 Grafana Pod 재시작
kubectl rollout restart deployment -n monitoring prometheus-grafana
```

## 📊 Part 3: 모범 사례

### 변수 네이밍 컨벤션

```
# 권장
$namespace       # 단수형
$pod             # 단수형
$cluster         # 단수형

# 비권장
$namespaces      # 복수형 (혼란)
$ns              # 약어 (불명확)
```

### 대시보드 설계 원칙

```
┌─────────────────────────────────────────────────────────────┐
│  좋은 대시보드의 특징                                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 목적이 명확                                              │
│     - 서비스 개요 / 상세 분석 / 알림 현황                   │
│                                                             │
│  2. 계층적 구조                                              │
│     - 상단: 전체 요약 (Stat 패널)                           │
│     - 중단: 주요 메트릭 (Time series)                       │
│     - 하단: 상세 정보 (Table)                               │
│                                                             │
│  3. 일관된 색상                                              │
│     - 녹색: 정상                                             │
│     - 노랑: 경고                                             │
│     - 빨강: 위험                                             │
│                                                             │
│  4. 적절한 변수                                              │
│     - 너무 많으면 복잡, 너무 적으면 유연성 부족              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 🔑 오늘 배운 핵심 문법

```
# 반드시 외울 것!

# 변수 쿼리
label_values(metric, label)
label_values(metric{filter="value"}, label)

# 쿼리에서 변수 사용
{namespace=~"$namespace"}     # 단일/다중 값
{namespace=~"$namespace"}     # Multi-value + All

# 내장 변수
$__interval          # 자동 시간 간격
$__rate_interval     # rate()용 최적 간격
$__range             # 현재 시간 범위
$__from, $__to       # 시간 범위 (ms)
```
