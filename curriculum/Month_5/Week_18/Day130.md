### Grafana Alerting vs Prometheus Alerting

```
┌─────────────────────────────────────────────────────────────┐
│  언제 어떤 것을 사용할까?                                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Prometheus Alerting (Alertmanager):                        │
│  ✅ Prometheus 메트릭 전용                                   │
│  ✅ 고성능, 대규모 환경에 적합                               │
│  ✅ PrometheusRule CRD로 GitOps 관리                        │
│  ✅ 복잡한 라우팅, 억제 규칙                                 │
│  → 메트릭 알림의 표준                                        │
│                                                             │
│  Grafana Alerting:                                          │
│  ✅ 다양한 데이터 소스 지원 (Loki, ES, CloudWatch)          │
│  ✅ UI로 쉬운 알림 생성                                      │
│  ✅ 대시보드 패널과 연동                                     │
│  ✅ 알림 이력 관리                                          │
│  → 통합 알림, 빠른 설정                                     │
│                                                             │
│  권장:                                                       │
│  - 메트릭 → Prometheus Alerting                             │
│  - 로그 → Grafana Alerting (Loki)                          │
│  - 복합 조건 → Grafana Alerting                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 핵심 구성 요소

| 구성 요소 | 설명 |
|----------|------|
| **Alert Rule** | 알림 조건 정의 (쿼리 + 조건 + 레이블) |
| **Contact Point** | 알림 수신 채널 (Slack, Email, PagerDuty) |
| **Notification Policy** | 알림 라우팅 규칙 |
| **Silence** | 일시적 알림 무시 |
| **Alert Group** | 알림 그룹화 |

### Alert Rule 구조

```yaml
# Grafana Alert Rule 구성 요소

1. Query (쿼리)
   - 데이터 소스에서 데이터 조회
   - A, B, C 등 여러 쿼리 가능

2. Expression (표현식)
   - Reduce: 시계열을 단일 값으로 (Last, Mean, Min, Max)
   - Threshold: 조건 비교 (IS ABOVE, IS BELOW)
   - Math: 쿼리 간 수식 ($A / $B)
   - Classic condition: 레거시 방식

3. Evaluation (평가)
   - Folder: 알림 저장 폴더
   - Evaluation group: 평가 그룹
   - Pending period: 대기 시간 (for 절과 동일)

4. Labels & Annotations
   - Labels: 라우팅에 사용
   - Annotations: 알림 메시지에 포함
```

### 실습 1: Contact Point 생성 (20분)

**목표**: Slack 알림 채널 설정

```
좌측 메뉴 → Alerting → Contact points → Add contact point
```

**Slack Contact Point**:

```
설정:
- Name: slack-alerts
- Integration: Slack

Slack 설정:
- Recipient: #alerts (채널명)
- Webhook URL: https://hooks.slack.com/services/xxx/xxx/xxx
  (Slack App → Incoming Webhooks에서 생성)

Optional settings:
- Username: Grafana Alert
- Icon emoji: :grafana:
- Mention Users: @oncall
- Mention Groups: @platform-team

"Test" 버튼으로 테스트 후 "Save contact point"
```

**Email Contact Point** (추가):

```
설정:
- Name: email-alerts
- Integration: Email

Email 설정:
- Addresses: team@company.com, oncall@company.com
- Single email: ✓ (여러 알림을 하나의 이메일로)

"Save contact point"
```

### 실습 2: 첫 번째 Alert Rule 생성 (30분)

**목표**: CPU 사용률 알림 규칙 생성

```
좌측 메뉴 → Alerting → Alert rules → New alert rule
```

**Step 1: Query 설정**

```
Rule name: High CPU Usage

Query A:
Data source: Prometheus
Query:
  100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

Options:
- Legend: {{ instance }}
- Min step: 1m
```

**Step 2: Expression 설정**

```
Expression B (Reduce):
- Function: Last
- Input: A
- Mode: Strict

Expression C (Threshold):
- Input: B
- IS ABOVE: 80
```

**Step 3: Evaluation 설정**

```
Folder: Alerts (새로 생성 또는 선택)
Evaluation group: node-alerts (새로 생성)

Evaluation interval: 1m
Pending period: 5m  (5분 동안 지속 시 알림)
```

**Step 4: Labels & Annotations**

```
Labels:
- severity: warning
- team: platform

Annotations:
- Summary: High CPU usage on {{ $labels.instance }}
- Description: CPU usage is {{ $values.B }}% on node {{ $labels.instance }}
- Runbook URL: https://wiki.company.com/runbook/high-cpu
```

**"Save rule and exit"**

### 실습 3: 에러율 Alert Rule (25분)

**목표**: HTTP 에러율 알림

```
Rule name: High Error Rate

Query A (총 요청):
sum(rate(http_requests_total[5m])) by (job)

Query B (에러 요청):
sum(rate(http_requests_total{status=~"5.."}[5m])) by (job)

Expression C (Math):
Input: $B / $A

Expression D (Threshold):
Input: C
IS ABOVE: 0.05

Labels:
- severity: critical
- team: platform

Annotations:
- Summary: High error rate on {{ $labels.job }}
- Description: Error rate is {{ printf "%.2f" $values.C }}% (threshold: 5%)
```

### 실습 4: Notification Policy 설정 (20분)

**목표**: 라벨 기반 알림 라우팅

```
좌측 메뉴 → Alerting → Notification policies
```

**Root Policy (기본)**:

```
Default contact point: slack-alerts
Group by: alertname, namespace
Group wait: 30s
Group interval: 5m
Repeat interval: 4h
```

**중첩 Policy 추가** (critical 알림):

```
"+ New nested policy" 클릭

Matching labels:
- severity = critical

Contact point: pagerduty-oncall (또는 slack-critical)
Group wait: 10s
Repeat interval: 1h

Continue matching subsequent sibling nodes: ✓ (이메일도 보내려면)
```

**중첩 Policy 추가** (팀별):

```
Matching labels:
- team = payment

Contact point: slack-payment-team
Override grouping: ✓
Group by: alertname, service
```

### 실습 5: Alert Rule 테스트 (15분)

**목표**: 알림 발생 및 해소 테스트

**방법 1: 항상 발생하는 조건**

```
임시 Alert Rule 생성:

Query:
vector(1)

Expression (Threshold):
IS ABOVE: 0

Pending period: 0s

→ 즉시 Firing 상태로 전환
→ 알림 수신 확인 후 삭제
```

**방법 2: UI에서 상태 확인**

```
좌측 메뉴 → Alerting → Alert rules

상태:
- Normal: 정상 (녹색)
- Pending: 조건 충족, 대기 중 (노랑)
- Firing: 알림 발송 중 (빨강)
- No Data: 데이터 없음
- Error: 쿼리 에러
```

**Silences 테스트**:

```
1. Alerting → Silences → Add silence
2. Matchers: alertname = High CPU Usage
3. Duration: 2 hours
4. Comment: Testing silence feature
5. Create
```

## 📊 Part 3: Prometheus vs Grafana Alerting

### 비교 요약

| 항목 | Prometheus Alerting | Grafana Alerting |
|------|-------------------|------------------|
| 데이터 소스 | Prometheus만 | 모든 데이터 소스 |
| 설정 방식 | YAML (PrometheusRule) | UI 또는 JSON |
| 고가용성 | Alertmanager 클러스터 | Grafana HA (Enterprise) |
| 알림 이력 | 별도 저장 필요 | 내장 |
| 복잡한 라우팅 | 강력 (Alertmanager) | 기본적 |
| GitOps | CRD로 관리 | JSON/Terraform |

### 권장 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│  하이브리드 알림 구조                                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Prometheus 메트릭                                          │
│       ↓                                                     │
│  Prometheus Alerting Rules                                  │
│       ↓                                                     │
│  Alertmanager ──────────────────→ Slack, PagerDuty         │
│                                                             │
│  Loki 로그                                                  │
│       ↓                                                     │
│  Grafana Alerting ──────────────→ Slack, PagerDuty         │
│                                                             │
│  CloudWatch, Datadog 등                                     │
│       ↓                                                     │
│  Grafana Alerting ──────────────→ 동일 채널로 통합          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
