# 📅 Day 131: Thanos 소개 - Prometheus의 확장

## 🎯 오늘의 목표

> **토스플레이스 최우선 요건**: "Prometheus, **Thanos**, Grafana를 이용한 모니터링"

Prometheus는 훌륭한 모니터링 도구지만, **대규모 환경**에서는 한계가 있습니다. Thanos는 이러한 한계를 해결하여 **장기 저장**, **고가용성**, **멀티 클러스터 쿼리**를 가능하게 합니다.

## 📚 Part 1: 핵심 개념 (50분)

### Prometheus의 한계

```
┌─────────────────────────────────────────────────────────────┐
│  단일 Prometheus의 문제점                                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 저장 공간 제한                                           │
│     - 로컬 디스크에 저장                                     │
│     - 보통 15일 ~ 30일 보관                                  │
│     - "3개월 전 데이터 필요해요" → 없음                      │
│                                                             │
│  2. 단일 장애점 (SPOF)                                       │
│     - Prometheus 다운 = 모니터링 불가                        │
│     - 데이터 손실 위험                                       │
│                                                             │
│  3. 수평 확장 불가                                           │
│     - 메트릭이 많아지면 한계                                 │
│     - 단일 서버의 메모리/CPU 제한                            │
│                                                             │
│  4. 멀티 클러스터 통합 어려움                                │
│     - 클러스터별 별도 Prometheus                             │
│     - 통합 대시보드 구성 복잡                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Thanos가 해결하는 문제

| Prometheus 한계 | Thanos 해결책 |
|----------------|--------------|
| 저장 공간 제한 | Object Storage (S3, GCS)로 무제한 저장 |
| 단일 장애점 | 여러 Prometheus + Sidecar로 HA |
| 수평 확장 불가 | Query로 분산 Prometheus 통합 쿼리 |
| 멀티 클러스터 | Global View (Store Gateway) |
| 장기 데이터 쿼리 느림 | Compactor로 다운샘플링 |

### Thanos 컴포넌트 상세

#### 1. Sidecar

```
┌─────────────────────────────────────────────────────────────┐
│  Thanos Sidecar                                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  역할:                                                       │
│  - Prometheus Pod에 함께 배포                                │
│  - 실시간 데이터를 Query에 제공                              │
│  - 완성된 블록을 Object Storage에 업로드                     │
│                                                             │
│  배포 형태:                                                  │
│  ┌─────────────────────────────────────┐                    │
│  │  Pod                                │                    │
│  │  ┌─────────────┐ ┌───────────────┐ │                    │
│  │  │ Prometheus  │ │ Thanos        │ │                    │
│  │  │ Container   │ │ Sidecar       │ │                    │
│  │  │             │ │               │ │                    │
│  │  │  /data ─────┼─┼→ 블록 읽기     │ │                    │
│  │  └─────────────┘ └───────┬───────┘ │                    │
│  └──────────────────────────┼─────────┘                    │
│                             │                               │
│                             ▼                               │
│                    Object Storage                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 2. Store Gateway

```
┌─────────────────────────────────────────────────────────────┐
│  Thanos Store Gateway                                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  역할:                                                       │
│  - Object Storage의 과거 데이터를 Query에 제공               │
│  - 인덱스 캐싱으로 빠른 조회                                 │
│  - 장기 데이터 접근의 핵심                                   │
│                                                             │
│  동작:                                                       │
│  1. Object Storage에서 블록 메타데이터 동기화               │
│  2. Query 요청 시 필요한 블록 로드                          │
│  3. 결과 반환                                                │
│                                                             │
│  주의:                                                       │
│  - 메모리 사용량 높음 (인덱스 캐싱)                          │
│  - 디스크 캐시 설정 권장                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 실습 2: Deduplication 이해 (20분)

**문제 상황**:
```
HA 구성 시 2개의 Prometheus가 동일 타겟을 스크랩
→ 같은 메트릭이 중복 저장됨
→ 쿼리 결과가 2배로 나옴?
```

**Thanos 해결책 - Deduplication**:
```yaml
# 각 Prometheus에 external_labels 설정
# prometheus-a.yaml
global:
  external_labels:
    cluster: prod
    replica: prometheus-a    # ← replica 레이블

# prometheus-b.yaml
global:
  external_labels:
    cluster: prod
    replica: prometheus-b    # ← replica 레이블

# Thanos Query가 replica 레이블로 중복 제거
# 동일 시리즈 중 하나만 선택
```

### 실습 3: 보관 정책 설계 (20분)

**일반적인 보관 정책**:

```yaml
# compactor 설정
retention:
  # Raw 데이터 (원본 해상도)
  resolution_raw: 30d       # 30일 보관
  
  # 5분 해상도 다운샘플링
  resolution_5m: 90d        # 90일 보관
  
  # 1시간 해상도 다운샘플링
  resolution_1h: 365d       # 1년 보관
```

**저장 공간 예측**:

```
┌─────────────────────────────────────────────────────────────┐
│  저장 공간 계산 예시                                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  메트릭 수: 100,000개                                        │
│  스크랩 간격: 30초                                           │
│  포인트당 크기: ~2 bytes (압축 후)                           │
│                                                             │
│  Raw 30일:                                                   │
│  100,000 × (30일 × 24시간 × 120포인트) × 2 bytes            │
│  = 약 17 GB                                                  │
│                                                             │
│  5분 해상도 90일:                                            │
│  100,000 × (90일 × 24시간 × 12포인트) × 2 bytes             │
│  = 약 5 GB                                                   │
│                                                             │
│  1시간 해상도 365일:                                         │
│  100,000 × (365일 × 24포인트) × 2 bytes                     │
│  = 약 1.7 GB                                                 │
│                                                             │
│  총: 약 24 GB (1년 보관)                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 📊 Part 3: 핵심 정리

### Thanos 도입 체크리스트

| 요구사항 | Thanos 필요? |
|---------|-------------|
| 30일 이상 데이터 보관 | ✅ 필요 |
| 멀티 클러스터 통합 쿼리 | ✅ 필요 |
| Prometheus HA 구성 | ✅ 필요 |
| 단일 클러스터, 15일 보관 | ❌ 불필요 |

### 필수 컴포넌트 vs 선택 컴포넌트

| 컴포넌트 | 필수 | 용도 |
|---------|------|------|
| Sidecar | ✅ | 실시간 데이터, 블록 업로드 |
| Query | ✅ | 통합 쿼리 |
| Store Gateway | ✅ | 장기 데이터 조회 |
| Compactor | ✅ | 압축, 다운샘플링 |
| Ruler | ❌ | 글로벌 규칙 (선택) |
| Query Frontend | ❌ | 캐싱, 분할 (선택) |
