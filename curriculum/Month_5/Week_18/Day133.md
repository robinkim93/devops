## 📚 Part 1: 핵심 개념 (30분)

### Thanos Query의 역할

```
┌─────────────────────────────────────────────────────────────┐
│  Thanos Query = 글로벌 쿼리 엔진                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 여러 Store에서 데이터 수집                               │
│     - Sidecar (최근 데이터)                                 │
│     - Store Gateway (과거 데이터)                           │
│     - 다른 클러스터의 Sidecar                               │
│                                                             │
│  2. PromQL 처리                                              │
│     - 표준 Prometheus API 호환                              │
│     - Grafana에서 직접 사용 가능                            │
│                                                             │
│  3. 중복 제거 (Deduplication)                               │
│     - HA Prometheus의 중복 데이터 제거                       │
│     - replica 레이블 기반                                   │
│                                                             │
│  4. 부분 응답 (Partial Response)                             │
│     - 일부 Store 실패 시 나머지 결과 반환                    │
│     - 가용성 우선 설정 가능                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 쿼리 처리 흐름

```
┌─────────────────────────────────────────────────────────────────────────┐
│  "지난 7일간 클러스터별 CPU 사용률" 쿼리                                 │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  Grafana 쿼리:                                                          │
│  sum(rate(node_cpu_seconds_total{mode!="idle"}[5m])) by (cluster)      │
│                                                                         │
│  시간 범위: last 7 days                                                 │
│                                                                         │
│               ┌─────────────────────────────────────────┐               │
│               │           Thanos Query                   │               │
│               │  1. 시간 범위 분석                        │               │
│               │  2. Store 선택                           │               │
│               │  3. 병렬 요청                            │               │
│               └────────────────┬────────────────────────┘               │
│                                │                                        │
│           ┌────────────────────┼────────────────────┐                  │
│           │                    │                    │                  │
│           ▼                    ▼                    ▼                  │
│   ┌───────────────┐   ┌───────────────┐   ┌───────────────┐           │
│   │   Sidecar A   │   │   Sidecar B   │   │ Store Gateway │           │
│   │  (최근 2시간)  │   │  (최근 2시간)  │   │ (과거 7일)    │           │
│   │  cluster=a    │   │  cluster=b    │   │ cluster=a,b   │           │
│   └───────┬───────┘   └───────┬───────┘   └───────┬───────┘           │
│           │                   │                   │                    │
│           └───────────────────┼───────────────────┘                    │
│                               ▼                                        │
│                    ┌─────────────────────┐                             │
│                    │  결과 병합 & 중복제거 │                             │
│                    │  (by cluster 집계)   │                             │
│                    └─────────────────────┘                             │
│                               │                                        │
│                               ▼                                        │
│                    ┌─────────────────────┐                             │
│                    │   최종 결과 반환     │                             │
│                    │  cluster=a: 45%     │                             │
│                    │  cluster=b: 62%     │                             │
│                    └─────────────────────┘                             │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Query 옵션

| 옵션 | 설명 | 기본값 |
|------|------|--------|
| `--query.replica-label` | 중복 제거에 사용할 레이블 | - |
| `--query.partial-response` | 부분 응답 허용 | false |
| `--query.auto-downsampling` | 자동 다운샘플링 | true |
| `--query.max-concurrent` | 최대 동시 쿼리 수 | 20 |
| `--store` | Store 주소 (여러 개 지정) | - |

### 실습 2: 기본 쿼리 테스트 (20분)

**목표**: Thanos Query에서 PromQL 실행

```promql
# 1. 현재 데이터 확인 (Sidecar에서)
up

# 2. external_labels 확인
up{cluster="my-cluster"}

# 3. 메트릭 존재 확인
count(node_cpu_seconds_total)

# 4. CPU 사용률
100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
```

**Deduplication 테스트**:
```promql
# Deduplication OFF
up
# → HA 구성 시 replica=a, replica=b 두 개 결과

# Deduplication ON (체크박스 활성화)
up
# → 중복 제거되어 하나의 결과
```

### 실습 3: Grafana에 Thanos 연결 (30분)

**목표**: Grafana에서 Thanos Query를 Data Source로 사용

```bash
# Grafana 접속
kubectl port-forward -n monitoring svc/prometheus-grafana 3000:80 &
# http://localhost:3000
```

**Data Source 추가**:
```
1. Configuration → Data Sources → Add data source
2. Prometheus 선택

설정:
- Name: Thanos
- URL: http://thanos-query.monitoring.svc:10902
- Access: Server (default)

Custom HTTP Headers (선택):
- Header: X-Thanos-Query-Deduplicate
- Value: true

"Save & test" 클릭
```

**기존 대시보드에서 Data Source 변경**:
```
1. 대시보드 열기
2. 패널 Edit
3. Data source 드롭다운에서 "Thanos" 선택
4. 쿼리 실행 확인
```

### 실습 4: 장기 데이터 쿼리 (30분)

**목표**: Object Storage에 저장된 과거 데이터 조회

```promql
# 1. 지난 24시간 평균 CPU
avg_over_time(
  (100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100))
  [24h]
)

# 2. 지난 7일간 일별 요청 수 (Recording Rule이 있다면)
sum(increase(http_requests_total[1d]))

# 3. 지난 30일간 데이터 범위 확인
# (Store Gateway에서 가져온 데이터)
min_over_time(up[30d])
max_over_time(up[30d])
```

**시간 범위별 데이터 소스 확인**:
```
Thanos Query UI에서:
1. 쿼리 실행
2. "Enable query analysis" 옵션 활성화 (있는 경우)
3. 또는 로그에서 확인:

kubectl logs -n monitoring deploy/thanos-query | grep "querying"
```

**다운샘플링 테스트**:
```promql
# Max source resolution 변경하여 비교

# Raw (원본 해상도)
rate(http_requests_total[5m])
# → 모든 포인트 표시

# 5m 해상도
rate(http_requests_total[5m])
# → 5분 단위로 다운샘플링된 데이터

# 1h 해상도 (장기 쿼리 시 자동)
rate(http_requests_total[5m])
# → 1시간 단위 다운샘플링
```

### 실습 5: 글로벌 뷰 쿼리 (20분)

**목표**: 여러 클러스터 데이터 통합 쿼리

```promql
# 클러스터별 CPU 사용률
sum(rate(node_cpu_seconds_total{mode!="idle"}[5m])) by (cluster)
/
sum(rate(node_cpu_seconds_total[5m])) by (cluster)
* 100

# 클러스터별 Pod 수
count(kube_pod_info) by (cluster)

# 전체 클러스터 메모리 총합
sum(node_memory_MemTotal_bytes)

# 클러스터 간 비교 (있는 경우)
avg(rate(http_requests_total[5m])) by (cluster)
```

**레이블로 필터링**:
```promql
# 특정 클러스터만
up{cluster="prod-a"}

# 프로덕션 환경만
up{env="production"}

# 여러 클러스터
up{cluster=~"prod-a|prod-b"}
```

### 실습 6: 쿼리 성능 최적화 (20분)

**목표**: 효율적인 Thanos 쿼리 작성

**느린 쿼리 패턴과 개선**:

```promql
# ❌ 느림: 긴 범위에서 고해상도 데이터
rate(http_requests_total[5m])
# 시간 범위: 30 days
# → 수백만 포인트 처리

# ✅ 개선: 장기 범위에서는 다운샘플링 사용
# Thanos UI에서 Max resolution: 1h 선택
# 또는 Recording Rule 사전 계산 활용
```

```promql
# ❌ 느림: 레이블 없이 모든 시계열
sum(rate(container_cpu_usage_seconds_total[5m]))

# ✅ 개선: 필터 추가
sum(rate(container_cpu_usage_seconds_total{container!=""}[5m])) by (namespace)
```

**부분 응답 활용**:
```
특정 Store가 느리거나 실패할 때:

1. "Enable partial response" 체크
2. 응답 가능한 Store의 데이터만 반환
3. 가용성 > 정확성 상황에서 유용
```
