# 📅 Day 126: Alertmanager 설정과 알림 라우팅

## 🎯 오늘의 목표

> **토스플레이스 연결점**: "장애 알림을 적절한 담당자에게 전달하는 시스템 구축"

Prometheus가 알림을 **발생**시키면, Alertmanager가 이를 **전달**합니다. 올바른 Alertmanager 설정은 **알림 피로를 줄이고**, **적절한 담당자에게**, **적시에** 알림을 전달하는 핵심입니다.

## 📚 Part 1: 핵심 개념 (40분)

### Alertmanager의 역할

```
┌─────────────────────────────────────────────────────────────┐
│  Alertmanager가 하는 일                                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 그룹화 (Grouping)                                       │
│     - 비슷한 알림을 묶어서 한 번에 전송                       │
│     - 예: 10개 Pod 다운 → 1개 알림 (10 pods affected)       │
│                                                             │
│  2. 억제 (Inhibition)                                       │
│     - 상위 알림이 있으면 하위 알림 억제                       │
│     - 예: 클러스터 다운 → 개별 Pod 알림 억제                 │
│                                                             │
│  3. 음소거 (Silencing)                                      │
│     - 특정 시간 동안 알림 무시                               │
│     - 예: 유지보수 중 알림 끄기                              │
│                                                             │
│  4. 라우팅 (Routing)                                        │
│     - 알림을 적절한 채널로 전달                              │
│     - 예: critical → PagerDuty, warning → Slack            │
│                                                             │
│  5. 중복 제거 (Deduplication)                               │
│     - 같은 알림 반복 전송 방지                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Alertmanager 아키텍처

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     Alertmanager Architecture                           │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   Prometheus                                                            │
│       │                                                                 │
│       │ POST /api/v1/alerts                                             │
│       ▼                                                                 │
│   ┌───────────────────────────────────────────────────────────┐        │
│   │                    Alertmanager                            │        │
│   │                                                            │        │
│   │  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐       │        │
│   │  │  Dispatcher │→ │  Inhibitor  │→ │  Silencer   │       │        │
│   │  │  (라우팅)    │  │  (억제)     │  │  (음소거)   │       │        │
│   │  └─────────────┘  └─────────────┘  └─────────────┘       │        │
│   │         │                                                  │        │
│   │         ▼                                                  │        │
│   │  ┌─────────────────────────────────────────────────┐     │        │
│   │  │               Notification Pipeline             │     │        │
│   │  │  ┌─────────┐ ┌─────────┐ ┌─────────┐          │     │        │
│   │  │  │ Grouping│ │  Wait   │ │ Dedup   │          │     │        │
│   │  │  └─────────┘ └─────────┘ └─────────┘          │     │        │
│   │  └─────────────────────────────────────────────────┘     │        │
│   └────────────────────────┬───────────────────────────────────┘        │
│                            │                                            │
│              ┌─────────────┼─────────────┐                             │
│              ▼             ▼             ▼                              │
│         ┌────────┐   ┌────────┐   ┌──────────┐                         │
│         │  Slack │   │ Email  │   │PagerDuty │                         │
│         └────────┘   └────────┘   └──────────┘                         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 설정 파일 구조

```yaml
# alertmanager.yaml 전체 구조

global:                    # 전역 설정
  resolve_timeout: 5m      # 알림 해제 판단 시간
  smtp_smarthost: '...'    # 이메일 서버
  slack_api_url: '...'     # Slack Webhook URL

route:                     # 라우팅 규칙
  receiver: 'default'      # 기본 수신자
  group_by: ['alertname']  # 그룹화 기준
  group_wait: 30s          # 그룹 대기 시간
  group_interval: 5m       # 그룹 재전송 간격
  repeat_interval: 4h      # 반복 전송 간격
  routes:                  # 하위 라우팅 규칙
    - match:
        severity: critical
      receiver: 'pagerduty'

receivers:                 # 수신자 목록
  - name: 'default'
    slack_configs: [...]
  - name: 'pagerduty'
    pagerduty_configs: [...]

inhibit_rules:            # 억제 규칙
  - source_match:
      severity: 'critical'
    target_match:
      severity: 'warning'
    equal: ['alertname']
```

### 라우팅 매칭 규칙

```
┌─────────────────────────────────────────────────────────────┐
│  Route 매칭 순서                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  route:                                                     │
│    receiver: default          # ← 매칭 안 되면 여기로       │
│    routes:                                                  │
│      - match:                                               │
│          severity: critical   # ← 1번 체크                  │
│        receiver: pagerduty                                  │
│      - match:                                               │
│          team: platform       # ← 2번 체크                  │
│        receiver: platform-slack                             │
│      - match_re:                                            │
│          service: "api-.*"    # ← 3번 체크 (정규식)         │
│        receiver: api-team                                   │
│                                                             │
│  규칙:                                                       │
│  - 위에서 아래로 순차 매칭                                   │
│  - 첫 번째 매칭에서 멈춤 (continue: true면 계속)            │
│  - 매칭 없으면 부모의 receiver로                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 그룹화 타이밍

| 설정 | 설명 | 권장값 |
|------|------|--------|
| `group_wait` | 첫 알림 후 그룹 대기 | 30s |
| `group_interval` | 같은 그룹 새 알림 대기 | 5m |
| `repeat_interval` | 동일 알림 반복 주기 | 4h |

```
시간 →  0     30s    5m     9m     4h
        │      │      │      │      │
        ▼      ▼      ▼      ▼      ▼
알림A ──●──────┬──────────────────────────
알림B ─────●───┤ (30s 내 도착)
알림C ─────────┼───●─── (5m 내 도착)
              │      │
              └──────┴─── 모아서 한 번에 발송
                          │
                          4h 후 다시 발송 (지속 시)
```

### 실습 2: Slack 알림 설정 (30분)

**목표**: Slack으로 알림 전송 설정

```bash
# 1. Slack Webhook URL 준비
# Slack App 생성 → Incoming Webhooks 활성화 → URL 복사

# 2. Secret으로 Alertmanager 설정 생성
cat << 'EOF' > alertmanager-config.yaml
apiVersion: v1
kind: Secret
metadata:
  name: alertmanager-prometheus-kube-prometheus-alertmanager
  namespace: monitoring
stringData:
  alertmanager.yaml: |
    global:
      resolve_timeout: 5m
      slack_api_url: 'https://hooks.slack.com/services/YOUR/WEBHOOK/URL'
    
    route:
      receiver: 'slack-default'
      group_by: ['alertname', 'severity', 'namespace']
      group_wait: 30s
      group_interval: 5m
      repeat_interval: 4h
      routes:
        # Critical 알림 → 즉시 전송
        - match:
            severity: critical
          receiver: 'slack-critical'
          group_wait: 10s
          repeat_interval: 1h
        
        # Warning 알림 → 일반 채널
        - match:
            severity: warning
          receiver: 'slack-warning'
        
        # Info 알림 → 정보 채널 (느슨하게)
        - match:
            severity: info
          receiver: 'slack-info'
          repeat_interval: 24h
    
    receivers:
      - name: 'slack-default'
        slack_configs:
          - channel: '#alerts'
            send_resolved: true
            title: '{{ .Status | toUpper }}: {{ .CommonLabels.alertname }}'
            text: >-
              {{ range .Alerts }}
              *Alert:* {{ .Annotations.summary }}
              *Description:* {{ .Annotations.description }}
              *Severity:* {{ .Labels.severity }}
              {{ end }}
      
      - name: 'slack-critical'
        slack_configs:
          - channel: '#alerts-critical'
            send_resolved: true
            color: '{{ if eq .Status "firing" }}danger{{ else }}good{{ end }}'
            title: '🚨 {{ .Status | toUpper }}: {{ .CommonLabels.alertname }}'
            text: >-
              {{ range .Alerts }}
              *Alert:* {{ .Annotations.summary }}
              *Description:* {{ .Annotations.description }}
              *Namespace:* {{ .Labels.namespace }}
              *Runbook:* {{ .Annotations.runbook_url }}
              {{ end }}
      
      - name: 'slack-warning'
        slack_configs:
          - channel: '#alerts-warning'
            send_resolved: true
            color: 'warning'
            title: '⚠️ {{ .CommonLabels.alertname }}'
            text: >-
              {{ range .Alerts }}
              {{ .Annotations.summary }}
              {{ end }}
      
      - name: 'slack-info'
        slack_configs:
          - channel: '#alerts-info'
            send_resolved: false
            title: 'ℹ️ {{ .CommonLabels.alertname }}'
            text: '{{ .CommonAnnotations.summary }}'
    
    inhibit_rules:
      # Critical이 발생하면 같은 alertname의 Warning 억제
      - source_match:
          severity: 'critical'
        target_match:
          severity: 'warning'
        equal: ['alertname', 'namespace']
EOF

# 3. 적용 (주의: 기존 설정 덮어씀)
kubectl apply -f alertmanager-config.yaml

# 4. Alertmanager 재시작 (설정 반영)
kubectl rollout restart statefulset -n monitoring alertmanager-prometheus-kube-prometheus-alertmanager

# 5. 확인
kubectl get pods -n monitoring | grep alertmanager
```

### 실습 4: 팀별 라우팅 설정 (25분)

**목표**: 서비스/팀별로 다른 채널에 알림

        team: platform
      receiver: 'slack-platform'
      routes:
        - match:
            severity: critical
          receiver: 'pagerduty-platform'
    
    - match:
        team: payment
      receiver: 'slack-payment'
      routes:
        - match:
            severity: critical
          receiver: 'pagerduty-payment'

    - match_re:
        service: 'api-.*'
      receiver: 'slack-api-team'

        namespace: production
      receiver: 'slack-production'

### 실습 5: Inhibit Rules 설정 (15분)

**목표**: 상위 알림이 있을 때 하위 알림 억제

```yaml
inhibit_rules:
  # 1. Critical이 있으면 Warning 억제
  - source_match:
      severity: 'critical'
    target_match:
      severity: 'warning'
    equal: ['alertname', 'namespace']
  
  # 2. 노드 다운이면 해당 노드의 Pod 알림 억제
  - source_match:
      alertname: 'NodeDown'
    target_match_re:
      alertname: 'Pod.*'
    equal: ['node']
  
  # 3. 클러스터 다운이면 모든 알림 억제
  - source_match:
      alertname: 'ClusterDown'
    target_match_re:
      alertname: '.*'
    equal: []
```

## 📊 Part 3: 모범 사례

### 알림 설계 원칙

```
┌─────────────────────────────────────────────────────────────┐
│  좋은 알림의 조건                                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. Actionable (조치 가능)                                   │
│     - 알림을 받고 뭘 해야 하는지 명확                        │
│     - runbook_url 포함                                      │
│                                                             │
│  2. Specific (구체적)                                        │
│     - 어떤 서비스, 어떤 문제인지 명확                        │
│     - "서버 문제" ❌ → "payment-api P99 > 2s" ✅            │
│                                                             │
│  3. Timely (적시)                                            │
│     - 너무 빠르면 노이즈, 너무 느리면 의미 없음              │
│     - for 절로 조절                                          │
│                                                             │
│  4. Not Noisy (노이즈 최소화)                                │
│     - 무시하는 알림이 많으면 진짜 알림도 놓침                │
│     - 불필요한 알림은 삭제하거나 severity 낮추기            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
