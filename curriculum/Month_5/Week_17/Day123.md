# 📅 Day 123: ServiceMonitor로 자동 메트릭 수집

## 🎯 오늘의 목표

> **토스플레이스 연결점**: "마이크로서비스 환경에서 수백 개 서비스의 메트릭 자동 수집"

Kubernetes에서 새 서비스를 배포할 때마다 Prometheus 설정을 수동으로 변경하는 것은 비효율적입니다. **ServiceMonitor**를 사용하면 레이블 기반으로 자동으로 메트릭 수집 대상을 발견하고 설정할 수 있습니다.

## 📚 Part 1: 핵심 개념 (40분)

### ServiceMonitor란?

```
┌─────────────────────────────────────────────────────────────┐
│  Prometheus Operator의 Service Discovery                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  전통적 방식 (수동):                                         │
│  prometheus.yml에 직접 타겟 추가                             │
│  - static_configs:                                          │
│    - targets: ['myapp:8080']                                │
│  → 서비스 추가될 때마다 설정 변경 + Prometheus 재시작        │
│                                                             │
│  ServiceMonitor 방식 (자동):                                 │
│  1. 앱에 label 추가: app=myapp                              │
│  2. ServiceMonitor가 label로 서비스 발견                     │
│  3. Prometheus Operator가 자동으로 설정 반영                 │
│  → 설정 변경 없이 자동 수집!                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 동작 원리

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    ServiceMonitor 동작 흐름                             │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   ┌──────────────┐                                                      │
│   │  개발자가     │                                                      │
│   │  앱 배포      │                                                      │
│   └──────┬───────┘                                                      │
│          │                                                              │
│          ▼                                                              │
│   ┌──────────────┐     label:          ┌──────────────────┐            │
│   │   Service    │────app=myapp────────│  ServiceMonitor  │            │
│   │  (myapp-svc) │    매칭!            │  selector:       │            │
│   └──────────────┘                     │    app: myapp    │            │
│          │                             └────────┬─────────┘            │
│          │ :8080/metrics                        │                       │
│          ▼                                      ▼                       │
│   ┌──────────────┐                     ┌──────────────────┐            │
│   │     Pod      │◄────────────────────│   Prometheus     │            │
│   │   /metrics   │     scrape          │   Operator       │            │
│   └──────────────┘                     │   (자동 설정)     │            │
│                                        └──────────────────┘            │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### ServiceMonitor vs PodMonitor

| 구분 | ServiceMonitor | PodMonitor |
|------|---------------|------------|
| 대상 | Kubernetes Service | Pod 직접 |
| 사용 케이스 | 일반적인 서비스 | Service 없는 Pod, DaemonSet |
| 발견 방식 | Service selector 매칭 | Pod label 매칭 |
| 권장 상황 | **대부분의 경우** | 특수한 경우만 |

### ServiceMonitor 주요 필드

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: myapp-monitor
  namespace: monitoring        # ServiceMonitor 위치
  labels:
    release: prometheus        # ⚠️ 중요: Prometheus가 이 label로 찾음
spec:
  # 1. 어떤 Service를 찾을 것인가?
  selector:
    matchLabels:
      app: myapp               # 이 label을 가진 Service 선택
  
  # 2. 어느 namespace에서 찾을 것인가?
  namespaceSelector:
    matchNames:
    - default                  # default namespace에서만
    # any: true               # 모든 namespace (주의!)
  
  # 3. 어떻게 수집할 것인가?
  endpoints:
  - port: metrics              # Service의 port 이름
    interval: 30s              # 수집 주기
    path: /metrics             # 메트릭 경로
    scrapeTimeout: 10s         # 타임아웃
```

### 자주 하는 실수와 해결

```
┌─────────────────────────────────────────────────────────────┐
│  ❌ 실수 1: release 레이블 누락                              │
├─────────────────────────────────────────────────────────────┤
│  ServiceMonitor를 만들었는데 Prometheus가 인식 못함         │
│                                                             │
│  원인: Prometheus가 특정 label의 ServiceMonitor만 수집      │
│                                                             │
│  확인:                                                      │
│  kubectl get prometheus -n monitoring -o yaml | grep -A5 serviceMonitorSelector
│                                                             │
│  해결: ServiceMonitor에 해당 label 추가                     │
│  labels:                                                    │
│    release: prometheus  # 또는 해당 값                      │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  ❌ 실수 2: port 이름 불일치                                 │
├─────────────────────────────────────────────────────────────┤
│  Service:                                                   │
│    ports:                                                   │
│    - name: http           # ← 이름                          │
│      port: 8080                                             │
│                                                             │
│  ServiceMonitor:                                            │
│    endpoints:                                               │
│    - port: metrics        # ← 이름이 다름! 수집 안됨        │
│                                                             │
│  해결: 이름 일치시키기                                       │
│    - port: http           # ← 동일하게                       │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  ❌ 실수 3: namespace 불일치                                 │
├─────────────────────────────────────────────────────────────┤
│  Service: namespace=production                              │
│  ServiceMonitor namespaceSelector: default                  │
│  → production의 Service를 찾지 못함                         │
│                                                             │
│  해결:                                                       │
│  namespaceSelector:                                         │
│    matchNames:                                              │
│    - production                                             │
└─────────────────────────────────────────────────────────────┘
```

### 실습 1: 메트릭을 노출하는 앱 배포 (25분)

**목표**: /metrics 엔드포인트를 가진 애플리케이션 배포

```bash
# 1. 테스트 앱 배포 (metrics endpoint 포함)
cat << 'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: sample-app
  namespace: default
  labels:
    app: sample-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: sample-app
  template:
    metadata:
      labels:
        app: sample-app
    spec:
      containers:
      - name: app
        image: quay.io/brancz/prometheus-example-app:v0.5.0
        ports:
        - name: web
          containerPort: 8080
        - name: metrics
          containerPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: sample-app
  namespace: default
  labels:
    app: sample-app          # ← ServiceMonitor가 이걸 찾음
spec:
  selector:
    app: sample-app
  ports:
  - name: web
    port: 80
    targetPort: 8080
  - name: metrics            # ← ServiceMonitor가 이 port 이름 사용
    port: 8080
    targetPort: 8080
EOF

# 2. 배포 확인
kubectl get pods -l app=sample-app
kubectl get svc sample-app

# 3. 메트릭 확인
kubectl port-forward svc/sample-app 8080:8080 &
curl http://localhost:8080/metrics
```

**예상 출력 (metrics)**:
```
# HELP http_requests_total Total number of HTTP requests
# TYPE http_requests_total counter
http_requests_total{code="200",method="get"} 15
http_requests_total{code="404",method="get"} 2
# HELP version Application version
# TYPE version gauge
version{version="v0.5.0"} 1
```

**분석 포인트**:
- `# HELP`: 메트릭 설명
- `# TYPE`: 메트릭 타입 (counter, gauge, histogram)
- 레이블과 함께 값이 출력됨

### 실습 2: ServiceMonitor 생성 (20분)

**목표**: 자동 메트릭 수집 설정

```bash
# 1. ServiceMonitor 생성
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: sample-app-monitor
  namespace: monitoring          # monitoring namespace에 생성
  labels:
    release: prometheus          # ⚠️ 필수: Prometheus가 이 label로 찾음
spec:
  selector:
    matchLabels:
      app: sample-app            # Service의 label과 매칭
  namespaceSelector:
    matchNames:
    - default                    # Service가 있는 namespace
  endpoints:
  - port: metrics                # Service의 port 이름
    interval: 15s                # 15초마다 수집
    path: /metrics               # 메트릭 경로
EOF

# 2. 생성 확인
kubectl get servicemonitor -n monitoring sample-app-monitor

# 3. 상세 확인
kubectl describe servicemonitor -n monitoring sample-app-monitor
```

**예상 출력**:
```
NAME                 AGE
sample-app-monitor   10s
```

### 실습 5: PodMonitor 사용 (20분)

**목표**: Service 없이 Pod 직접 모니터링

```bash
# 1. PodMonitor 생성 (Service가 없는 경우)
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: PodMonitor
metadata:
  name: sample-app-pods
  namespace: monitoring
  labels:
    release: prometheus
spec:
  selector:
    matchLabels:
      app: sample-app
  namespaceSelector:
    matchNames:
    - default
  podMetricsEndpoints:
  - port: metrics              # Pod의 containerPort 이름
    interval: 15s
    path: /metrics
EOF

# 2. 확인
kubectl get podmonitor -n monitoring
```

**사용 케이스**:
- DaemonSet (각 노드의 Pod 직접 모니터링)
- Service 없는 배치 작업
- 특정 Pod만 선택적 모니터링

### 실습 6: 릴레이블링 (Relabeling) (20분)

**목표**: 메트릭 레이블 수정/추가/제거

```bash
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: sample-app-relabel
  namespace: monitoring
  labels:
    release: prometheus
spec:
  selector:
    matchLabels:
      app: sample-app
  namespaceSelector:
    matchNames:
    - default
  endpoints:
  - port: metrics
    interval: 15s
    # 메트릭 릴레이블링
    metricRelabelings:
    # 1. 특정 메트릭만 유지
    - sourceLabels: [__name__]
      regex: 'http_requests_total|version'
      action: keep
    # 2. 레이블 이름 변경
    - sourceLabels: [code]
      targetLabel: status_code
      action: replace
    # 3. 레이블 제거
    - regex: 'instance'
      action: labeldrop
EOF
```

**릴레이블링 액션**:
| 액션 | 설명 |
|------|------|
| `keep` | 매칭되는 것만 유지 |
| `drop` | 매칭되는 것 제거 |
| `replace` | 레이블 값 변경/추가 |
| `labeldrop` | 레이블 자체 제거 |
| `labelkeep` | 매칭되는 레이블만 유지 |

## 📊 Part 3: 트러블슈팅 가이드

### 메트릭이 수집되지 않을 때

```bash
# 1단계: ServiceMonitor 존재 확인
kubectl get servicemonitor -n monitoring

# 2단계: label 매칭 확인

# 3단계: Prometheus config 확인
kubectl exec -n monitoring prometheus-prometheus-kube-prometheus-prometheus-0 -- \
  cat /etc/prometheus/config_out/prometheus.env.yaml | grep -A20 "sample-app"

# 4단계: Pod에서 직접 메트릭 확인
kubectl exec -it deploy/sample-app -- curl localhost:8080/metrics

# 5단계: Prometheus 로그 확인
kubectl logs -n monitoring prometheus-prometheus-kube-prometheus-prometheus-0 -c prometheus | grep "sample-app"
```
