## 📚 Part 1: 핵심 개념 (40분)

### Alerting 흐름

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        Prometheus Alerting Flow                         │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   ┌───────────────────┐                                                 │
│   │  Alerting Rule    │  expr: error_rate > 0.05                       │
│   │  (PrometheusRule) │  for: 5m                                       │
│   └─────────┬─────────┘                                                 │
│             │                                                           │
│             ▼                                                           │
│   ┌───────────────────┐                                                 │
│   │   조건 충족 시     │  Pending (5분 대기)                             │
│   │   Alert 상태 변경  │  → Firing (알림 발송)                           │
│   └─────────┬─────────┘                                                 │
│             │                                                           │
│             ▼                                                           │
│   ┌───────────────────┐                                                 │
│   │   Alertmanager    │  그룹화, 중복 제거, 라우팅                       │
│   └─────────┬─────────┘                                                 │
│             │                                                           │
│       ┌─────┴─────┬──────────────┐                                     │
│       ▼           ▼              ▼                                      │
│   ┌───────┐  ┌────────┐  ┌────────────┐                                │
│   │ Slack │  │ Email  │  │ PagerDuty  │                                │
│   └───────┘  └────────┘  └────────────┘                                │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Alert 상태

| 상태 | 설명 | 의미 |
|------|------|------|
| **Inactive** | 조건 미충족 | 정상 상태 |
| **Pending** | 조건 충족, for 대기 중 | 일시적일 수 있음 |
| **Firing** | for 기간 지속 | 실제 문제! 알림 발송 |

### for 절의 중요성

```
┌─────────────────────────────────────────────────────────────┐
│  for 절 = "최소 지속 시간"                                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ❌ for 없이:                                                │
│                                                             │
│  error_rate > 0.05 → 즉시 알림!                             │
│                                                             │
│  문제: 순간적인 스파이크에도 알림 (노이즈)                   │
│                                                             │
│  시간 →  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━             │
│  값   →       ↑                                             │
│              0.06 (1초간)                                    │
│  결과 → 🔔 알림! (불필요)                                    │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ✅ for: 5m 사용:                                            │
│                                                             │
│  error_rate > 0.05 for 5m → 5분 지속 시 알림                 │
│                                                             │
│  시간 →  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━             │
│  값   →       ↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑                        │
│              5분 연속 0.06                                   │
│  결과 → 🔔 알림! (실제 문제)                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Severity 레벨 설계

```
┌─────────────────────────────────────────────────────────────┐
│  Severity 레벨 가이드                                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  🔴 critical: 즉각 대응 필요                                 │

│     - 데이터 손실 위험                                       │

│  🟠 warning: 신속 대응 필요                                  │

│     - 방치 시 critical로 발전 가능                           │
│     - 대응: 업무 시간 내                                     │

│                                                             │

│     - 트렌드 파악용                                          │

│     - 채널: Slack #alerts-info                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Alerting Rule 구조

```yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: myapp-alerts
  namespace: monitoring
  labels:
    release: prometheus
spec:
  groups:
  - name: myapp.alerts
    rules:
    - alert: HighErrorRate           # 알림 이름
      expr: |                        # PromQL 조건
        sum(rate(http_requests_total{status=~"5.."}[5m])) by (service)
        /
        sum(rate(http_requests_total[5m])) by (service)
        > 0.05
      for: 5m                        # 지속 시간
      labels:
        severity: critical           # 심각도
        team: platform               # 담당팀
      annotations:
        summary: "High error rate on {{ $labels.service }}"
        description: "Error rate is {{ $value | humanizePercentage }} (threshold: 5%)"
        runbook_url: "https://wiki.company.com/runbook/high-error-rate"
```

### Annotations 템플릿 변수

| 변수 | 설명 | 예시 |
|------|------|------|
| `{{ $labels.xxx }}` | 메트릭 레이블 | `{{ $labels.service }}` |
| `{{ $value }}` | 현재 값 | `0.0523` |
| `{{ $value \| humanizePercentage }}` | 백분율 형식 | `5.23%` |
| `{{ $value \| humanizeDuration }}` | 시간 형식 | `2h 30m` |
| `{{ $value \| humanize }}` | 숫자 형식 | `1.23M` |

### 실습 1: 기본 Alerting Rule 생성 (25분)

**목표**: 에러율 기반 알림 규칙 생성

```bash
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: http-alerts
  namespace: monitoring
  labels:
    release: prometheus
    app: kube-prometheus-stack
spec:
  groups:
  - name: http.alerts
    rules:
    # 1. 높은 에러율 알림
    - alert: HighHttpErrorRate
      expr: |
        (
          sum(rate(http_requests_total{status=~"5.."}[5m])) by (job, service)
          /
          sum(rate(http_requests_total[5m])) by (job, service)
        ) > 0.05
      for: 5m
      labels:
        severity: critical
      annotations:
        summary: "High HTTP error rate detected"
        description: |
          Service {{ $labels.service }} has error rate of {{ $value | humanizePercentage }}.
          This is above the threshold of 5%.
        runbook_url: "https://wiki.example.com/runbook/high-error-rate"
    
    # 2. HTTP 요청 없음 알림
    - alert: NoHttpRequests
      expr: |
        sum(rate(http_requests_total[5m])) by (job) == 0
      for: 10m
      labels:
        severity: warning
      annotations:
        summary: "No HTTP requests received"
        description: "Job {{ $labels.job }} has received no HTTP requests for 10 minutes."
EOF

# 생성 확인
kubectl get prometheusrules -n monitoring http-alerts -o yaml
```

### 실습 3: 리소스 기반 알림 (25분)

**목표**: CPU/메모리 사용률 알림 규칙 생성

```bash
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: resource-alerts
  namespace: monitoring
  labels:
    release: prometheus
    app: kube-prometheus-stack
spec:
  groups:
  - name: resource.alerts
    rules:
    # 1. 높은 CPU 사용률
    - alert: HighCpuUsage
      expr: |
        (
          100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
        ) > 80
      for: 10m
      labels:
        severity: warning
      annotations:
        summary: "High CPU usage on {{ $labels.instance }}"
        description: "CPU usage is {{ $value | printf \"%.1f\" }}% on node {{ $labels.instance }}."
    
    # 2. 높은 메모리 사용률
    - alert: HighMemoryUsage
      expr: |
        (
          (1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)) * 100
        ) > 85
      for: 10m
      labels:
        severity: warning
      annotations:
        summary: "High memory usage on {{ $labels.instance }}"
        description: "Memory usage is {{ $value | printf \"%.1f\" }}% on node {{ $labels.instance }}."
    
    # 3. 디스크 공간 부족
    - alert: DiskSpaceLow
      expr: |
        (
          (1 - (node_filesystem_avail_bytes{fstype!~"tmpfs|overlay"} / node_filesystem_size_bytes)) * 100
        ) > 80
      for: 10m
      labels:
        severity: warning
      annotations:
        summary: "Low disk space on {{ $labels.instance }}"
        description: "Disk usage is {{ $value | printf \"%.1f\" }}% on {{ $labels.mountpoint }}."
    
    # 4. 디스크 공간 거의 없음
    - alert: DiskSpaceCritical
      expr: |
        (
          (1 - (node_filesystem_avail_bytes{fstype!~"tmpfs|overlay"} / node_filesystem_size_bytes)) * 100
        ) > 95
      for: 5m
      labels:
        severity: critical
      annotations:
        summary: "Critical disk space on {{ $labels.instance }}"
        description: "Disk usage is {{ $value | printf \"%.1f\" }}% on {{ $labels.mountpoint }}. Immediate action required!"
EOF
```

### 실습 4: Kubernetes 관련 알림 (25분)

**목표**: Pod, Deployment 상태 알림 설정

```bash
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: kubernetes-alerts
  namespace: monitoring
  labels:
    release: prometheus
    app: kube-prometheus-stack
spec:
  groups:
  - name: kubernetes.alerts
    rules:
    # 1. Pod 재시작 반복
    - alert: PodRestartingTooMuch
      expr: |
        increase(kube_pod_container_status_restarts_total[1h]) > 3
      for: 5m
      labels:
        severity: warning
      annotations:
        summary: "Pod {{ $labels.pod }} is restarting frequently"
        description: "Pod {{ $labels.namespace }}/{{ $labels.pod }} has restarted {{ $value | printf \"%.0f\" }} times in the last hour."
    
    # 2. Pod Pending 상태 지속
    - alert: PodPendingTooLong
      expr: |
        kube_pod_status_phase{phase="Pending"} == 1
      for: 15m
      labels:
        severity: warning
      annotations:
        summary: "Pod {{ $labels.pod }} stuck in Pending"
        description: "Pod {{ $labels.namespace }}/{{ $labels.pod }} has been Pending for more than 15 minutes."
    
    # 3. Deployment 복제본 불일치
    - alert: DeploymentReplicasMismatch
      expr: |
        kube_deployment_spec_replicas != kube_deployment_status_replicas_available
      for: 10m
      labels:
        severity: warning
      annotations:
        summary: "Deployment {{ $labels.deployment }} replicas mismatch"
        description: "Deployment {{ $labels.namespace }}/{{ $labels.deployment }} has {{ $value }} unavailable replicas."
    
    # 4. Pod OOM Killed
    - alert: PodOOMKilled
      expr: |
        kube_pod_container_status_last_terminated_reason{reason="OOMKilled"} == 1
      for: 0m
      labels:
        severity: critical
      annotations:
        summary: "Container {{ $labels.container }} was OOM killed"
        description: "Container {{ $labels.container }} in pod {{ $labels.namespace }}/{{ $labels.pod }} was OOM killed."
EOF
```

### 실습 5: 알림 테스트 (20분)

**목표**: 실제로 알림이 발생하는지 테스트

```bash
# 1. 의도적으로 알림 트리거 (항상 참인 조건)
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: test-alert
  namespace: monitoring
  labels:
    release: prometheus
    app: kube-prometheus-stack
spec:
  groups:
  - name: test.alerts
    rules:
    - alert: TestAlert
      expr: vector(1) > 0    # 항상 참
      for: 1m                 # 1분 후 발동
      labels:
        severity: info
      annotations:
        summary: "This is a test alert"
        description: "Testing alerting pipeline."
EOF

# 2. 1분 후 Prometheus Alerts 페이지에서 확인
# http://localhost:9090/alerts

# 3. Alertmanager 확인
kubectl port-forward -n monitoring svc/alertmanager-operated 9093:9093 &
# 브라우저: http://localhost:9093

# 4. 테스트 후 삭제
kubectl delete prometheusrule -n monitoring test-alert
```

### 실습 6: 실무 알림 패턴 10가지 (10분)

```yaml
# 참고용: 실제 프로덕션에서 자주 쓰이는 패턴

# 1. SLA 위반 (가용성 99.9% 미달)
- alert: SLAViolation
  expr: (1 - sum(rate(http_requests_total{status=~"5.."}[24h])) / sum(rate(http_requests_total[24h]))) < 0.999

# 2. 응답 지연 (P99 > 2초)
- alert: HighLatency
  expr: histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket[5m])) by (le)) > 2

# 3. 인증서 만료 임박 (30일 이내)
- alert: CertificateExpiringSoon
  expr: (probe_ssl_earliest_cert_expiry - time()) / 86400 < 30

# 4. 큐 적체
- alert: QueueBacklog
  expr: queue_length > 1000

# 5. DB 커넥션 풀 고갈
- alert: DBConnectionPoolExhausted
  expr: db_connection_pool_available == 0

# 6. 외부 API 장애
- alert: ExternalAPIDown
  expr: probe_success{job="external-api"} == 0

# 7. 메모리 누수 의심
- alert: PossibleMemoryLeak
  expr: increase(container_memory_usage_bytes[1h]) > 500000000  # 500MB/hour 증가

# 8. 급격한 트래픽 증가
- alert: TrafficSpike
  expr: rate(http_requests_total[5m]) > 2 * rate(http_requests_total[5m] offset 1h)

# 9. 로그 에러 급증
- alert: LogErrorSpike
  expr: rate(log_messages_total{level="error"}[5m]) > 10

# 10. 배포 후 에러율 증가
- alert: DeploymentCausedErrors
  expr: rate(http_requests_total{status=~"5.."}[5m]) > 1.5 * rate(http_requests_total{status=~"5.."}[5m] offset 10m)
```
