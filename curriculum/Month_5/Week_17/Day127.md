## 📚 핵심 개념 복습

### 1. Prometheus 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│  반드시 기억할 것                                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Pull 모델:                                                  │
│  - Prometheus가 타겟에서 메트릭을 "가져옴"                   │
│  - 타겟이 죽으면 up=0으로 감지 가능                          │
│                                                             │
│  핵심 컴포넌트:                                              │
│  - Prometheus Server: 수집, 저장, 쿼리                      │
│  - Alertmanager: 알림 라우팅, 그룹화, 전송                  │
│  - Grafana: 시각화                                          │
│                                                             │
│  Prometheus Operator CRDs:                                  │
│  - ServiceMonitor: 서비스 자동 수집                         │
│  - PodMonitor: Pod 직접 수집                                │
│  - PrometheusRule: Recording/Alerting 규칙                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2. 메트릭 타입별 쿼리 방법

```
┌─────────────────────────────────────────────────────────────┐
│  메트릭 타입        │  올바른 사용법                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Counter (증가만)                                           │
│  ✅ rate(http_requests_total[5m])  # 초당 증가율           │
│  ✅ increase(http_requests_total[1h])  # 구간 증가량       │
│  ❌ http_requests_total  # 의미 없는 누적값                 │
│                                                             │
│  Gauge (증감)                                                │
│  ✅ memory_usage_bytes  # 현재 값 직접 사용                 │
│  ✅ avg_over_time(cpu_usage[5m])  # 구간 평균              │
│  ❌ rate(memory_usage_bytes[5m])  # 보통 의미 없음         │
│                                                             │
│  Histogram (분포)                                            │
│  ✅ histogram_quantile(0.99, sum(rate(..._bucket[5m])) by (le))
│  ✅ sum(rate(..._sum[5m])) / sum(rate(..._count[5m]))  # 평균
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3. 핵심 PromQL 쿼리 10선

```promql
# 1. 요청률 (RPS)
sum(rate(http_requests_total[5m])) by (service)

# 2. 에러율
sum(rate(http_requests_total{status=~"5.."}[5m])) by (service)
/
sum(rate(http_requests_total[5m])) by (service)

# 3. P99 응답시간
histogram_quantile(0.99,
  sum(rate(http_request_duration_seconds_bucket[5m])) by (le, service)
)

# 4. 노드 CPU 사용률 (%)
100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# 5. 노드 메모리 사용률 (%)
(1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)) * 100

# 6. Pod CPU TOP 10
topk(10, sum(rate(container_cpu_usage_seconds_total{container!=""}[5m])) by (pod))

# 7. Pod 메모리 TOP 10
topk(10, sum(container_memory_usage_bytes{container!=""}) by (pod, namespace))

# 8. 컨테이너 재시작 횟수
sum(increase(kube_pod_container_status_restarts_total[1h])) by (pod) > 0

# 9. 디스크 사용률
(1 - node_filesystem_avail_bytes / node_filesystem_size_bytes) * 100

# 10. 살아있는 타겟 수
count(up == 1)
```

### 4. ServiceMonitor 핵심

```yaml
# 성공적인 ServiceMonitor의 필수 요소
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: myapp
  namespace: monitoring
  labels:
    release: prometheus        # ⚠️ 필수: Prometheus가 찾는 label
spec:
  selector:
    matchLabels:
      app: myapp               # Service의 label과 일치
  namespaceSelector:
    matchNames:
    - default                  # Service가 있는 namespace
  endpoints:
  - port: metrics              # Service의 port 이름과 일치
    interval: 30s
    path: /metrics
```

### 5. Recording vs Alerting Rules

```yaml
# Recording Rule: 쿼리 결과 저장 (record: 사용)
- record: job:http_requests:rate5m
  expr: sum(rate(http_requests_total[5m])) by (job)

# Alerting Rule: 조건 충족 시 알림 (alert: 사용)
- alert: HighErrorRate
  expr: job:http_error_rate:ratio > 0.05
  for: 5m
  labels:
    severity: critical
  annotations:
    summary: "Error rate {{ $value | humanizePercentage }}"
```

### 6. Alertmanager 라우팅

```yaml
route:
  receiver: 'default'
  group_by: ['alertname', 'severity']
  routes:
    - match:
        severity: critical
      receiver: 'pagerduty'
    - match:
        severity: warning
      receiver: 'slack-warning'

receivers:
  - name: 'slack-warning'
    slack_configs:
      - channel: '#alerts'
        send_resolved: true
```

### 실습 2: 새 앱 모니터링 설정 (30분)

**시나리오**: 새로운 마이크로서비스를 배포하고 모니터링 설정

```bash
# 1. 앱 배포
cat << 'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: review-app
  labels:
    app: review-app
    team: platform
spec:
  replicas: 3
  selector:
    matchLabels:
      app: review-app
  template:
    metadata:
      labels:
        app: review-app
        team: platform
    spec:
      containers:
      - name: app
        image: quay.io/brancz/prometheus-example-app:v0.5.0
        ports:
        - name: http
          containerPort: 8080
        - name: metrics
          containerPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: review-app
  labels:
    app: review-app
    team: platform
spec:
  selector:
    app: review-app
  ports:
  - name: http
    port: 80
    targetPort: 8080
  - name: metrics
    port: 8080
    targetPort: 8080
EOF

# 2. ServiceMonitor 생성
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: review-app
  namespace: monitoring
  labels:
    release: prometheus
spec:
  selector:
    matchLabels:
      app: review-app
  namespaceSelector:
    matchNames:
    - default
  endpoints:
  - port: metrics
    interval: 15s
EOF

# 3. Recording & Alerting Rules 생성
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: review-app-rules
  namespace: monitoring
  labels:
    release: prometheus
spec:
  groups:
  - name: review-app.rules
    rules:
    # Recording Rules
    - record: job:review_app_requests:rate5m
      expr: sum(rate(http_requests_total{job="review-app"}[5m]))
    - record: job:review_app_errors:rate5m
      expr: sum(rate(http_requests_total{job="review-app", code=~"5.."}[5m]))
    
    # Alerting Rules
    - alert: ReviewAppHighErrorRate
      expr: |
        job:review_app_errors:rate5m / job:review_app_requests:rate5m > 0.05
      for: 5m
      labels:
        severity: critical
        team: platform
      annotations:
        summary: "Review App error rate is high"
        description: "Error rate is {{ $value | humanizePercentage }}"
    
    - alert: ReviewAppDown
      expr: up{job="review-app"} == 0
      for: 1m
      labels:
        severity: critical
        team: platform
      annotations:
        summary: "Review App is down"
EOF

# 4. 확인
kubectl get servicemonitor -n monitoring review-app
kubectl get prometheusrules -n monitoring review-app-rules
```

### 실습 4: 문제 해결 시나리오 (15분)

**시나리오**: ServiceMonitor를 만들었는데 메트릭이 수집되지 않음

```bash
# 트러블슈팅 순서

# 1. ServiceMonitor가 존재하는지 확인
kubectl get servicemonitor -n monitoring review-app

# 2. ServiceMonitor의 label이 Prometheus selector와 일치하는지
kubectl get prometheus -n monitoring -o yaml | grep -A5 serviceMonitorSelector

# 3. Service의 label이 ServiceMonitor selector와 일치하는지
kubectl get svc review-app --show-labels
kubectl get servicemonitor -n monitoring review-app -o yaml | grep -A3 selector

# 4. Service의 port 이름이 ServiceMonitor endpoint와 일치하는지
kubectl get svc review-app -o yaml | grep -A5 ports
kubectl get servicemonitor -n monitoring review-app -o yaml | grep -A3 endpoints

# 5. Pod에서 직접 메트릭 확인
kubectl exec -it deploy/review-app -- curl localhost:8080/metrics

# 6. Prometheus config에 반영되었는지 확인
kubectl exec -n monitoring prometheus-prometheus-kube-prometheus-prometheus-0 -- \
  cat /etc/prometheus/config_out/prometheus.env.yaml | grep review-app
```
