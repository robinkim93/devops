### Prometheus 아키텍처

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        Prometheus Architecture                          │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────┐       │
│  │                    Prometheus Server                         │       │
│  │  ┌─────────────┐ ┌─────────────┐ ┌─────────────────────┐   │       │
│  │  │  Retrieval  │ │    TSDB     │ │    HTTP Server      │   │       │
│  │  │  (Scraper)  │ │  (Storage)  │ │   (PromQL API)      │   │       │
│  │  └──────┬──────┘ └─────────────┘ └─────────────────────┘   │       │
│  │         │                                    │               │       │
│  └─────────┼────────────────────────────────────┼───────────────┘       │
│            │ Pull                               │                        │
│            │ (scrape)                           │ Query                  │
│    ┌───────┴───────────────────────┐           │                        │
│    │           │           │       │           ▼                        │
│    ▼           ▼           ▼       ▼     ┌───────────┐                  │
│ ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  │  Grafana  │                  │
│ │ Node │  │ App  │  │ K8s  │  │Istio │  │           │                  │
│ │Export│  │/metric│ │ API  │  │Proxy │  └───────────┘                  │
│ └──────┘  └──────┘  └──────┘  └──────┘                                  │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────┐       │
│  │                    Alertmanager                              │       │
│  │  - 알림 그룹화, 중복 제거, 라우팅                            │       │
│  │  - Slack, PagerDuty, Email 등 연동                          │       │
│  └─────────────────────────────────────────────────────────────┘       │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Pull vs Push 모델

| 구분 | Pull (Prometheus) | Push (예: StatsD) |
|------|-------------------|-------------------|
| 방향 | 서버가 타겟에서 수집 | 타겟이 서버로 전송 |
| 장점 | 타겟 상태 파악 가능 (up/down) | 방화벽 뒤 환경에 적합 |
| 단점 | 네트워크 접근 필요 | 타겟 상태 파악 어려움 |
| 사용 | 쿠버네티스 환경 표준 | 단발성 작업, 배치 |

### 메트릭 데이터 타입

| 타입 | 설명 | 예시 | 사용 케이스 |
|------|------|------|------------|
| **Counter** | 증가만 가능 | `http_requests_total` | 요청 수, 에러 수 |
| **Gauge** | 증감 가능 | `memory_usage_bytes` | 메모리, 온도, 큐 크기 |
| **Histogram** | 분포 측정 | `request_duration_bucket` | 응답시간 분포, P99 |
| **Summary** | 클라이언트 분위수 | `request_duration_quantile` | 응답시간 (서버 부하 낮음) |

```
┌─────────────────────────────────────────────────────────────┐
│  Prometheus Operator (권장)                                  │

│                                                             │
│  장점:                                                      │
│  ✅ CRD로 설정 관리 (ServiceMonitor, PrometheusRule)        │
│  ✅ 자동 타겟 디스커버리                                     │

│                                                             │
│  Custom Resources:                                          │
```

### 실습 1: kube-prometheus-stack 설치 (20분)

**목표**: Prometheus Operator와 전체 모니터링 스택 설치

```bash
# 1. Helm 레포지토리 추가
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update

# 2. monitoring 네임스페이스 생성
kubectl create namespace monitoring

# 3. kube-prometheus-stack 설치
helm install prometheus prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --set prometheus.prometheusSpec.retention=7d \
  --set prometheus.prometheusSpec.resources.requests.memory=1Gi \
  --set prometheus.prometheusSpec.resources.requests.cpu=500m

# 설치 확인
kubectl get pods -n monitoring -w
```

**예상 출력** (모든 Pod이 Running이 될 때까지 2-3분):
```
NAME                                                     READY   STATUS    RESTARTS   AGE
alertmanager-prometheus-kube-prometheus-alertmanager-0   2/2     Running   0          2m
prometheus-grafana-5c6b8d4f7-x2kj4                       3/3     Running   0          2m
prometheus-kube-prometheus-operator-7d7b8c5c9-r4vnd      1/1     Running   0          2m
prometheus-kube-state-metrics-6c8d5c5c9-8x2kj            1/1     Running   0          2m
prometheus-prometheus-kube-prometheus-prometheus-0       2/2     Running   0          2m
prometheus-prometheus-node-exporter-xxxxx                1/1     Running   0          2m
```

**분석 포인트**:
- `prometheus-kube-prometheus-operator`: CRD 관리
- `prometheus-prometheus-...`: 실제 Prometheus 서버
- `alertmanager-...`: 알림 관리자
- `prometheus-grafana-...`: 시각화 대시보드
- `node-exporter`: 노드 메트릭 수집

### 실습 3: 기본 PromQL 쿼리 실행 (30분)

**목표**: 핵심 메트릭 조회 방법 학습

```promql
# 1. 노드 메트릭 확인
# 노드 CPU 사용률 (%)
100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
```

**예상 출력**:
```
{instance="192.168.1.10:9100"} 23.45
{instance="192.168.1.11:9100"} 18.72
```

```promql
# 2. 노드 메모리 사용률 (%)
(1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)) * 100
```

**예상 출력**:
```
{instance="192.168.1.10:9100"} 67.23
{instance="192.168.1.11:9100"} 54.18
```

```promql
# 3. Pod 메모리 사용량 (네임스페이스별)
sum(container_memory_usage_bytes{container!=""}) by (namespace)
```

**예상 출력**:
```
{namespace="kube-system"}     1073741824
{namespace="monitoring"}      2147483648
{namespace="default"}         536870912
```

```promql
# 4. 컨테이너 CPU 사용률
sum(rate(container_cpu_usage_seconds_total{container!=""}[5m])) by (pod)
```

**분석 기준**:
- CPU > 80%: 주의 필요
- CPU > 95%: 스케일링 검토
- 메모리 > 85%: OOM 위험

### 실습 5: 설치된 CRD 확인 (15분)

```bash
# 1. CRD 목록 확인
kubectl get crd | grep monitoring.coreos.com

# 예상 출력:
# alertmanagerconfigs.monitoring.coreos.com
# alertmanagers.monitoring.coreos.com
# podmonitors.monitoring.coreos.com
# probes.monitoring.coreos.com
# prometheuses.monitoring.coreos.com
# prometheusrules.monitoring.coreos.com
# servicemonitors.monitoring.coreos.com
# thanosrulers.monitoring.coreos.com

# 2. ServiceMonitor 목록 확인
kubectl get servicemonitors -n monitoring

# 3. 특정 ServiceMonitor 상세 확인
kubectl get servicemonitor -n monitoring prometheus-kube-prometheus-kubelet -o yaml
```

**분석 포인트**:
```yaml
# ServiceMonitor 핵심 필드
spec:
  endpoints:
  - port: https-metrics      # 수집할 포트
    interval: 30s            # 수집 주기
    path: /metrics           # 메트릭 경로
  selector:
    matchLabels:
      app.kubernetes.io/name: kubelet  # 대상 서비스 선택
```
