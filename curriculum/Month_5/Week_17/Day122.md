## 📚 Part 1: 핵심 개념 (40분)

### 메트릭 데이터 타입 심화

```
┌─────────────────────────────────────────────────────────────┐
│  메트릭 타입 선택 가이드                                     │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  "이 값이 시간이 지나면 어떻게 변하나?"                      │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  계속 증가만 한다 → Counter                          │   │
│  │  (요청 수, 에러 수, 처리된 바이트)                    │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  오르락내리락 한다 → Gauge                           │   │
│  │  (메모리 사용량, 온도, 큐 크기, 동시 접속자)          │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  분포를 알고 싶다 → Histogram                        │   │
│  │  (응답시간 P99, 요청 크기 분포)                       │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Counter vs Gauge 실수 방지

```
┌─────────────────────────────────────────────────────────────┐
│  ❌ 흔한 실수                                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Counter에 rate() 없이 사용:                                │
│  http_requests_total = 1,523,847                            │
│  → "이 숫자가 뭘 의미하지?" (의미 없음)                      │
│                                                             │
│  ✅ 올바른 사용:                                            │
│  rate(http_requests_total[5m]) = 127.5                      │
│  → "초당 127.5개 요청 처리 중" (의미 있음!)                  │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Gauge에 rate() 사용:                                       │
│  rate(memory_usage_bytes[5m]) = ???                         │
│  → "메모리가 초당 얼마나 변하나?" (보통 의미 없음)           │
│                                                             │
│  ✅ 올바른 사용:                                            │
│  memory_usage_bytes = 4294967296                            │
│  → "현재 4GB 사용 중" (의미 있음!)                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### rate() vs irate() 차이

| 함수 | 계산 방식 | 사용 케이스 | 특징 |
|------|----------|------------|------|
| `rate()` | 구간 전체 평균 | 알림, 장기 트렌드 | 안정적, 스무딩 |
| `irate()` | 마지막 두 포인트 | 실시간 대시보드 | 민감, 스파이크 감지 |

```
시간 →   t1    t2    t3    t4    t5
값    →  100   150   200   180   250

rate([5m]):  전체 평균 기울기 = 30/분
irate():     마지막 구간만 = (250-180)/(t5-t4) = 급등!
```

### 집계 함수 요약

| 함수 | 설명 | 예시 |
|------|------|------|
| `sum()` | 합계 | `sum(rate(http_requests_total[5m]))` |
| `avg()` | 평균 | `avg(container_memory_usage_bytes) by (namespace)` |
| `max()` | 최대값 | `max(node_cpu_usage) by (instance)` |
| `min()` | 최소값 | `min(node_memory_available_bytes)` |
| `count()` | 개수 | `count(up == 1)` (살아있는 타겟 수) |
| `topk()` | 상위 N개 | `topk(5, sum(rate(...)) by (pod))` |
| `bottomk()` | 하위 N개 | `bottomk(5, ...)` |
| `quantile()` | 분위수 | `quantile(0.95, ...)` |

### by vs without

```promql
# by: 지정한 레이블만 유지
sum(rate(http_requests_total[5m])) by (service, method)
# 결과: {service="api", method="GET"} 125.5

# without: 지정한 레이블만 제외
sum(rate(http_requests_total[5m])) without (instance, pod)
# 결과: 나머지 모든 레이블 유지
```

### 실습 1: 레이블 필터링 마스터 (20분)

**목표**: 다양한 필터링 연산자 사용법 익히기

```promql
# 1. 정확한 매칭 (=)
http_requests_total{method="GET"}

# 2. 부정 매칭 (!=)
http_requests_total{status!="200"}

# 3. 정규식 매칭 (=~)
http_requests_total{method=~"GET|POST"}
http_requests_total{path=~"/api/v[12]/.*"}

# 4. 정규식 부정 (!~)
http_requests_total{path!~"/health.*"}

# 5. 여러 조건 조합
container_memory_usage_bytes{
  namespace="production",
  container!="POD",
  container=~"api-.*"
}
```

**예상 출력 예시**:
```
http_requests_total{method="GET", status="200", path="/api/users"} 15234
http_requests_total{method="GET", status="200", path="/api/orders"} 8921
```

**분석 포인트**:
- 정규식은 `=~`와 `!~` 사용
- 빈 문자열 제외: `container!=""`
- 여러 값 OR: `method=~"GET|POST|PUT"`

### 실습 2: Counter 메트릭 분석 (25분)

**목표**: rate(), increase() 올바르게 사용하기

```promql
# 1. 초당 요청률 (rate)
rate(http_requests_total[5m])
```

**예상 출력**:
```
{method="GET", path="/api/users", status="200"} 45.23
{method="POST", path="/api/orders", status="201"} 12.87
```

```promql
# 2. 서비스별 총 요청률
sum(rate(http_requests_total[5m])) by (service)
```

**예상 출력**:
```
{service="api-gateway"} 523.45
{service="user-service"} 234.12
{service="order-service"} 189.34
```

```promql
# 3. 지난 1시간 총 요청 수 (increase)
sum(increase(http_requests_total[1h])) by (service)
```

**예상 출력**:
```
{service="api-gateway"} 1884420
{service="user-service"} 843312
```

```promql
# 4. 에러율 계산 (핵심!)
sum(rate(http_requests_total{status=~"5.."}[5m])) by (service)
/
sum(rate(http_requests_total[5m])) by (service)
```

**예상 출력**:
```
{service="api-gateway"} 0.0023    # 0.23% 에러율
{service="order-service"} 0.0512  # 5.12% 에러율 ⚠️
```

**분석 기준**:
- 에러율 < 0.1%: 정상
- 에러율 0.1-1%: 주의
- 에러율 > 1%: 심각

### 실습 3: Histogram과 P99 계산 (30분)

**목표**: histogram_quantile로 응답시간 분석

```promql
# 1. P99 응답시간 (전체)
histogram_quantile(0.99,
  sum(rate(http_request_duration_seconds_bucket[5m])) by (le)
)
```

**예상 출력**:
```
{} 0.234  # 234ms
```

```promql
# 2. 서비스별 P99
histogram_quantile(0.99,
  sum(rate(http_request_duration_seconds_bucket[5m])) by (le, service)
)
```

**예상 출력**:
```
{service="api-gateway"} 0.156
{service="user-service"} 0.234
{service="order-service"} 0.892  # 느림! ⚠️
```

```promql
# 3. P50, P90, P99 비교
histogram_quantile(0.50, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))  # 중앙값
histogram_quantile(0.90, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))  # P90
histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))  # P99
```

**분석 팁**:
```
P50 = 100ms, P99 = 2000ms 인 경우:
→ 대부분(50%)은 100ms 이내지만
→ 1%는 2초나 걸림 (tail latency 문제)
→ 특정 조건에서 느린 요청 조사 필요
```

```promql
# 4. 평균 응답시간 (Histogram에서)
sum(rate(http_request_duration_seconds_sum[5m]))
/
sum(rate(http_request_duration_seconds_count[5m]))
```

**P99 vs 평균**:
- 평균: 전체적인 트렌드
- P99: 최악의 사용자 경험 (더 중요!)

### 실습 4: 실무 쿼리 패턴 10가지 (30분)

**목표**: 실제 업무에서 바로 사용할 쿼리 익히기

```promql
# 1. 🔥 노드 CPU 사용률 (%)
100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# 2. 🔥 노드 메모리 사용률 (%)
(1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)) * 100

# 3. 🔥 Pod CPU 사용량 TOP 10
topk(10, sum(rate(container_cpu_usage_seconds_total{container!=""}[5m])) by (pod, namespace))

# 4. 🔥 Pod 메모리 사용량 TOP 10
topk(10, sum(container_memory_usage_bytes{container!=""}) by (pod, namespace))

# 5. 🔥 네임스페이스별 CPU 사용량
sum(rate(container_cpu_usage_seconds_total{container!=""}[5m])) by (namespace)

# 6. 🔥 컨테이너 재시작 횟수
sum(increase(kube_pod_container_status_restarts_total[1h])) by (pod, namespace) > 0

# 7. 🔥 Pending 상태 Pod
kube_pod_status_phase{phase="Pending"} == 1

# 8. 🔥 디스크 사용률 (%)
(1 - (node_filesystem_avail_bytes{fstype!~"tmpfs|overlay"} / node_filesystem_size_bytes)) * 100

# 9. 🔥 네트워크 수신 트래픽 (bytes/sec)
sum(rate(node_network_receive_bytes_total{device!~"lo|veth.*|docker.*|br-.*"}[5m])) by (instance)

# 10. 🔥 API 서버 요청 지연 P99
histogram_quantile(0.99, sum(rate(apiserver_request_duration_seconds_bucket[5m])) by (le, verb))
```

**실습 방법**:
1. 위 쿼리를 Prometheus UI에서 하나씩 실행
2. 결과 확인 및 Graph 탭에서 시각화
3. 자신의 환경에 맞게 레이블 수정

### 실습 5: 복잡한 쿼리 작성 (15분)

**목표**: 여러 함수를 조합한 고급 쿼리

```promql
# 시나리오: "지난 5분간 에러율이 1% 이상인 서비스 찾기"
(
  sum(rate(http_requests_total{status=~"5.."}[5m])) by (service)
  /
  sum(rate(http_requests_total[5m])) by (service)
) > 0.01
```

```promql
# 시나리오: "메모리 사용량이 limit의 80% 이상인 컨테이너"
(
  sum(container_memory_usage_bytes{container!=""}) by (pod, container, namespace)
  /
  sum(kube_pod_container_resource_limits{resource="memory"}) by (pod, container, namespace)
) > 0.8
```

```promql
# 시나리오: "최근 1시간 대비 현재 요청량 변화율"
(
  sum(rate(http_requests_total[5m]))
  -
  sum(rate(http_requests_total[5m] offset 1h))
)
/
sum(rate(http_requests_total[5m] offset 1h))
```

### 시나리오: API 응답 지연 원인 분석

```promql
# 1단계: 전체 P99 확인
histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))
# 결과: 2.5초 (평소 200ms) → 이상!

# 2단계: 서비스별 분리
histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket[5m])) by (le, service))

# 3단계: 엔드포인트별 분리  
histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket{service="payment"}[5m])) by (le, path))
# 결과: /api/payment/process만 느림

# 4단계: 해당 시간대 DB 쿼리 확인 → 원인 발견!
```
