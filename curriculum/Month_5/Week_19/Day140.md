## 📚 Part 1: 전체 스택 점검 (30분)

### 모니터링 스택 상태 확인

```bash
# 1. 전체 Pod 상태
kubectl get pods -n monitoring

# 예상 출력 (모두 Running):
# prometheus-prometheus-kube-prometheus-prometheus-0
# alertmanager-prometheus-kube-prometheus-alertmanager-0
# prometheus-grafana-xxx
# prometheus-kube-prometheus-operator-xxx
# prometheus-prometheus-node-exporter-xxx (노드당 1개)
# loki-0
# promtail-xxx (노드당 1개)
# thanos-query-xxx
# thanos-store-gateway-0
# thanos-compactor-0

# 2. 서비스 상태
kubectl get svc -n monitoring | grep -E "prometheus|grafana|loki|thanos|alertmanager"

# 3. CRD 상태
kubectl get servicemonitors,prometheusrules -n monitoring | wc -l
```

### 연결 상태 테스트

```bash
# Prometheus → Targets
kubectl port-forward -n monitoring svc/prometheus-kube-prometheus-prometheus 9090:9090 &
curl -s http://localhost:9090/api/v1/targets | jq '.data.activeTargets | length'

# Thanos → Stores
kubectl port-forward -n monitoring svc/thanos-query 10902:10902 &
curl -s http://localhost:10902/api/v1/stores | jq '.data | length'

# Alertmanager → Status
kubectl port-forward -n monitoring svc/alertmanager-operated 9093:9093 &
curl -s http://localhost:9093/api/v2/status | jq '.cluster.status'

# Grafana → Health
kubectl port-forward -n monitoring svc/prometheus-grafana 3000:80 &
curl -s http://localhost:3000/api/health
```

## 🛠️ Part 2: End-to-End 시나리오 테스트 (2시간)

### 시나리오 1: 새 서비스 모니터링 설정 (30분)

**목표**: 처음부터 끝까지 새 서비스에 모니터링 추가

```bash
# 1. 샘플 애플리케이션 배포
cat << 'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: demo-app
  namespace: default
  labels:
    app: demo-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: demo-app
  template:
    metadata:
      labels:
        app: demo-app
    spec:
      containers:
      - name: app
        image: quay.io/brancz/prometheus-example-app:v0.5.0
        ports:
        - name: http
          containerPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: demo-app
  labels:
    app: demo-app
spec:
  selector:
    app: demo-app
  ports:
  - name: http
    port: 80
    targetPort: 8080
  - name: metrics
    port: 8080
    targetPort: 8080
EOF

# 2. ServiceMonitor 생성
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: demo-app
  namespace: monitoring
  labels:
    release: prometheus
spec:
  selector:
    matchLabels:
      app: demo-app
  namespaceSelector:
    matchNames:
    - default
  endpoints:
  - port: metrics
    interval: 15s
EOF

# 3. Recording Rules 생성
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: demo-app-rules
  namespace: monitoring
  labels:
    release: prometheus
spec:
  groups:
  - name: demo-app.rules
    rules:
    - record: job:demo_app_requests:rate5m
      expr: sum(rate(http_requests_total{job="demo-app"}[5m]))
    - record: job:demo_app_errors:rate5m
      expr: sum(rate(http_requests_total{job="demo-app", code=~"5.."}[5m]))
EOF

# 4. Alerting Rules 생성
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: demo-app-alerts
  namespace: monitoring
  labels:
    release: prometheus
spec:
  groups:
  - name: demo-app.alerts
    rules:
    - alert: DemoAppHighErrorRate
      expr: |
        job:demo_app_errors:rate5m / job:demo_app_requests:rate5m > 0.05
      for: 5m
      labels:
        severity: critical
        service: demo-app
      annotations:
        summary: "High error rate on demo-app"
        description: "Error rate is {{ $value | humanizePercentage }}"
        runbook_url: "https://wiki.company.com/runbook/demo-app-errors"
    
    - alert: DemoAppDown
      expr: up{job="demo-app"} == 0
      for: 1m
      labels:
        severity: critical
        service: demo-app
      annotations:
        summary: "Demo app is down"
EOF

# 5. 확인
kubectl get servicemonitor,prometheusrules -n monitoring | grep demo-app
```

### 시나리오 2: 장애 주입 및 감지 테스트 (30분)

**목표**: 의도적으로 장애를 발생시키고 알림이 오는지 확인

```bash
# 1. 테스트 알림 규칙 (항상 발동)
cat << 'EOF' | kubectl apply -f -
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: test-alert
  namespace: monitoring
  labels:
    release: prometheus
spec:
  groups:
  - name: test.alerts
    rules:
    - alert: TestAlertForE2E
      expr: vector(1) > 0
      for: 30s
      labels:
        severity: info
        test: "true"
      annotations:
        summary: "E2E Test Alert"
        description: "This is a test alert for E2E verification"
EOF

# 2. Prometheus Alerts 페이지에서 확인
# http://localhost:9090/alerts
# 30초 후 Pending → 1분 후 Firing

# 3. Alertmanager에서 확인
# http://localhost:9093/#/alerts

# 4. 테스트 알림 삭제
kubectl delete prometheusrule test-alert -n monitoring
```

**Pod 장애 시뮬레이션**:
```bash
# Demo app Pod 삭제하여 장애 시뮬레이션
kubectl delete pod -l app=demo-app --grace-period=0 --force

# DemoAppDown 알림 확인 (1분 후)
curl -s http://localhost:9090/api/v1/alerts | jq '.data.alerts[] | select(.labels.alertname == "DemoAppDown")'

# Pod 자동 재생성 확인
kubectl get pods -l app=demo-app -w
```

### 시나리오 3: 대시보드 구성 테스트 (30분)

**목표**: 서비스별 대시보드 완성

```
Grafana (http://localhost:3000)에서:

1. 새 대시보드 생성: "Demo App Overview"

2. Variables 추가:
   - namespace: label_values(kube_pod_info, namespace)
   - pod: label_values(kube_pod_info{namespace=~"$namespace"}, pod)

3. Row 1: Overview (Stat 패널들)
   - Running Pods: count(kube_pod_status_phase{namespace="default", pod=~"demo-app.*", phase="Running"})
   - Request Rate: job:demo_app_requests:rate5m
   - Error Rate: job:demo_app_errors:rate5m / job:demo_app_requests:rate5m * 100

4. Row 2: Resources (Time series)
   - CPU: sum(rate(container_cpu_usage_seconds_total{pod=~"demo-app.*"}[5m])) by (pod)
   - Memory: sum(container_memory_usage_bytes{pod=~"demo-app.*"}) by (pod)

5. Row 3: Logs (Logs 패널)
   - Data source: Loki
   - Query: {namespace="default", app="demo-app"}

6. 저장 및 공유
```

### 시나리오 4: 로그와 메트릭 연계 분석 (30분)

**목표**: 메트릭 이상 → 로그 분석 → 원인 파악

```bash
# 1. 트래픽 생성
kubectl run -it --rm load-test --image=busybox --restart=Never -- sh -c '
  for i in $(seq 1 100); do
    wget -q -O- http://demo-app.default.svc/
    sleep 0.1
  done
'

# 2. Grafana Explore에서 확인
# 왼쪽: Prometheus - 요청 수
sum(rate(http_requests_total{job="demo-app"}[5m]))

# 오른쪽: Loki - 관련 로그
{namespace="default", app="demo-app"}
```

**Split View 활용**:
```
1. Explore 열기
2. Split 버튼 클릭
3. 왼쪽 패널: Prometheus (메트릭)
   - sum(rate(http_requests_total{job="demo-app"}[5m]))
4. 오른쪽 패널: Loki (로그)
   - {namespace="default", app="demo-app"}
5. 같은 시간 범위로 동기화
6. 메트릭 스파이크 시점의 로그 확인
```
