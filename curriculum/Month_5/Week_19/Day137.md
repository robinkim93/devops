## 📚 Part 1: 핵심 개념 (40분)

### Loki란?

```
┌─────────────────────────────────────────────────────────────┐
│  Loki = "Prometheus for Logs"                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Prometheus:                                                │
│  - Pull 기반 메트릭 수집                                    │
│  - 레이블로 메트릭 구분                                     │
│  - PromQL로 쿼리                                            │
│                                                             │
│  Loki:                                                      │
│  - Push 기반 로그 수집                                      │
│  - 레이블로 로그 스트림 구분 ← 동일!                        │
│  - LogQL로 쿼리                                             │
│                                                             │
│  장점:                                                       │
│  - Prometheus와 레이블 체계 통일                            │
│  - Grafana에서 메트릭 + 로그 함께 조회                      │
│  - 로그 내용 인덱싱 안 함 → 저장 비용 낮음                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Loki 아키텍처

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         Loki Architecture                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│                          ┌───────────────────┐                          │
│                          │      Grafana      │  ← 로그 시각화           │
│                          └─────────┬─────────┘                          │
│                                    │ Query                              │
│                                    ▼                                    │
│                          ┌───────────────────┐                          │
│                          │       Loki        │                          │
│                          │  ┌─────────────┐  │                          │
│                          │  │ Distributor │  │  ← 로그 수신, 분배       │
│                          │  └──────┬──────┘  │                          │
│                          │         │         │                          │
│                          │  ┌──────┴──────┐  │                          │
│                          │  │  Ingester   │  │  ← 메모리 버퍼, 청크    │
│                          │  └──────┬──────┘  │                          │
│                          │         │         │                          │
│                          │  ┌──────┴──────┐  │                          │
│                          │  │   Querier   │  │  ← 쿼리 처리             │
│                          │  └─────────────┘  │                          │
│                          └─────────┬─────────┘                          │
│                                    │ Storage                            │
│                                    ▼                                    │
│                          ┌───────────────────┐                          │
│                          │  Object Storage   │  ← S3, GCS, FileSystem  │
│                          │   (Chunks + Index)│                          │
│                          └───────────────────┘                          │
│                                    ▲                                    │
│              ┌─────────────────────┼─────────────────────┐             │
│              │                     │                     │             │
│        ┌─────┴─────┐         ┌─────┴─────┐         ┌─────┴─────┐       │
│        │ Promtail  │         │ Promtail  │         │ Promtail  │       │
│        │ (Node 1)  │         │ (Node 2)  │         │ (Node 3)  │       │
│        └───────────┘         └───────────┘         └───────────┘       │
│             ↑                     ↑                     ↑              │
│         Pod 로그              Pod 로그              Pod 로그           │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 핵심 컴포넌트

| 컴포넌트 | 역할 |
|---------|------|
| **Promtail** | 로그 수집 에이전트 (각 노드에 DaemonSet) |
| **Distributor** | 로그 수신, Ingester에 분배 |
| **Ingester** | 로그를 청크로 압축, 저장소에 기록 |
| **Querier** | LogQL 쿼리 처리 |
| **Compactor** | 인덱스 압축 (선택) |

### Loki vs Elasticsearch

| 항목 | Loki | Elasticsearch |
|------|------|---------------|
| 인덱싱 | 레이블만 | 전체 텍스트 |
| 저장 비용 | 낮음 | 높음 |
| 쿼리 속도 | 빠름 (레이블) / 느림 (전문) | 빠름 |
| 운영 복잡도 | 낮음 | 높음 |
| 사용 케이스 | 클라우드 네이티브 | 전문 검색 필요 시 |

## 🛠️ Part 2: 실습 (1시간 40분)

### 실습 1: Loki Stack 설치 (25분)

**목표**: Loki + Promtail 설치

```bash
# 1. Helm repo 추가
helm repo add grafana https://grafana.github.io/helm-charts
helm repo update

# 2. Loki Stack 설치 (Loki + Promtail)
helm install loki grafana/loki-stack \
  --namespace monitoring \
  --set promtail.enabled=true \
  --set grafana.enabled=false \
  --set loki.persistence.enabled=true \
  --set loki.persistence.size=10Gi

# 3. 설치 확인
kubectl get pods -n monitoring -l app=loki
kubectl get pods -n monitoring -l app=promtail
```

**예상 출력**:
```
NAME                    READY   STATUS    RESTARTS   AGE
loki-0                  1/1     Running   0          2m
promtail-xxxxx          1/1     Running   0          2m   # 노드마다 1개
```

### 실습 3: 기본 LogQL 쿼리 (30분)

**목표**: LogQL 문법 익히기

**Grafana Explore에서 테스트**:
```
1. 좌측 메뉴 → Explore
2. Data source: Loki 선택
```

**기본 쿼리**:

```logql
# 1. 특정 네임스페이스의 모든 로그
{namespace="default"}

# 2. 특정 Pod의 로그
{namespace="monitoring", pod=~"loki.*"}

# 3. 특정 컨테이너의 로그
{namespace="default", container="nginx"}

# 4. 여러 조건 조합
{namespace="default", app="myapp", env="production"}
```

**필터링**:

```logql
# 5. 텍스트 포함 (대소문자 구분)
{namespace="default"} |= "error"

# 6. 텍스트 포함 (대소문자 무시)
{namespace="default"} |~ "(?i)error"

# 7. 텍스트 미포함
{namespace="default"} != "health"

# 8. 정규식 매칭
{namespace="default"} |~ "status=[45][0-9][0-9]"

# 9. 여러 필터 조합
{namespace="default"} |= "error" != "timeout" |~ "user_id=[0-9]+"
```

**파싱**:

```logql
# 10. JSON 파싱
{namespace="default"} | json

# JSON 필드로 필터
{namespace="default"} | json | level="error"

# 11. logfmt 파싱
{namespace="default"} | logfmt

# logfmt 필드로 필터
{namespace="default"} | logfmt | status>=500

# 12. 정규식 추출
{namespace="default"} | regexp `user=(?P<user>\w+)`
```

### 실습 4: 로그 기반 메트릭 (25분)

**목표**: 로그에서 메트릭 추출

```logql
# 1. 에러 로그 수 (시간당)
count_over_time({namespace="default"} |= "error" [1h])

# 2. 에러율 (분당)
sum(rate({namespace="default"} |= "error" [5m]))

# 3. 네임스페이스별 로그 수
sum by (namespace) (count_over_time({namespace=~".+"}[1h]))

# 4. JSON 로그에서 응답 시간 평균
avg_over_time(
  {namespace="default"} 
  | json 
  | unwrap response_time 
  [5m]
)

# 5. HTTP 상태 코드별 로그 수
sum by (status) (
  count_over_time(
    {namespace="default"} 
    | json 
    | status!="" 
    [1h]
  )
)
```

### 실습 5: 메트릭과 로그 연계 (20분)

**목표**: 에러 발생 시 관련 로그 빠르게 찾기

**Grafana 대시보드에서**:

```
1. 메트릭 패널 생성 (에러율)
   sum(rate(http_requests_total{status=~"5.."}[5m])) by (service)

2. 로그 패널 생성 (같은 Row에)
   {namespace="$namespace", app="$service"} |= "error"

3. 변수 설정
   - namespace
   - service

4. 메트릭에서 스파이크 확인
   → 같은 시간대의 로그에서 원인 확인
```

**Split View 활용**:
```
Explore에서:
1. Split 버튼 클릭 (우측)
2. 왼쪽: Prometheus (메트릭)
3. 오른쪽: Loki (로그)
4. 같은 시간 범위로 동시 조회
```

### 실습 6: Promtail 설정 커스터마이징 (10분)

**목표**: 로그 수집 설정 이해

```yaml
# Promtail ConfigMap 예시
apiVersion: v1
kind: ConfigMap
metadata:
  name: promtail-config
data:
  promtail.yaml: |
    server:
      http_listen_port: 3101
    
    positions:
      filename: /run/promtail/positions.yaml
    
    clients:
      - url: http://loki:3100/loki/api/v1/push
    
    scrape_configs:
      # Kubernetes Pod 로그
      - job_name: kubernetes-pods
        kubernetes_sd_configs:
          - role: pod
        relabel_configs:
          # 네임스페이스 레이블
          - source_labels: [__meta_kubernetes_namespace]
            target_label: namespace
          # Pod 이름
          - source_labels: [__meta_kubernetes_pod_name]
            target_label: pod
          # 컨테이너 이름
          - source_labels: [__meta_kubernetes_pod_container_name]
            target_label: container
          # 앱 레이블
          - source_labels: [__meta_kubernetes_pod_label_app]
            target_label: app
        
        pipeline_stages:
          # JSON 로그 파싱
          - json:
              expressions:
                level: level
                msg: message
          # level 레이블로 추가
          - labels:
              level:
```

## 📊 Part 3: LogQL 요약

### 쿼리 구조

```logql
# 기본 구조
{selector} | parser | filter | formatter

# 예시
{namespace="default", app="api"}   # 스트림 선택
| json                              # JSON 파싱
| level="error"                     # 필터
| line_format "{{.message}}"        # 포맷 변경
```

### 주요 연산자

| 연산자 | 설명 | 예시 |
|--------|------|------|
| `\|=` | 포함 | `\|= "error"` |
| `!=` | 미포함 | `!= "debug"` |
| `\|~` | 정규식 | `\|~ "error\|warn"` |
| `!~` | 정규식 미매칭 | `!~ "health.*"` |

### 메트릭 함수

| 함수 | 설명 |
|------|------|
| `count_over_time()` | 로그 라인 수 |
| `rate()` | 초당 로그 수 |
| `bytes_over_time()` | 로그 바이트 수 |
| `bytes_rate()` | 초당 바이트 |
