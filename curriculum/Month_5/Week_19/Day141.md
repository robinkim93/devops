### 2. SLI/SLO 핵심

```
SLI (지표): "측정하는 것"
- 가용성 SLI: 성공 요청 / 전체 요청
- 지연시간 SLI: 목표 시간 이내 응답 비율

SLO (목표): "달성할 것"
- "월간 99.9%의 요청이 200ms 이내 응답"

Error Budget (에러 예산): "허용 범위"
- 99.9% SLO = 0.1% 실패 허용 = 월 43.2분 다운타임
```

**SLO 수준별 다운타임**:
| SLO | 월간 | 연간 |
|-----|------|------|
| 99% | 7.2시간 | 3.65일 |
| 99.9% | 43.2분 | 8.76시간 |
| 99.99% | 4.3분 | 52.6분 |

### 3. LogQL 핵심 문법

```logql
# 스트림 선택
{namespace="production", app="myapp"}

# 필터링
|= "error"    # 포함
!= "health"   # 미포함
|~ "5[0-9]{2}"  # 정규식

# 파싱
| json
| logfmt
| regexp `user=(?P<user>\w+)`

# 메트릭 추출
count_over_time({app="myapp"} |= "error" [1h])
sum(rate({app="myapp"} |= "error" [5m]))
```

### 4. 트러블슈팅 체크리스트

```
□ 1. 현재 상태 확인
  - 에러율, P99, 요청량

□ 2. 변경 이력 확인
  - 최근 배포, 설정 변경

□ 3. 리소스 상태 확인
  - CPU, 메모리, 디스크

□ 4. 의존성 확인
  - DB, 외부 API, 캐시

□ 5. 로그 확인
  - 에러 로그, 스택 트레이스
```

### 5. 알림 전략 요약

```
Severity 레벨:
- P1 (Critical): 즉시 대응, PagerDuty
- P2 (Warning): 30분 내, Slack urgent
- P3 (Info): 업무 시간 내, Slack
- P4 (Low): 참고용

좋은 알림 조건:
- Actionable (조치 가능)
- Relevant (관련성)
- Timely (적시성)
- Unique (고유성)
- Complete (완전성)
```

## 🛠️ 종합 실습

### 실습 1: 핵심 쿼리 복습 (20분)

```promql
# Golden Signals - Latency
histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket[5m])) by (le, service))

# Golden Signals - Traffic
sum(rate(http_requests_total[5m])) by (service)

# Golden Signals - Errors
sum(rate(http_requests_total{status=~"5.."}[5m])) by (service) / sum(rate(http_requests_total[5m])) by (service)

# Golden Signals - Saturation
(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100

# SLI - 가용성
sum(increase(http_requests_total{status!~"5.."}[30d])) / sum(increase(http_requests_total[30d]))

# SLI - 지연시간
sum(increase(http_request_duration_seconds_bucket{le="0.2"}[30d])) / sum(increase(http_request_duration_seconds_count[30d]))
```

### 실습 2: LogQL 복습 (15분)

```logql
# 에러 로그 검색
{namespace="production"} |= "error" != "health"

# JSON 로그 파싱 및 필터
{namespace="production"} | json | level="error" | status>=500

# 시간당 에러 수
count_over_time({namespace="production"} |= "error" [1h])

# 분당 에러율
sum(rate({namespace="production"} |= "error" [5m]))
```

### 실습 3: 종합 시나리오 - "서비스가 느려요" (40분)

```bash
# Step 1: 현재 상태 확인 (메트릭)
```

```promql
# P99 지연시간
histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket[5m])) by (le, service))

# 요청량 (급증 여부)
sum(rate(http_requests_total[5m])) by (service)

# 에러율
sum(rate(http_requests_total{status=~"5.."}[5m])) by (service) / sum(rate(http_requests_total[5m])) by (service)
```

```bash
# Step 2: 리소스 상태 확인
```

```promql
# CPU 사용률
sum(rate(container_cpu_usage_seconds_total{container!=""}[5m])) by (pod) / sum(kube_pod_container_resource_limits{resource="cpu"}) by (pod)

# 메모리 사용률
sum(container_memory_usage_bytes{container!=""}) by (pod) / sum(kube_pod_container_resource_limits{resource="memory"}) by (pod)
```

```bash
# Step 3: 로그 확인
```

```logql
# 에러 로그

# 타임아웃 로그
{namespace="production", service="slow-service"} |= "timeout"

# 느린 쿼리 로그
{namespace="production", service="slow-service"} |~ "duration.*[0-9]{4}ms"
```

### 실습 4: SLO 대시보드 생성 (25분)

```
Grafana에서 "SLO Dashboard" 생성:

Variables:
- service: label_values(http_requests_total, service)
- slo_target: 0.999 (Custom)

Panel 1: 현재 가용성 (Stat)
sum(rate(http_requests_total{service="$service", status!~"5.."}[5m])) / sum(rate(http_requests_total{service="$service"}[5m]))

Panel 2: Error Budget 남은 비율 (Gauge)
($slo_target - (1 - (sum(rate(http_requests_total{service="$service", status!~"5.."}[5m])) / sum(rate(http_requests_total{service="$service"}[5m]))))) / (1 - $slo_target) * 100

Panel 3: SLO 트렌드 (Time series)
sum(rate(http_requests_total{service="$service", status!~"5.."}[5m])) / sum(rate(http_requests_total{service="$service"}[5m]))
+ SLO 라인: $slo_target
```
